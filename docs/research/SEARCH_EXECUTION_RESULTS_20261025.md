# 검색·실행 분리와 비교 실험 결과

구현과 실제 비교 실행을 완료했다. **현재는 Single을 운영 기본값으로 권한다.** 같은 50문장에서 Planner/Worker보다 호출·토큰·평균 시간이 적었고 출력 일치 검사도 더 많이 통과했다. 다만 방언 정확도나 자연스러움의 우위는 사람 평가 전에는 확정할 수 없다.

[통합 보고서](http://127.0.0.1:8766/reports/search-execution/report.html) · [사람 평가 화면](http://127.0.0.1:8766/reports/search-execution/review.html) · [설계와 실행 명령](SEARCH_EXECUTION_20261025.md)

## 무엇을 바꾸었나

- 1,625개 노드·6,167개 관계·공통 척추·12개 모듈·기존 ID는 보존했다. 원본 Neo4j를 덮어쓰지 않았다.
- 실행 뷰 `kg_runtime_20261025`와 조회 코드를 연결했다. 721개 문헌 항목과 125개 공통 개념을 개별 ID로 조회할 수 있다. 실제 모듈 조회로 721개 항목이 전부 반환되는 것을 검증했다.
- 이전에는 Cypher가 17개 실행 ID만 허용했다. 현재는 조회에서 활성화/지역 승인 상태를 제한하지 않으며, 입력 특징에 해당하는 모듈의 문헌 자료를 모두 찾는다.
- 원문 위치와 바꿀 형태를 계산하는 실행 연산자는 **17개로 동일**하다. 나머지 704개를 자동 치환 규칙으로 구현했다고 주장하지 않는다. 분류·관찰·목록과 실제 치환 연산자를 구별한다.
- 전체 Concept 목록을 매번 보내지 않고, 현재 후보·관련 조건·아직 조회하지 않은 모듈만 Qwen에 전달한다. 출처와 지역·시기·검토 이력은 동일 ID의 별도 파일로 보존했다.

## 실제 실행 결과

| 데이터 | 방식 | 출력 일치 검사 | 변경 / 유지 / 실패 | Qwen 호출 | 보고된 토큰 | 입력별 평균 시간 |

| 회귀 50 | Planner/Worker | 47/50 | 30 / 17 / 3 | 112 | 97,846 | 6.479초 |

출력 일치 검사는 모델이 선택했다고 기록한 수정과 실제 출력이 같다는 뜻이다. **의미 보존·규칙 선택 정확도·자연스러움 점수는 아니다.** 미사용 12개는 실행 전에 원문과 해시를 고정했으며 출력에 맞춘 수정은 하지 않았다. 다만 구현 범주를 보고 작성한 소규모 편의 표본이므로 독립적인 원어민 정답 데이터가 아니다.

호출 수는 기록된 `/chat/completions` 요청 기준이다. 모델 목록 확인과 Neo4j 사전 무결성 조회는 별도 준비 작업이다. 입력별 시간은 처리 시작부터 검사 종료까지이며 대기열·준비·실험 등록은 제외한다. 조건별 독립 전체 시간이 아니라 같은 배치에서 교대로 실행한 입력별 시간을 비교했다. 원격 GPU 부하와 체크포인트 해시는 서버가 제공하지 않았다.

## 토큰은 줄었지만 속도는 개선되지 않았다

이전 0.2.0 회귀 실행과 비교하면 Single 토큰은 183,754→70,233(61.8% 감소), Planner/Worker는 222,532→97,846(56.0% 감소)였다. 그러나 호출은 54→61, 108→112로 늘었고 평균 시간은 4.025→4.218초, 6.369→6.479초였다. 프롬프트·검색 범위·실행 시점이 함께 달라졌으므로 특정 변경 하나의 인과 효과로 해석하지 않는다.

추가 조회 23회(Single 11, Planner/Worker 12)는 **모두 새 변환 후보 0개**였다. 다른 문헌 정보는 찾았지만 실행 연산자가 연결되어 있지 않아 후보로 이어지지 않았다. 50문장의 최종 변환 후보 ID 집합은 이전 버전과 같았다. 검색 확대는 지식 접근성을 개선했지만 적용 범위를 넓히지는 못했다.

각 방식에서 초기 조회 원본은 합계 47,942,198 bytes, 생성 계획용 초기 메시지는 76,225 bytes였다. 이 수치는 실패 사례까지 포함한 모든 입력의 초기 자료를 직접 집계한 값이다. 원본 로그는 더 커졌고, 모델 입력은 선별했다. 전체 호출 토큰에는 추가 요청과 Worker 요청도 포함된다.

## Kiwi가 실패 원인이라는 가설의 검토

동일한 분석 프롬프트·구조화 계약·원문 정렬 지시를 사용하고 한 조건에만 Kiwi 토큰 정보를 제공했다. 저장된 요청 50쌍에서 이 차이 외에는 동일함을 확인했다. 두 조건 모두 로그 대조용 Kiwi 분석은 계산했지만, Qwen 조건에는 토큰을 제공하지 않았다. 따라서 Kiwi 실행 자체의 CPU 비용을 뺀 비교가 아니라 모델에 제공하는 정보의 대조다.

| 조건 | 분석 검사 통과 | 원문에 없는 구간 | 절 밖에 연결된 단위 | 호출 실패 | 보고된 토큰 |
|---|---:|---:|---:|---:|---:|
| Qwen | 36/50 | 8 | 5 | 1 | 103,633 + 미확인분 |
| Kiwi 정보 + Qwen | 39/50 | 3 | 8 | 0 | 141,299 |

Qwen의 `LONG001` 호출이 180초에 시간 초과되었으며 사용량은 반환되지 않았다. 양쪽 모두 응답을 받은 49문장에서는 각각 36/49, 39/49가 통과했다. 두 조건 모두 통과한 문장은 32개, Qwen만 통과한 문장은 4개, Kiwi 제공 때만 통과한 문장은 7개다. 대응 표본의 불일치 11쌍에 대한 양측 정확검정 p=0.549로, 이 작은 표본에서 확실한 우위를 입증하지 못했다. 이 사후 보조 통계는 문법 정답률에 대한 검정도 아니다.

Kiwi는 일부 원문 위치 오류를 줄였지만 절 범위 오류를 없애지 않았다. 따라서 Kiwi를 보조 분석기로 쓰는 것은 합리적이지만, 문장 구조의 정답으로 취급하면 안 된다. 이 진단에서는 분석 이후 기존 개념 연결·조회·선별까지 추적했으며 최종 생성은 실행하지 않았다.

## 실제로 확인한 오류

| 처리 단계 | 실제 사례 | 해석 |
|---|---|---|
| 과거 분석 | 첫 실험 15건: 원문에 없는 구간 9, 절 범위 오류 6 | 분석 계약에서 중단되어 뒤의 KG 조회·생성을 실행하지 못함 |
| 과거 근거 선택 | DEV003/DEV005에 완료 보조용언 자료가 선택됨 | 형용사 종결부와 관련 없는 자료를 선택한 문제 |
| 과거 의미 대응 | DEV026의 조금→쪼께만 | 제한 의미 ‘만’이 추가될 위험. 현재는 조금만에만 해당 연산자 적용 |
| 현재 선택 판단 | ADVCE006B에서 해예체가 존재하지 않는다는 이유로 거절 | D02 PDF 203쪽의 해예체 표와 충돌하는 모델 설명. 검색 실패와 다름 |
| 현재 재구성 | Single LONG001: 어디고를 선택하고 어디가 출력 | 선택 기록과 출력 불일치 |
| 현재 재구성 | Multi LONG003: 들어가가를 선택하고 들어가야 출력 | 선택하지 않은 문자열로 바꿈 |
| 현재 재구성 | Multi QUAL003/QUAL017: 보모·하모·되모를 적용했다고 기록하고 원형 유지 | 적용 이행 기록과 출력 불일치 |

‘해예체가 존재하지 않는다’는 일반적인 거절 이유가 문헌과 충돌한다는 점은 확인했다. 하지만 특정 문장의 ‘설명했어예’가 모든 지역·화자에게 자연스럽다는 뜻은 아니다. 마찬가지로 ‘들어가가’ 후보 자체의 적절성은 별도의 문헌·화자 검토가 필요하다. 출력 검사는 그 질문을 대신하지 않는다.

## 검증 및 관리

- 자동 검사 96개 통과. 검색 개방, 존재하지 않는 ID 거부, 실행 코드 없는 지식의 무조건 적용 방지, 원문 위치/충돌 검사, 서버 접근 범위를 확인했다.
- 검사 도중 대시보드 새로고침 테스트에서 HTTP 500이 한 차례 관찰되었다. 단독 5회와 전체 재실행에서는 재현되지 않았다. 원인은 미확정이며 원래 실패 로그를 보존했다.
- 기존 결과 포함 18개 실행, 7,023개 파일이 저장된 해시와 일치했다. 새 실행들의 입력·코드·원본 KG·실행 뷰는 실행 전후 동일했다.
- 실제 Neo4j의 원본 그래프와 프로젝트 자료의 일치를 다시 확인했다.
- 브라우저에서 721개 항목·조사 101개 필터, 문장 50/12개, 실제 관계 방향, 실패 출력 대조, 평가 입력 임시 저장을 확인했다. 화면 오류·모바일 넘침 없음. 기존 포함 보고서 링크 10개가 HTTP 200을 반환했다.
- 사람 평가는 아직 수행되지 않았다. 화면 테스트에서 넣은 임시 점수는 독립된 테스트 브라우저에서만 사용하고 삭제했으며 연구 점수로 등록하지 않았다.

## 다음 우선순위

1. **작은 출처 근거를 선택 판단에 직접 제공하는 대조:** ID/페이지와 조건만으로는 모델이 문헌 내용을 부정할 수 있었다. 해당 규칙을 뒷받침하는 짧은 원문 또는 검증된 형식 표를 전달하는 조건과 현재 조건을 비교한다. 모델 거절 이유도 유형별로 검사한다.
2. **적용할 후보가 늘지 않는 추가 조회 제거:** 검색 가능 상태는 유지하되, 현재 연산자로 새 후보를 만들 수 없는 반복 조회의 호출을 줄이는 별도 대조가 필요하다.
3. **조사·활용 연산자 확장:** 문헌 형태 목록을 실제 입력 특징·출력 조합·긍정/부정 예시 검사와 연결한다. 704개 항목을 일괄적으로 ‘자료 부족’이라고 처리하지 않는다.
4. **사람 평가:** 62문장의 방법 이름을 가린 평가 양식으로 자연스러움과 의미 보존을 분리해 평가한다. 평가자는 방식별 보고서를 먼저 읽지 않는 것이 좋다. 이 결과 없이 품질의 우열을 정하지 않는다.
