# 설계 결정 장부

상태 `inherited`는 기존 연구의 결정, `proposed`는 v3의 제안, `task_constraint`는 이번 이관의 작업 제약이다. 기존 코드가 새 저장소에 구현됐다는 뜻은 아니다. 결정의 증거는 [이관 문서](../KG_V3_RESEARCH_HANDOFF.md)의 해당 절과 고정 링크를 따른다.

| ID | 상태 | 결정과 이유 | 대안과 검증 경계 |
|---|---|---|---|
| D001 | task_constraint | 기존 저장소는 어떤 경우에도 수정하지 않음. 새 저장소에서만 연구 | 원본 이동·정리·자동 수정은 범위 밖 |
| D002 | inherited | KG는 방법 가설. 자연스러운 방언 생성과 의미·높임 보존이 목적 | 검색 성능만으로 최종 과제 달성 주장 금지 |
| D003 | inherited | 형태와 용법·기능·구성을 분리 | 철자 기반 병합은 동형이의·범위 차이를 잃음 |
| D004 | inherited | 근거 주장과 실행 후보/승인을 구별 | source_generalization도 입력 적용을 자동 보장하지 않음 |
| D005 | inherited | 조건의 대상 input/candidate/target/context 구별 | 입력이 방언형이어야만 활용을 찾는 순환 조건 방지 |
| D006 | inherited | 자료 의존성·지역·시대·분석 체계 보존 | 위키 다수결·경북+경남→전역 공통 자동 확대 금지 |
| D007 | inherited | AI-Hub는 평가 후보, 별도 어휘 JSON은 후보 자원 | 구축에 활용하면 해당 평가의 독립성을 다시 판단 |
| D008 | inherited | 문헌 확인형과 모델 조합형의 출처 분리 | 제한적 조합 정책은 화자 검증된 일반 규칙이 아님 |
| D009 | inherited | 원문 구간 결속과 보존 의무 기록 | 규격 검증은 분석 의미의 정확성을 보장하지 않음 |
| D010 | inherited | 네 조건 비교의 실제 정보·요청 차이를 기록 | C/D 동일 요청이면 관계 효과를 식별하지 못함 |
| D011 | inherited | 실패·초기 출력·재검토 미채택 보존 | 성공 출력만 선별하면 효과·실패율이 왜곡됨 |
| D012 | inherited | Neo4j는 확인 미러였음 | Cypher 전환이나 RDF 선택은 v3에서 미정 |
| D013 | proposed | v3는 작은 병목 진단과 기록 계약부터 시작 | 전체 KG 재구축이 최선이라는 근거는 아직 없음 |
| D014 | proposed | 새 실행 폴더 불변, latest는 포인터 | 과거20개 덮어쓰기의 중간 상태 소실 위험을 반복하지 않음 |
| D015 | proposed | 최소 근거·후보 제거·분석 oracle은 별도 진단 | oracle 성능을 실제 자동 파이프라인 성능으로 보고하지 않음 |
| D016 | proposed | 독립 새 입력과 방언 화자 맹검 평가 후 품질 결론 | 반복70개는 개발 회귀 사례로 취급 |

후속 변경 시 문제·근거·대안·선택 이유·결정 주체·상태·변경 파일·검증·결과·남은 한계를 추가한다. 폐기된 결정을 지우지 말고 새 결정 ID와 폐기 이유를 연결한다.
