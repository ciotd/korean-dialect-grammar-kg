# 실행층 재설계 · 50건 회귀 실험 결과

실행 구현과 세 조건의 50건 실험을 완료했다. **Single을 다음 연구의 기본 실행 방식으로 권한다.** 두 방식의 출력 검사 통과 수는 같고, Single이 호출·시간·토큰을 적게 사용했다. 이 권고는 운영 효율에 대한 판단이며 방언 품질의 우열을 뜻하지 않는다.

## 실패의 실제 위치

### 과거 분석 문제와 Kiwi 진단

과거 15건은 원문에 없는 구간 지정 9건, 절 밖에 단어를 연결한 오류 6건으로 중단됐다. Kiwi 진단에서는 각각 4건과 6건이었다. 과거 실패 8건이 통과했고, 과거 통과 3건이 새로 실패했다. 따라서 ‘Kiwi가 기존 오류를 모두 고쳤다’고 말할 수 없다.

- 통과로 바뀜: `ADVCE005A`, `ADVCE005B`, `DEV028`, `DEV030`, `NEW001`, `NEW007`, `NEW012`, `QUAL018`.
- 새로 실패: `DEV004`는 원문에 없는 ‘의’, `NEW008`은 원문에 없는 ‘네’, `QUAL005`는 원문에 없는 ‘했었던’을 구간으로 제시했다.
- 이 진단은 기존 프롬프트에 Kiwi 토큰과 정렬 지시를 함께 추가했다. 단일 요인의 순수 인과 효과를 측정한 실험은 아니다.

### 새 실행기의 출력 불일치

| 조건 / 입력 | 선택한 계획 | 실제 모델 출력의 차이 |
|---|---|---|
| Single / LONG003 | 들어가서 → 들어가가 | 바꾸었다고 기록했으나 들어가서로 유지 |
| Single / QUAL018 | 했다고 → 했다꼬 | 했다고꼬로 생성 |
| Multi / LONG003 | 들어가서 → 들어가가 | 들어가야로 바꿈 |
| Multi / QUAL017 | 하면 → 하모, 되면 → 되모 | 모두 적용했다고 기록했으나 두 구간을 그대로 유지 |

이는 실제 실행 기록의 불일치다. 예컨대 ‘들어가가’ 자체의 자연스러움을 인증하는 판정은 아니다. 해당 후보의 적절성 검토와 모델의 계획 이행 검사는 구별해야 한다. 실패 응답은 지우거나 사람이 고치지 않았고, 최종 유효 출력에서는 제외했다.

## KG 연결 범위와 남은 구현

- 원본과 실행 뷰 모두 **1,625노드, 6,167관계, 12모듈**. 원본과 Neo4j를 일괄 재작성하지 않았다.
- 721개 문헌 항목은 설계 규칙 81, 형태 목록 433, 관찰 183, 분류 24개로 나뉜다.
- 이번 실행기에 연결된 ID는 **17개**: 종결어미 11, 연결어미 3, 부사 3. 적용된 유효 출력에서는 Single 10종, Multi 11종이 실제 선택됐다.
- 문장에 맞는 후보는 각 방식에서 35건에 제공됐다. 후보가 없는 15건까지 무조건 방언화하지 않았다.
- 노드 속성 항목의 합계는 14,027→2,534, 파일 크기는 5,562,616→1,413,119 bytes다. 파일 형식도 달라 의미 손실 없는 압축률로 해석하지 않는다.
- 704개 미연결 항목을 `coverage_audit.json`과 보고서에서 전부 열람할 수 있다. 분류처럼 단독 변환이 아닌 항목과 조사·활용 실행기가 미구현인 항목을 구별한다.

## 비용에서 드러난 개선 과제

1. 추가 조회는 Single 4회, Multi 8회였고 새로 늘어난 후보는 모두 0개였다. 이번 규칙 풀에서는 반복 조회의 이득이 없었다. 이미 검색한 범위를 확인해 중복 호출을 생략할 필요가 있다.
2. 새 최초 조회 JSON은 조건별 416,999 bytes, 모델에 보내는 최초 메시지는 476,373 bytes였다. 형태 정보와 전체 125개 Concept 목록을 추가했기 때문이다. **새 조회→메시지 단계 자체는 바이트 기준 압축이 아니다.** 개념 목록을 필요할 때만 전달하는 후속 절제 실험이 합리적이다.
3. 현재 작업은 구간 치환이므로, 선택된 계획을 코드가 적용하고 Qwen은 선택·필요 시 검토만 맡는 더 단순한 대안이 있다. 이미 `apply_plan`이 검사 기준 문장을 만든다. 다만 이번 결과의 실패 출력을 이 코드로 교정해 성공으로 다시 집계하지 않았다.
