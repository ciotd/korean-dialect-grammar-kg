# 연구 버전 관리

2026-11-04부터 적용. 저장했다고 좋은 성능이 검증된 버전은 아니다.

## 저장 단위와 채택

1. 의미 있는 수정 묶음을 시작하기 전과 완료 후 복구 체크포인트를 만든다. 매 글자 수정마다 커밋하지 않는다.
2. 체크포인트는 코드·문서·공유 가능한 KG·실험 설정/요약을 Git 커밋으로 묶는다. 실험은 별도 Run ID로 당시 요청·응답·코드/KG 사본을 보존한다.
3. 후보와 비교 기준 버전을 구별한다. 더 최신이라는 이유로 운영 기준을 바꾸지 않는다. 동일 입력·모델·설정에서 시제/의미/높임 오류, 자연스러움 및 비용을 비교하고 채택 이유를 DECISIONS.md에 남긴다.
4. 악화/불확실한 후보도 보존한다. 되돌릴 때 기존 작업 폴더를 강제 초기화하지 않고 해당 커밋의 별도 worktree에서 복원·검사한다.
5. 푸시는 로컬 커밋과 구별해 기록한다. 체크포인트 생성 도구는 자동 푸시하지 않는다.

## 현재 폴더와 원격 기록이 다른 이유

GitHub main은 2026-10-27의 `26291f5`이다(2026-11-04 API 확인). 현재 G: main HEAD는 10월13일 `fd774a9`이다. 10월27일 당시 Git 내부 쓰기 제한으로 C: 별도 checkout에서 업로드했기 때문이다. 따라서 G:에서 untracked로 보이는 파일이 모두 GitHub에 없는 것은 아니다.

새 체크포인트는 origin/main 또는 직전 체크포인트를 부모로 하고, 임시 Git index로 작성한다. 기존 main·작업 파일·사용자의 index는 변경하지 않는다. 원격에만 있는 누락 파일은 삭제로 처리하지 않고 부모에서 보존하며 manifest에 표시한다. 실제 삭제 의도가 생기면 별도 검토한다. 체크포인트는 `checkpoints/<UTC시간>` 브랜치에서 찾는다.

## 명령

```powershell
python tools/research_checkpoint.py prepare
# 출력된 secret_findings가 없고 포함/제외 목록을 확인한 다음:
python tools/research_checkpoint.py commit --directory "local/version_history/<출력된 시간>"
```

prepare는 후보 파일의 SHA-256과 비밀정보 의심 위치를 기록한다. commit은 파일이 바뀌지 않았는지, Git에 저장되는 바이트가 같은지 검사한다. 자동 비밀정보 검사는 완전한 보안 검사를 대체하지 않는다. parent/HEAD/커밋/ref와 로컬 비공개 사본 목록은 `local/version_history/<시간>/manifest.json`에 남는다.

원본 PDF·전체 추출 본문·AI-Hub 파생 자료·인증정보·private/local·로컬 에이전트 설정·임시 work는 Git에서 제외한다. 비공개 KG graph.json과 data/derived_private는 **로컬 private_state 사본**으로만 보존한다. 이는 GitHub에 업로드하지 않는다.

**복원 한계:** 3GB 이상인 기존 비공개 실행 기록 전체, 외부 문헌, 인증정보, 설치환경, 실행 중 Neo4j DB는 이 도구가 복제하지 않는다. 실행 기록은 원래 Run 폴더에서 유지한다. 같은 디스크의 체크포인트는 디스크 고장 대비 백업이 아니다. 다른 PC로 이동할 때는 권한 있는 비공개 자료를 별도로 옮겨야 한다.
