01. Architecture Overview

이 산출물은 문헌 근거를 연결한 탐색용 KG입니다. 문장 변환기나 실행 가능한 문법 규칙 엔진은 아닙니다. 설계 명세, 원문 진술, Builder의 개념 매핑을 서로 구별합니다.

숫자의 의미: 전체 노드 수에는 문헌 위치·검토 기록·관리 노드가 포함됩니다. 지식의 정확도나 방언 생성 성능을 뜻하지 않습니다. 직접 대조한 좁은 Claim과 기존 원자의 검증 범위는 다릅니다.

원형 배치는 탐색용입니다. 모듈을 누르면 해당 항목 목록이 열립니다. 공통 척추 노드는 이번에 추가한 관리 노드이며, 기존 911개 항목에 있었던 ID나 고정 실행 루트가 아닙니다.

02. 실제 노드·관계·근거 탐색

검색 또는 문헌·모듈 필터로 시작점을 바꿀 수 있습니다. 노드를 선택하면 실제 연결과 원문 발췌를 확인할 수 있습니다.

03. Schema Specification

기존 Schema의 37개 엔터티 유형·40개 관계 계약을 원문 그대로 보존했습니다. 현재 생성된 관계 유형과 향후 실행기에서 사용할 계약은 구별합니다. 기존 cross_reference는 의미 참조이며 실행 순서가 아닙니다.

이번에 추가한 최소 관계

자동 인용 위치는 cites_source_span, 직접 대조한 진술은 Claim → analyzed_by → SourceSpan, 공통 개념으로의 해석은 interpreted_as로 구분합니다. 근거 위치가 있다는 사실을 규칙의 참·적용 가능성으로 승격하지 않습니다.

04. Source-to-KG Mapping
원문 7종의 파일 해시와 페이지 수를 확인했습니다. 이전 전체 문헌 분담 검토와 이번 구축의 직접 진술 대조는 별도 작업입니다. 이번에는 전쪽 텍스트를 추출하여 인용 위치를 연결하고, 아래 Claim의 문맥을 직접 대조했습니다. 모든 기존 항목을 새로 독립 의미 검증한 것은 아닙니다.
문헌 × 최종 관리 모듈
셀은 해당 문헌을 인용하는 기존 방언 항목 수입니다. 0은 이번 기존 분류에 항목이 없다는 뜻이며 언어현상 자체가 없다는 뜻이 아닙니다. 셀을 누르면 목록을 볼 수 있습니다.

05. Graph Statistics
모듈 간 연결 수는 해당 모듈에 닿는 기존 관계 수입니다. 같은 연결이 양쪽 모듈에 나타나므로 합계를 전체 관계 수로 사용하면 안 됩니다. 문헌별 수치도 복수 문헌 인용 항목이 중복될 수 있습니다.
