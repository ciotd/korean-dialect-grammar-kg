# 최소 지시 → 시스템 지시 → KG 정보 분리 진단

2026-11-04 사용자 승인 범위: 세 조건을 비교하고 원인이 확인되면 수정·새 개발 문장·50건까지 연결한다. 최종 작성자는 Qwen이다.

## 첫 실험

- 입력: 직전 r7 50건에서 아/어요 계열 지시가 전달됐던 **9개 위치 전부**. 새 9문장 데이터셋이 아니며, 긴 문장에서는 해당 한 위치만 수정한다.
- 조건 A: 짧은 시스템 지시 + 원문·위치·“마지막 요만 예로 바꾸기”.
- 조건 B: A와 완전히 같은 사용자 패킷 + 기존 연구용 시스템 지시.
- 조건 C: B와 같은 시스템 지시 + 기존 KG action 필드를 추가한 패킷. A/B의 명시적 수정 지시는 그대로 둔다.
- 고정: 원문 전체, 선택 위치, 수정 목표, 모델, schema, temperature=0, top_p=1, thinking=false, seed, max_tokens=2048. 조건별 3회 반복. 총 81생성 호출. 분석·조회 재실행 없음.
- A/B 차이는 시스템 지시 전체다. C에는 기존 form/composition과 명시적 수정 지시의 불일치 가능성이 포함되므로, B/C 차이를 단순히 토큰 길이의 효과로 부르지 않는다.
- 채점: 대상의 마지막 요만 예로 바꾸고 그 외 글자를 유지했는지. 이는 기계적인 지시 수행 검사이며 자연스러운 방언 정답률이 아니다. 완성형 비교값은 평가에만 사용한다.
- 원문/응답/패킷/실패/조건/해시/반복 변동을 저장하고 기존 관리 workflow에 등록한다.

## 결과에 따른 분기와 종료 기준

1. A가 반복 성공하고 B 또는 C에서 실패: 처음 차이가 생긴 조건을 우선 수정하되, 시스템 지시의 길이와 개별 문구 효과를 혼동하지 않는다.
2. A부터 실패: KG 지식 추가로 해결됐다고 주장하지 않는다. 실제 요청·원시 응답·출력 형식 제약을 점검하고, 일반 문자열 편집과 방언 작업 지시의 차이를 추가 진단한다.
3. 성공 조건이 확인되면 문장별 예외 없이 공통 전달 경로에 구현한다. 아직 노출하지 않은 개발 문장으로 검사한 뒤 기존50 전체를 실행한다.
4. 비교가 불안정하면 원인 미확정으로 기록한다. 실패 대안을 운영에 채택하지 않고 다음 분리 진단 또는 필요한 사용자 판단을 구체적으로 제시한다.

## 검토자

- 기존 Orca Codex: 조건 고정·실제 요청·출력 처리·집계 검토. 코드/KG는 직접 수정하지 않는다.
- 기존 Orca Claude: 지시 수행 검사와 언어학적 정당성 구분, 시제·높임 보존 해석 검토. 문헌 전체 반복 검토는 하지 않는다.
- 모든 의견은 문제 위치 → 실제 근거 → 수정안으로 기록한다. 독립 검토는 모델 합의에 의한 사실 인증이 아니다.
