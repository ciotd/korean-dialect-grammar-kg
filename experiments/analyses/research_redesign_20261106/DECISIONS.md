# 검토 후 바뀐 계획과 다음 착수점

이번에는 **기존 자료 재집계, 선행 연구 확인, 두 검토자의 독립 의견과 상호 검토, 계획 수정**을 했다. Qwen 실험과 KG 수정은 하지 않았다. 26묶음 전체를 재정제하거나 전체 문장 검사를 실행한 결과도 아니다.

## 핵심 판단

현재 KG에는 12개 문법 모듈과 연결 자료가 있다. 그러나 7종의 정보가 모두 조건·표현·예외로 정제됐는지, 모든 연결이 적절한지까지 검증 완료된 상태는 아니다. 원본은 문헌 내용·설계·출처가 섞인 자료 그래프이며, 최신 후보에서 조건으로 조회하는 용법은56개다. 노드1625개를 규칙1625개로 읽거나, 56/1625로 완성도를 계산해서는 안 된다.

## 독립 검토와 상호 검토에서 실제 바뀐 것

| 논점 | 검토에서 확인한 반론 | 최종 계획에 반영 |
|---|---|---|
| 모든 노드를 예문으로 통과 | 문헌·분류·출처와 적용 조건은 역할이 다름 | 전체 ID 구조·출처 검사 + 용법의 긍정/반례/모호성 검사로 분리 |

| 분석 두 역할 병렬 | 구조가 다르면 기능 판단 대상도 달라짐 | 첫 후보를 구조→의미의 순차 분업으로 변경. 구조 오류 전파는 별도 위험으로 기록 |

| 생성 후 경고로 한 번 재작성 | 이전 유사 실험 실패, 방언 재분석 경고의 오탐 가능 | 즉시 기본 채택하지 않음. 같은3호출의 일반 재검토와 역할 분담을 비교 |
| 그래프 대 조건표 | 같은 지식·같은 선택·같은 요청이면 언어 출력 차이를 기대할 근거 없음 | 반환값·요청 동등성부터 검사. 같은 요청이면 중복 생성 대신 재사용과 비용을 명시 |
| 사람 판단 우선 | 운영 목표 선택과 문헌 사실 변경은 다름 | 원문 보존 + 사용자 승인 지식·정책층 분리. 실제 충돌만 사용자 판단 |

### 검토자 의견 중 그대로 채택하지 않은 내용

- SourceAtom721개를 전부 ‘출처·위치 메타데이터’로 분류한 설명은 잘못이다. 문헌 내용 항목이다. 이 때문에 ‘85%가 쓸모없는 메타데이터’라고 결론내리지 않는다.
- 기존12용법에는 `rule_type` 속성이 없다. 새44개는 표현 후보41·보존2·주의1이다. 기존12개를 속성 확인 없이 합쳐 표현 후보53개라고 보고하지 않는다.
- ‘-어서이지만 이유’ 같은 일반적인 반례는 대상 규칙에 따라 오답이다. 해당 규칙이 이유를 허용하면 반례가 될 수 없다.
- 전달량 감소 후 차이가 작다고 망각 가설을 곧바로 기각하지 않는다. 검사한 조작의 효과와 불확실성을 보고한다.
- Kiwi가 ‘안/못’을 부사로 분류한 것과 부정 정보를 전달하지 못한 것은 같은 문제가 아니다. 위치·연결·전달 기록으로 판단한다.
- 모델 여러 명이 동의했거나, 출처 문장이 실제로 있다는 것만으로 문법 해석을 확정하지 않는다.
- 지역·세대를 모든 입력의 새 필수 조건으로 만들지 않는다. 기존 현대 경상도 목표를 유지하고 충돌 항목만 구체적으로 묻는다.

## 단계마다 Claude와 GPT를 어떻게 쓰나

| 단계 | Claude 검토자 | GPT 검토자 | 리드의 결과물 |
|---|---|---|---|
| KG 검사·정제 | 문헌의 뜻·조건·표현·예외와 현대 사용의 충돌 | 노드·관계·조건의 표현, 누락·중복·원문 매핑 | 검사대장, 정제 후보, 사람 판단이 필요한 쟁점 |
| 원인 진단 준비 | 수정 분석과 필요한 결합 설명의 언어적 근거 | 어떤 변수만 바뀌는지, 실제 전달 내용·호출 예산 | 네 조건 요청 예시, 기대 결과·종료 기준 |
| Qwen 분업 설계 | 역할 경계에서 잃는 문맥·높임·시제·부정 | 위치 ID·인계 형식·충돌·호출 통제 | 실행 가능한 역할 명세와 단일 방식 대조 |
| 실험 결과 검토 | 원문→분석→지식→출력 중 의미가 처음 달라진 위치 | 원시 기록·집계·버전·실패 분모·데이터 누출 | 입력별 원인 증거와 채택/미채택 결정 |
| 논문 평가 | 화자 평가 지침과 구체 오류 항목 보조 | 공정 비교·불확실성·비용·주장 범위 | 사람이 최종 판단한 품질 결과와 재현 자료 |

두 검토자는 각자 독립 의견을 작성한 뒤 상대와 리드의 초안을 읽었다. 리드는 반론을 검토해 계획을 수정했다. 두 모델이 동의했다는 사실을 독립적인 언어 사실 증명으로 쓰지 않는다. 최종 평가 참조답은 이 개선 루프에 전달하지 않는다. 검토 원문은 아래에 공개해 채택하지 않은 의견도 확인할 수 있게 했다.

## 다음에 무엇부터 할까

| 순서 | 실제 작업 | 종료 조건 | 결과가 예상과 다르면 |
|---|---|---|---|
| 1 | 전체 노드·관계 역할별 대장, 56용법·57분기의 특징값 검사 목록 작성 | 고유 ID 분모·검사 대상·근거·미확인 사유가 모두 연결. 조회 구현 검사 통과 | 잘못된 조건·연결은 수정, 미확인 용법은 완료로 세지 않음 |
| 2 | 7종 원문→KG 누락·충돌 대조를 병행하며 검사 예문 작성 | 시험할 범위는 근거·조건·반례 확인. 문헌 전체 미완료는 계속 표시 | 출처 부족·현대 표현 충돌은 선택지와 영향 범위를 사람에게 제시 |
| 3 | 저장/수정 분석 × 기존/관리정보 축소의 네 조건 명세 | 기존 노출 입력16개 선정 이유·ID, 실제 요청, 평가 기준, 3반복 최대192생성호출 예산 명시 | 지식 내용까지 달라지면 투영 수정. 예상값이 불확실하면 진단 개입으로만 표시 |
| 4 | 먼저 위 진단, 다음 Kiwi·분석 분업·생성 분업을 각각 비교 | 어떤 단계가 개선됐고 어디가 악화됐는지 비용과 함께 확인 | 동일 지시 반복 중단. 더 큰 모델 또는 다른 역할 구조 비교로 이동 |
| 5 | 기본 범위·모델·구조 고정 후 검색 방식과 독립 화자 평가 | 같은 원천·예산의 비교 및 새 문장 블라인드 평가 | 효과 없음·동등·악화도 그대로 보고 |

**이번 종료점은 검토를 반영한 연구 계획이다.** 다음 단계의 검사 목록·실제 요청·192호출은 아직 만들거나 실행한 것이 아니다. 16개는 새 데이터셋 이름이 아니라 기존80개 중 진단용으로 사전 선정할 규모안이다. 기존50·개발30·재사용18은 독립 최종평가로 다시 이름 붙이지 않는다.

사용자에게 지금 수백 항목의 승인을 요청하지 않는다. 다음 착수는 모델 호출 없는 검사대장·조건검사·실제 요청 명세 준비이며, 연구 목적·생성 주체를 바꾸지 않는다. 문헌과 현대 표현의 구체적 충돌, 다음 모델 환경, 사람 평가 인력은 해당 결정을 할 시점에 이유·선택지와 함께 요청한다.
