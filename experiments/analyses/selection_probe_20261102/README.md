# 선택 계획 비교 진단 — 2026-11-02

## 무엇을 확인하는가

같은 표준어·저장 분석·전체 전달 카드·Qwen 워커·검사 코드를 유지하고,
과거 자동 선택 계획을 검토자가 고른 계획으로 바꾸면 무엇이 달라지는지 확인한다.
실제 Qwen을 호출하는 원인 확인 실험이다. 완성 시스템의 최종 성능평가가 아니다.

- 검토 대상: 승인된 회귀 데이터 50문장 전부.
- 조건: 저장 선택 / 검토 선택 × 3회 반복. 워커만 실행하며 Single/Multi 비교가 아니다.
- 처리 기록: 300개. 사전 준비상 실제 호출: 219회(기존 41×3, 검토 32×3).
- 양쪽 실제 생성 가능: 28문장×3=84쌍. 이 중 10문장은 의미상 같은 선택이다.
- 검토 후보 미확보: 18문장. 성공·원문 유지로 세지 않는다.
- LONG003의 미전달 질문 카드는 추가하지 않는다. 남은 세 위치만 검토한다.
- 기존 잘못된 형태 번호(DEV012)는 대조군에서 고치지 않고 차단을 기록한다.

## 무엇을 고정하고 무엇을 바꿨나

고정: 원문, 형태소 및 문법 분석, 카드 내용·순서, 워커 프롬프트, 모델 설정,
현재 검사·활용 보정 코드. 양쪽 모두 전체 카드 목록을 보낸다.

변경: 선택 카드/형태/원문 위치, 편집의 적용·보류, 묶음·의존관계·생략.
선택 계획 전체의 진단이며 단일 카드 하나만의 효과라고 주장하지 않는다.
자유로운 옛 instruction/reason은 양쪽 같은 문장으로 재작성한다.

모델에는 전체 정답이나 완성 교체 단어를 주지 않는다. 내부 검사용 plan의
suffix_projection(프로그램이 미리 만든 활용 후보)은 모델 전달물에서 제외한다.
이전 결과와의 차이는 인과 비교로 쓰지 않는다. 이번에 새로 실행한 두 조건을 비교한다.

검토 선택은 승인 참조를 알고 작성한 후보다. 언어학적 정답으로 인증한 것이 아니며,
새 문장 일반화 또는 자동 선택기의 성능을 뜻하지 않는다. 부분 목표와 문장 전체를 구분한다.
같은 선택이라도 편집 ID·계획 해시는 다르므로 요청 바이트가 완전히 같지는 않다.

## 기록과 설명

- `review.py`: 50개 입력의 목표 식별자와 미확보 범위. 모델에 직접 전달하지 않는다.
- `runner.py`: 공통 계획 구성, 조건 고정, 실제 호출, 원시 결과·검사·최종 반영 기록.
- `test_probe.py`: 입력·카드 범위·누출 방지·대조군 보존 등 10개 사전 검사.
- `monitor.py`: 실제 호출 수 기준의 대시보드 진행. 미호출 즉시 처리와 호출 시간을 구별.
- `verify_run.py`: 실행 후 300기록/219요청, 동일 입력, 해시·6개 실행 등록 검사.
- `build_report.py`: 실제 저장 결과에서 사람이 읽는 표와 단계별 사례 생성.
- `private/latest.json`: 이번 실제 실행 폴더 및 6개 Run ID.
- `private/<timestamp>/snapshot/`: 실행 시 코드·자료 스냅숏. 인증정보 제외.
- `private/<timestamp>/results.json`: 모든 반복·조건의 결과.
- `private/report.html`: 원문·참조·두 결과·원시 제안·검사·보정·최종 반영을 보는 보고서.
- `private/reviewer.json`: 기존 독립 검토자의 구조 점검 및 첫 반복 검토.

실제 입력·생성·참조 및 문헌 파생 자료는 private에 두며 공개 커밋하지 않는다.
API 인증정보는 기존 `test.py`를 안전하게 읽으며 요청 저장물에는 기록하지 않는다.

## 재현

저장된 실행을 다시 조회하려면 `build_report.py`와 `verify_run.py`를 실행한다.
`runner.py --run`은 새 Qwen 호출을 발생시키므로 단순 보고서 재생성에 쓰지 않는다.
실행별 freeze/snapshot과 Python 버전, 모델명, 프롬프트, seed, usage를 함께 보존한다.
서버가 공개하지 않은 체크포인트·GPU 정보와 모델의 비결정성은 남은 한계다.

## 결과 해석 원칙

변경 수는 자연스러움 정확도가 아니다. needs_review로 모델이 거절한 것,
검사가 막은 것, 호출 실패, 후보 미확보를 구분한다. 현재 원본 result.status가
unchanged여도 edit_trace의 raw_action=needs_review를 보고서에서 별도 집계한다.
Qwen이 생성한 raw와 프로그램이 고친 after를 구별한다. 같은 오류 코드의 중복 기록은
한 처리 기록 안에서 중복 제거하여 집계한다. 실패·미호출의 output_text는 null이고
원문 대체 후보 fallback_original은 별도 필드다.
