# 문장 분석에서 문법 지식까지: 2026-11-07 점검

새 KG가 예전과 같은지에서 한 걸음 더 나아가, 실제 분석값으로 필요한 지식에 도달하는지 확인했다. 이번 작업은 진단이며 문법 규칙이나 생성 코드를 고치지 않았다.

## 수행 결과

- 저장된 실제 분석 99기록·802단위로 규칙 도달 현황을 재생했다. 반복 입력이 포함되므로 99개 독립 문장으로 세지 않는다.
- 기존 50문장에 리드가 지정한 90개 점검 지점을 대조했다. 49개는 지식이 선택·전달되었다. 이는 번역 정확도가 아니다. 전체 문법 현상을 빠짐없이 정답 라벨링한 것도 아니다.
- 규칙 56개를 대상으로 새 점검 문장 57개를 준비하고 형태 분석·질문 형식을 검사했다. Qwen 연결 시도가 실패하여 새 의미 분석·생성은 실행하지 않았다.
- Neo4j에 새 KG 1,491노드·5,037관계를 별도 버전으로 추가했다. 파일/DB 속성 일치와 기존 DB 보존을 검증했다. 실제 파이프라인의 조회기는 여전히 파일 기반이다.
- 초기 진단 중 6개 분류를 재검토하여 정정했다. 초기 결과도 남겼다. 현재 판단은 `reviewed_summary.json`을 기준으로 읽는다.

## 핵심 발견과 다음 순서

1. ‘어디’의 장소 역할과 의문 성격을 양자택일하게 만든 분석 질문을 분리한다. 서로 동시에 참일 수 있다.
2. ‘하지 마’의 본동작/보조동작과 앞뒤 절 연결 후보를 명확하게 제시하고 잘못된 방향을 검사한다.
3. 어떤 값을 골라도 규칙 선택이 달라지지 않는 조건 때문에 조회를 막는지 점검한다. 모든 미확정 값을 허용하는 변경은 하지 않는다.
4. 규칙 설명이 허용한다고 말하는 범위와 실제 조건의 차이를 원문에 대조한다. 원문 근거는 실행 그래프 밖에서 유지한다.
5. 수정 후보는 새 버전에 두고 반례·새 문장·기존 50문장으로 검사한다. 이후 Qwen 최종 생성에서 시제·어간·높임과 자연스러움을 확인한다.

종료 기준은 필요한 지식에 실제 도달하며 부당한 적용이 늘지 않는 것이다. 후보 수 증가나 코드 검사 통과만으로 품질 개선을 주장하지 않는다. 개선이 없으면 같은 프롬프트 강조를 반복하지 않고 분석 형식·관계 표현을 재검토한다. 문헌 부족이나 해석 충돌은 사용자 판단 대상으로 분리한다.

## 산출물과 한계

- `latest.json`: 최초 진단 기록 위치. `report_latest.json`: 정정 반영 보고서 위치.
- `neo4j_latest.json`: 실제 적재·비교 결과 및 DB 논리 백업 위치.
- `cases.py`, `audit.py`, `report.py`: 점검 대상·재생·집계와 보고서 생성.
- `private/<run_id>/`: 원시 판정, 수동 값 보충 진단, 정정 이유, 50문장별 보고서. 문장과 문헌 인용은 비공개로 보존한다.

7종 전체의 재정독이나 KG 전체 의미 검증을 완료한 작업은 아니다. 이번에는 관련 규칙 7개의 분리된 출처 발췌를 추가 대조했다. 외부 Claude/Codex 검토자를 새로 호출하지 않았으며 독립 검토 완료로 표시하지 않는다. 다음 검토에서는 언어 검토자가 질문·문헌 해석을, 코드 검토자가 조건·관계 검사와 비교 통제를 확인하도록 한다.

사용자는 조회와 생성의 차이, 한 규칙과 복수 조건 분기의 차이를 두 퀴즈에서 정확히 구분했다. 추가 개념 확인을 의무적으로 반복하지 않는다.
