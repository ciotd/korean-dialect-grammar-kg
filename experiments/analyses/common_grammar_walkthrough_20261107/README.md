# 공통 문법 136개와 후보 용법 56개 설명

## 수행 범위와 연구 질문

2026-11-07 사용자는 공통 문법 틀의 구성 근거와 현재 용법의 연결을 실제 사례로 이해할 수 있도록 요청했다. Archify를 명시적으로 설치·사용하도록 요청했으며, 공식 `tt-a1i/archify`의 `archify` 패키지를 로컬 Codex 스킬 경로에 설치했다.

이번 질문은 **공통 설계가 무엇을 표현하며, 현재 실행 용법과 어떤 관계가 실제 저장되어 있는가**이다. 연구 전체의 의미·높임 보존 검증에 앞서 설계·구현·실행·평가의 구별을 사용자가 설명할 수 있도록 돕는다. KG 우월성이나 새 품질 개선을 평가하는 실험은 아니다.

## 산출물

`private/20261107T033934996218Z/guide.html`을 연다. 전체 그림 → 실제 사례 → 공통 136개 → 용법 56개 → 근거·판정 기준의 다섯 화면이다. 공통 항목은 12분야 필터, 검색, 직접 연결 여부로 탐색하며 용법과 양방향으로 이동한다.

- `overview.html`: 설치한 Archify로 생성·검사한 설명 페이지. 자료와 설계의 관계, 실행 흐름, 조건 용법 구조, 요청 실패 경로의 네 그림을 포함한다.
- `candidate.archify.md`: Archify 원고. 라이브 소스가 아닌 확인한 로컬 파일을 출처로 명시한다.
- `mapping.json`: 136개·56개 전체 ID와 직접 연결 55개.
- `manifest.json`, `snapshot/`: 입력 해시, 관련 코드·설계·후보 KG 사본, 과거 결과의 요약과 선택 사례 원본.
- `ui_validation.json`, PNG: 화면 동작·레이아웃 검사 기록.

예문을 포함한 보고서는 비공개 산출물로 보존한다. 공개 가능한 설명 도구와 문서만 복구 체크포인트에 포함한다. 연구 KG와 실행 코드는 바꾸지 않았다.

## 확인 결과와 한계

136개는 세부 책임 125개와 묶음 인터페이스 11개다. 그래프 유형으로는 AnalysisConcept 48, Construction 54, GrammarFeature 23, AggregateInterface 11이다. 설계 기록은 별도의 공통 한국어 문법책 전체가 제공되지 않았다고 명시한다. 문헌의 구별을 재사용 가능한 분석·보존 계약으로 만든 설계이며 한국어 문법의 완전성을 입증한 목록이 아니다.

공통 항목 121개에는 문헌 위치 목록이 있고 15개에는 없다. 후자의 11개는 묶음 인터페이스다. 문헌 위치의 존재는 해당 설계의 모든 내용이 원문으로 입증되었다는 판정이 아니다. 이번 작업에서 원문 페이지를 전수 의미 대조하지 않았다.

현재 후보 그래프에는 공통 항목 29개와 용법 29개를 잇는 직접 연결 55개가 있다. REFINES 23개, DESCRIBES_USAGE 32개다. 직접 연결이 없는 공통 항목 107개와 용법 27개는 **연결 대장상의 공백**이며 곧바로 미구현 개수나 구현률이 아니다. 현재 코드는 모든 G_* ID를 함수로 호출하지 않고 별도 용법의 조건을 읽는다.

136개 전체에 이번 설명을 위해 작성한 예문을 붙였다. 이는 실행·검증한 자연어 시험셋이 아니다. 과거 통합 실행 4개, 결과 기록 100건(입력 문자열 80종)을 읽었으며, 이들 기록에서 31개 용법 ID의 전달 예가 확인된다. 판본과 반복이 섞인 역사적 기록이므로 현재 56개에 대한 검증률로 사용하지 않는다. 모든 카드에 당시 기록과 현재 판본의 재검증을 구별한다고 표시했다.

실제 사례의 핵심은 IG019 조건 용법의 전달, IG006 대명사와 설명 의문의 동시 전달, IG013 요청 용법의 미전달이다. IG013은 ‘주이소’가 출력됐지만 조건 충족 용법 전달과 사용 선언은 0개였고 참고 문헌 항목 12개는 전달됐다. 따라서 방언처럼 보이는 출력만으로 특정 KG 용법이 적용되었다고 판정할 수 없다.

새 Qwen 호출 0회, KG 수정 0건, 새 독립 품질 평가 0건이다. 과거 조회 검사에서 추출한 57분기의 조건을 설명에 사용했으며 당시 후보 KG·조회 코드와 현재 파일의 해시 일치를 확인했다.

## 검증·종료 기준

모든 공통 항목과 용법이 화면에 있고, 예문과 실측 기록을 구분하며, 직접 연결을 실제 그래프에서 재계산하고, 입력 파일이 바뀌지 않았음을 확인하는 것이 이번 종료 기준이다. Archify의 validate/deliver/check가 통과했다. 별도 Edge 브라우저에서 136·56개 카드, 검색, 양방향 이동, 데스크톱/모바일 가로 넘침 여부를 검사했다. 선택 화면을 캡처해 시각적으로 검토했다. 이는 UI와 기록 대응 검사이지 문장 품질 평가가 아니다.

## 다음 작업과 분기

우선 사용자가 세 대표 사례를 따라 설계·연결·조회·생성의 차이를 익히고 분야별 항목을 읽는다. 그 다음 55개 연결의 타당성과 연결 공백을 원문·코드와 대조한다. 연결만 보충해서 언어 검증 완료로 처리하지 않는다.

이 대응이 설명 가능해지면 전체 KG의 조건·관계별 자연어 예문 설계와 실제 파이프라인 도달 검사로 이어진다. 모호한 설계나 부적절한 연결이 발견되면 근거를 확인해 새 판본의 수정 대상으로 남긴다. 현재 기록이 부족한 부분은 미확인으로 두며 성공 사례를 만들어 채우지 않는다.

별도 검토자는 사용하지 않았다. 계산·조회 기록과 코드로 확인했으며 독립 언어학 검토를 받았다고 주장하지 않는다. 이번 설명 자료 작성에 추가 사용자 승인이나 새 실험 범위 결정은 필요하지 않다.
