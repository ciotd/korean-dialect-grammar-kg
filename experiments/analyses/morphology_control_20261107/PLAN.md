# 형태 분석만 교체하는 통제 비교

질문: 같은 의미 분석·조회·작성 조건에서 형태소/품사 공급자를 Qwen 또는 Kiwi로 바꾸면 어떤 KG 연결과 출력 차이가 생기는가? KG 우월성 또는 자연스러움 정확도 검증은 아니다.

## 고정 및 변경

- 입력: 기존 개발 6문장. 정답/승인 참조를 요청에 넣지 않는다. 독립 최종 평가가 아니다.
- 공통 어절 위치: 같은 원문 정규식으로 결정. 문장/절 구획은 이전 Qwen 실행의 최초 구조 분석에서 얻은 구획을 양쪽에 동일하게 고정한다. 구획 자체의 정확성/발견 능력은 이번 실험 대상이 아니다.
- 바꾸는 것: 어절별 형태소 기본형과 품사. Qwen은 새 전용 형태소 분석 요청 1회/문장, Kiwi는 기존 tokenize 기능. Kiwi 결과를 Qwen에 제공하지 않는다.
- 공통 연결: 기존 observe_units로 같은 방식으로 단위/형태 특징을 산출한다. 의미상 시제·기능·높임·관계는 기존 Qwen meaning 담당. 형태소의 생략/오분류로 생긴 단위 차이는 처치의 결과로 기록한다. 어간/어미를 다시 별도 모델 필드로 중복 추측시키지 않는다.
- 공통 후속: 동일 PROMPTS[meaning/writer/reviewer], 같은 KG·조회코드·문자예산18000·모델·seed20261107·호출 설정. 실제 분석값과 전달 KG가 달라지는 것은 의도된 경로다. 값을 강제로 같게 만드는 실험이 아니다.
- 구조 재분석/자동 재작성은 양쪽 모두0. 검토는 같은 1회로 기록만 하고 출력을 덮어쓰지 않는다. 최종 문장은 writer의 실제 Qwen 응답이다.

## 실행과 종료

코드·통제 검사 및 두 검토자 설계 확인 후 6쌍 실행. 문장별 Qwen/Kiwi 순서를 번갈아 바꾼다. Qwen 형태 분석6 + 각 경로 의미/작성/검토18씩, 최대42호출. 자동 네트워크 재시도0. 같은 오류로3회 연속 실패 또는 설정된 마감이면 중단, 원본을 보존한다. 실패 분모를 숨기거나 실패한 방식만 다시 시도하지 않는다.

실행 전 검토 반영: 연속 실패는 백엔드별 처리 실패로 세어 다른 방식의 성공으로 초기화하지 않는다. Qwen 형태 분석의 자유 설명은 원본에 보존하되 후속 모델에 전달하지 않는다. 공통 표기 규약은 실제 Kiwi 출력에 맞춰 아요/어요/에요/ㄹ게요를 EF 하나로 설명했다. 이는 해당 표기를 사용하는 현재 KG에 연결하는 능력 비교이며 언어학적 분석의 절대 정답을 정한 것이 아니다. UNKNOWN 형태가 있는 단위는 과거/선어말 유무를 null로 남기고 적용 보류한다. 형태 단위가 없어진 오류를 정답으로 채우지 않는다.

분석 형태·단위·의미 응답→조건의 true/false/unknown→전달/보류→실제 출력과 비용을 문장별 대조한다. 보존 오류는 원문과 출력 근거로 정성 검토하고, 참조 없는 자연스러움 정확도는 계산하지 않는다. 한 번의 쌍 비교이므로 모델 변동과 표본 한계를 남긴다.

## 해석과 다음 단계

형태 조건 연결이 일관되게 개선되면 그 방식을 다음 개발 기준 후보로 권고한다. 양쪽 모두 실패하면 공통 연결/의미/생성에서 처음 어긋난 곳을 제시한다. 이번 공통 연결 자체도 이전 분업과 다르므로 이전 실험 대비 개선 전체를 분석기 효과라고 하지 않는다. 이 비교로 기본 경로를 자동 전환하거나50건으로 확대하지 않는다. 반복 프롬프트 조정은 하지 않는다.

Claude: 언어 해석·실제 정보 전달·출력 손실과 과도한 조건차단을 검토. Codex: 단일요인 통제·프로그램/호출/집계·출처 및 버전 기록 검토. 두 검토자는 코드/모델을 실행 변경하지 않고 문제 위치→실제 근거→수정안을 기록한다. 리드가 구현·검사·실행·보고를 담당한다.
