# 9분야 통합 구현·검증 실행 계획

사용자 승인: ①대상확인→②지식정제→③분석/조회확장→④모델생성→⑤통합검증을 하나의 작업으로 수행. 일반 수정·검사는 재승인 없이 진행. 이전 체크포인트 62653e6를 시작 복구점으로 사용한다. 원본 KG·이전 실행은 수정하지 않는다.

연구 질문: 종결어미만 조회하던 제한을 명사/조사/절/보조구성까지 넓혀 문헌 근거가 있는 지식을 실제 입력에 연결할 수 있는가? 이것은 통합 개발 실험이며 KG 우월성의 독립 평가가 아니다.

통제: 기존 Qwen 서버/모델 유지. 사용자 승인 참조50을 생성요청에 넣지 않음. Kiwi는 위치/관찰형태, Qwen은 기능·관계 분석과 최종 문장 생성. 코드가 최종문장을 고쳐 대체하지 않음. 문헌 조건과 구현 범위를 구별. 기존50은 회귀, 새 분야별 대조문은 개발용.

자료: 기존 원본KG 1625/6167, 911고유설계항목, 기존26작업목록, 7문헌 추출본/필요시 PDF. 자동배정/접두어검색을 의미검증으로 처리하지 않음.

실행 예산: 먼저 서버호환성1건과 모듈별 개발 입력의 분석·생성, 이후50건 분석·생성. 기본1회 분석+1회 생성, 자동재시도 없음. 모델 호출 총 상한200회(서버상태조회 별도). 성공 입력만 선정하지 않음. 형식/서버 실패가 연속3회면 해당 실행 중단해 원인을 기록하고 코드결함이면 수정후 새run으로 재개. 의미오류는 필드/전달/생성 단계별로 구분. 같은가설의프롬프트미세수정 반복 금지.
