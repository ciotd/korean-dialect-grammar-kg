# 이번 검토에서 실제로 채택한 것과 남긴 것

## 완료한 수정

| 발견 | 실제 수정 | 확인 |
|---|---|---|
| 내부 연결어미에 기존 종결 용법이 들어갈 위험 | 기존12용법의 종결 위치 조건을 새 통합 그래프에 명시 | 조건·관계 검사, 새 개발30·기존50 실행 |

마지막 관찰 코드 수정은 **50·18 실제 실행이 끝난 뒤** 반영했다. 당시 코드 사본과 실행 결과는 유지했다. 수정 후 모델을 다시 호출한 결과로 기존 출력을 설명하지 않는다.

Codex의 마지막 대조에서는 같은 참고자료의 매칭 형태 배열 순서가 프로세스마다 달라질 수 있는 점도 확인됐다. 내용과 선별 코드는 같았지만 모든 비분석 요청 바이트가 동일한 비교는 아니었다. 이후 코드는 배열을 정렬하고 서로 다른 Python hash seed에서 같은 패킷 해시가 나오는지 검사했다. 기존18 결과는 순서 차이와 반복 편차라는 한계를 가진 개발 관찰로 유지한다.

## 검토 의견을 그대로 적용하지 않은 항목

1. **같은 절의 모든 시제·기능을 같은 값으로 만들기:** 안긴절·연결형·본/보조의 역할 차이를 지울 수 있어 미채택.
2. **모듈 번호만으로 참고자료의 적용 단위를 결정하기:** Codex가 ‘거로 뒤 보조사’ 반례를 제시했다. 해당 필터를 제거하고 명시된 품사·입력 역할이 있을 때만 제외하도록 수정했다.
3. **제목 왼쪽에서 정확한 단어를 못 찾으면 역방향 자료로 보기:** 문구 안의 조사도 있을 수 있다. 명백하게 출력 쪽에만 맞을 때만 역방향 제외하고 나머지는 미정제로 남겼다.
4. **분석 모델이 높임을 잘못 고르면 높임 조건을 없애기:** 미채택. 생성 범위를 넓히기 위해 문법 조건을 지우는 대신 화계와 분석값 대응을 점검해야 한다. 검토자의 ‘-ㅂ시다’ 화계 설명·조건 제거 제안도 추가 원문 확인 전 확정하지 않는다.
5. **모든 축약 조사의 변환 차단:** ‘내/제’의 무변화를 모델이 사용했다고 보고하는 문제는 확인했다. 그러나 모든 축약을 차단하면 명사·조사를 함께 바꾸는 정상 용법도 막을 수 있어 일괄 차단하지 않았다. 사용 ID를 실제 적용 성공 수로 세지 않는다.
6. **관찰 오류처럼 보이는 형태를 일괄 차단하거나 강제 교정:** ‘계세요’의 잘못된 분석은 남아 있다. 새로운 문자열 예외로 덮지 않고, 형태 대안과 문맥 연결을 별도 검토 대상으로 뒀다.
7. **과거 손실에 같은 보존 지시를 더 반복하기:** 이번에도 과거 형태와 전역 보존 지시가 실제 전달됐는데 손실됐다. 기존 연구에서 이미 유사한 강조 실험이 실패했으므로 같은 처방을 성공 근거 없이 반복하지 않는다.

## 현재 채택 상태

- 통합 KG는 출처가 연결된 **실험 후보**다. 전체26묶음의 언어학적 정제 완료나 운영 품질 인증이 아니다.
- 분석 정의 보완은 별도 프롬프트로 보존한다. 특정9확인항목이 나아졌지만 요청·유사·반말 판정의 퇴행이 있어 기본 분석을 무조건 교체하지 않는다.
- 참고자료 축소는 구현·오프라인 재생까지 확인한 대안이다. 이번50·18의 실제 모델 요청에는 미적용이다.
- 현재 코드의 어간 연결 버그 수정은 저장 형태 재검사를 통과했다. 후속 모델 실험의 고정 기준을 만들 때 이 수정 포함 여부를 명시해야 한다.
- Neo4j 운영 DB 교체·GitHub 푸시는 이번 작업에서 수행하지 않았다.

## 다음 순서와 끝나는 기준

1. **분석 질문을 실제 KG 조건과 더 정확히 맞춘다.** 정의를 계속 길게 덧붙이기보다 각 단위가 답할 필요가 있는 특징·대상 관계만 묻는다. 요청·금지·청유·동반/유사·높임 대조를 함께 검사한다. 맞아진 항목 수뿐 아니라 새 오류·보류·관계 생략을 함께 기록한다. 같은 방식의 한 번 보완으로 반복 오류가 줄지 않으면 모델 비교 대상으로 넘긴다.
2. **동일 분석·동일 정제지식에서 참고자료 전달 방식만 비교한다.** 이번 오프라인 대안과 기존 방식의 실제 요청·원시 출력을 비교한다. 문헌 검색을 없앤 효과와 메타데이터 축소 효과를 혼동하지 않도록 조건을 나눈다. 정제 지식이 없는 위치의 자유 생성도 따로 집계한다.
3. **같은 요청으로 생성 모델을 비교한다.** 과거·높임·어간을 지키는지와 비용을 함께 본다. API 모델명만 교체해 곧바로 공정 비교가 되는 것은 아니며 템플릿·출력 형식·토큰 한도를 먼저 맞춘다.
4. **범위를 고정한 뒤 논문 효과 실험으로 간다.** 지식 없음·문서 검색·조건표·그래프를 같은 원천과 생성 모델로 비교한다. 기존50·개발30·재검사18은 독립 최종평가로 쓰지 않는다. 새 쉬운 문장의 블라인드 사람 평가가 종료 기준이다.

26묶음의 미완료 정제는 이와 별개로 계속 대장에서 추적한다. 사동·피동·수사·관형/인용과 일반 어휘 범위는 특히 부족하다. 실제 문헌 근거가 없는 용법을 실험 성공을 위해 채워 넣지는 않는다.
