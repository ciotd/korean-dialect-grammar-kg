## 그대로 채택하지 않은 해석

1. Claude의 ‘주어가 생략됐으면 subject_honorific=absent’ 제안은 채택하지 않는다. ‘어디 가세요?’처럼 주어가 생략돼도 높임 표현이 나타날 수 있다. 주어 생략·인칭 하나만으로 높임을 확정하는 일반 규칙을 만들지 않는다. 주체 높임의 정의와 실제 표지·어휘·범위 대조가 필요하다.
2. 금지/약속과 진행/과거가 언제나 충돌한다는 전역 규칙은 만들지 않는다. 인용·내포·시간 기준과 복합 보조구성이 있기 때문이다. 좁은 진단 예를 보편 금지 조건으로 올리지 않는다.
3. 현재 null 차단을 ‘조회기의 구현 버그’로 단정하지 않는다. 현재 정책대로 동작한 사실과 해당 KG 조건의 필요성을 구분한다. 이 정책을 이번 분업 비교와 동시에 완화하지 않는다.
4. 단일 모델의 오류가 질문 부하 때문이라는 결론은 미확정이다. 12개 기록만으로 원인을 확정하거나2명이 최적이라고 증명하지 않는다. 정의의 문제·형태/범위 오류·모델 지식 부족·생성 정보 무시도 남는다.
5. Claude가 제시한 +40~50% 토큰/수 초~20초 지연은 분업의 실측이 아니다. 최종안에서는 인용하지 않고 실제 토큰·호출·전체 지연 측정 계획만 제시한다.
6. 초안의 관계 역할14종은 실제 저장된 스키마13종으로 정정했다. 의미11필드 이외의 grammatical_role/clause_key/related_unit_ids 및 제안·진단 배열도 빠뜨리지 않는다.

## 구현 전에 고정할 계약

- 표준어 원문/스냅샷 버전+단위 ID+필드로 병합하며, 담당별 질문 목록을 실제 KG와 생성 보존 요구로 생성해 누락/중복을 검사한다.
- 첫 비교에서 구조 범위는 고정. clause_key를 두 의미 담당이 중복 작성하지 않는다. 보조 본/보조 명시표가 해당 관계의 단일 권위 필드다.
- 모든 관계에 동일절을 강제하지 않는다. 관형절 수식·절 연결 등 실제 관계별 종류/방향/범위 검사를 유지한다.
- 보조 의미·시제·높임·화행의 정의는 같은 문법 사실을 표현해야 한다. 단일군과 분업군에 서로 다른 선택지 뜻을 주지 않는다.
- 실패 워커 결과를 임의의 빈 구조로 채워 생성하지 않는다. 완료된 부분과 실패 기록을 모두 보존하고 예정 입력 분모에서 빼지 않는다.
- 분업 담당들이 각각 KG를 조회한 뒤 합치는 구조로 바꾸지 않는다. 합쳐진 분석으로 기존 조회기를 한 번 사용한다.
- 생성 담당에게 분업 모델들의 긴 설명이나 대화록을 추가하지 않는다. 동일 형식의 병합 분석·선택 지식만 전달한다.

## 다음 의사결정

이번 산출물은 구현 승인이 아니라 설계 제안이다. 다음에는 이 경계를 비교 후보로 구현할지와 최초 실험 범위/상한을 확정해야 한다. 세부 인프라·모델 변경은 포함하지 않는다. 사용자가 현재 제안을 채택하기 전 코드나 Qwen 실행은 하지 않는다.
