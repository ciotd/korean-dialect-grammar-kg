## 우선 후보: 절 담당1 + 의미 담당2, 전체5호출
Kiwi → Qwen 절 구획(기존 유지) → [의미·구성/관계 담당 A, 시간·높임 보존 담당 B] → 코드 병합 → 기존 KG → 기존 작성자 → 기존 진단 검토자.
두 의미 담당은 동일 원문·동일 단위/절 ID·Kiwi 관찰·관련 질문 정의를 받는다. 원문 전체는 둘 모두 볼 수 있게 하고, 불필요한 다른 담당의 응답 항목·KG 장문·방언 정답은 넣지 않는다. 같은 Qwen의 서로 다른 호출이며 독립 지식원을 뜻하지 않는다.

| 담당 | 맡는 것 | 맡지 않는 것 |
|---|---|---|
| 절 구획 | 주절/종속절 범위·포함 관계, 누락 의심 | 시제·높임·방언 생성. 첫 비교에서 기존 절 구획 고정 |
| A 구성/의미·관계 | 금지/요청/질문/평서, 보조 구성의 수혜/시도/진행 등, 부정 범위·사동피동·조사/명사/연결어미 의미 및 실제 단위 관계 | 시제와 높임 값 덮어쓰기, 형태/ID 자동 생성 |
| B 시간·높임 | 형태상의 과거와 문맥 시간 구별, 주체/상대 높임 구별, 겸양·객체높임 보존 근거 확인 | 본/보조 관계와 화행을 따로 다시 작성, 방언 표현 선택 |
| 코드 병합 | ID/누락/중복/자료형·작성 권한 검사, 기존 형식으로 합침 | 모르는 값을 정답으로 채움, 다수결, 의미 추론 |

왜 시제/높임을 한 담당에 묶나: 서로 같은 문법이라서가 아니라, 첫 실험에서 비용 증가를1회로 제한하면서 형태 근거와 보존 상태에 집중시키기 위해서다. 부하가 남으면 시제/높임도 별도 담당으로 나눈 대안(전체6회)을 다음에 비교한다. 무조건3명의 의미 담당이 좋다고 가정하지 않는다. A의 역할이 여전히 넓은 점을 검토해야 한다.

## 기존 필드의 작성자와 범위
실제 meaning schema의11개 의미 필드를 확인했다.
- A: clause_role, speech_act, question_kind, polarity, semantic_function, voice, auxiliary_kind, predicate_class. 실제14종 relations와 construction_links도 A가 맡는다. 절 ID는 재작성하지 않고, 바뀌어야 한다면 구조 이의로 기록한다.
- B: tense, addressee_level, subject_honorific.
- Kiwi 관찰(source_form, root_tag, past_form, prefinal_sequence 등)은 둘 다 읽기 전용. 수정 제안은 별도, 자동 덮어쓰기 없음.
- 겸양·객체높임, 문법상/양태의 세부사항은 지금 별도 KG 필드가 모두 있는 것이 아니다. 추가 보존 근거는 제안 기록으로 분리하고, 첫 통제 비교에서 생성 입력에 새 필드를 몰래 더하지 않는다. 현재 표현 가능한 의미는 기존 tense/auxiliary_kind/speech_act/semantic_function 등에 매핑하되 뜻을 억지로 합치지 않는다.
- 같은 unit_id라도 필요한 항목만 질문. 기능/시제/높임은 해당 절/단위를 지정한다. 명사마다 시제·주체높임 질문을 강제로 묻지 않는다.
- 누락(응답 안함), unknown(판단 못함), not_applicable(해당 없음)을 검사 기록에서 구별하는 제안. 기존 조회 형식의 null로 합칠 때 원래 사유는 외부 진단에 남긴다. null을 자동 true로 하지 않는다.

## 합치기와 오류 처리
모든 단위/필드의 담당은 실행 전 고정한다. 다른 담당의 필드가 오면 임의 우선순위로 덮지 않고 오류로 기록한다. 원문 근거·대상 절/단위 ID를 값과 연결한다. 근거 구절이 실제 존재한다는 코드 검사는 뜻이 맞다는 인증이 아니다.
첫 통제 비교는 자동 재질문0회·재작성0회, 명확하지 않은 값은 그대로 유지한다. 구조 누락·분기 미확정·관계 결측·모델 형식 오류를 따로 보고하고 전체 실패를 숨기지 않는다. 운영에서 충돌 재질문을 넣는다면 담당자 한 명에 최대1회로 별도 비교하며 호출 수에 포함한다. 상위 종합 모델이 전부 다시 분석하도록 하거나 끝없는 토론은 하지 않는다.
서로 다른 의미 항목의 연결 오류는 작성 권한만으로 예방되지 않는다. 예: 금지+진행의 의미 충돌, 인용 내부 시제와 주절의 시제. 이런 것은 명세된 좁은 검사나 검토 항목으로 남기고 일반 코드 정답 처리하지 않는다. 전체 원문·절 범위를 공유해 단어별 고립 분석을 피한다.

## 비교 대안과 비용
1. 기존 의미 담당1명: 전체4호출.
2. 질문과 응답을 같은 두 묶음으로 정리하되 의미 담당은1명 유지: 전체4회. 질문 정리 효과와 분업 효과를 분리할 대조군.
3. 권장 후보 의미 담당2명: 전체5회. 같은 단위에서 같은 필드 정의/조건/생성 지시로 비교.
4. 의미를 화행·관계 / 시제·상·양태 / 높임의3명으로 세분화: 전체6회. 첫 선택으로 고정하지 않고2명 결과에서 남은 병목이 뚜렷하면 비교.
단어마다/절마다 동적 워커를 늘리지 않는다. 첫 실험은 고정 워커 수. 긴 입력의 문맥 누락 여부는 별도 계층으로 평가한다. 병렬 호출은1GPU 서버에서 실제로 더 빠르다는 보장이 없고, 원문/스키마 중복으로 토큰은 늘 수 있다. 실측 총토큰·호출·wall time과 성공 출력만이 아닌 실패 포함 집계를 보존한다. 초기 비교는 분업의 실제 추가비용을 보고하며 토큰까지 동일한 공정비교라고 부르지 않는다. 논문에서 분업 자체 우월성을 주장하려면 비분업 재검토 등 추가 계산량 대조가 필요하다.

## 검증 제안(실행 승인 전)
과거12개는 회귀·원인 확인 자료이며 독립 최종평가가 아니다. 새 개발 문장은 금지/요청/평서와 시제·주체/상대높임·겸양·부정범위·보조용언·인용/관형절을 교차해 구성하고 출력 관찰 전 판정표를 동결한다. 모호한 문장은 unknown 허용 범위도 미리 적는다. 독립50새셋을 만들겠다는 결정이 아니다. 기존50은 다음 회귀.
같은 Kiwi/절/단위→동일 정의의 단일 의미 vs 분업 의미→동일 KG/작성/진단. 정확도 이름을 붙이려면 표준어 분석 정답을 사람이 검토해야 한다. 모델 합의·원문 변경률·관계6/6을 품질로 대신하지 않는다.
종료: 누락·오분류가 줄고 새 명백한 뜻/높임 손실이 없으며 비용이 보고된 때만 다음 통합 비교. 일회성 개선은 개발 관찰로 제한. 의미가 개선돼도 최종 높임이 계속 사라지면 생성 문제로 분리하고 워커 추가를 멈춘다. KG의 불필요한 조건 문제는 별도 대조군/수정으로 처리하고 분업과 동시에 바꾸지 않는다.
