# 지금 연구는 어디까지 왔나

2026-11-09 · 기존 기록을 모은 현재 상태표. **① 현재 상태 정리**이며 새 실험·KG 수정·전체 문헌 재검토 결과가 아니다.

## 한눈에 보는 결론

**문장을 분석하고, KG의 조건을 확인하고, Qwen이 문장 전체를 만드는 연결은 구현되어 실제 50문장에 실행됐다. 하지만 전체 문법 지식의 정제와 규칙별 검증은 끝나지 않았다.** 분석 때문에 잘못된 규칙을 찾는 문제와, 맞는 정보를 받아도 생성에서 과거·높임을 잃는 문제가 함께 남아 있다.

지금까지 한 일이 없다는 뜻은 아니다. 전체 연결·기록·저장 분리는 갖췄고 일부 용법은 실제 변환까지 확인했다. 다만 ‘연결되어 실행됨’, ‘규칙을 올바르게 적용함’, ‘자연스러운 문장임’은 서로 다른 완료 단계다.

| 바로 알아야 할 것 | 현재 상태 |
|---|---|
| 최근 실험 | 11월 9일, 기존 50문장 전부 시도. 48건 처리 완료, 2건 중단 |
| 형태 분석 | Kiwi가 담당. Qwen만으로 형태를 분석하는 경로는 비교용으로 보존 |
| Qwen 분석 | 절 범위 1회 + 의미·관계 통합 판단 1회. 의미·관계 자체의 추가 분업은 아직 설계 |
| Qwen 생성 | 후보 선택과 문장 전체 작성을 한 번에 수행. 이후 별도 검토. 이번 50건은 자동 재작성 0회 |
| KG | 파일의 조건 그래프를 조회. Neo4j는 시각화 사본이며 이번 실행의 조회 서버가 아님 |
| 전체 문법 준비 | 12모듈 보존, 56조건 조회 용법·57분기, 미정제 문헌 지식721개. 전체 용법 완성 아님 |
| 아직 입증하지 못한 것 | 전체 문법의 정확성, 현대 방언 자연스러움, 분업의 개선 효과, 일반 검색보다 KG가 유리하다는 효과 |

## 1. 현재 실제로 도는 흐름

**표준어 원문 → Kiwi 형태 관찰 → Qwen 절 범위 → Qwen 의미·관계 → 코드의 KG 조건 조회·전달 → Qwen 후보 선택·전체 작성 → Qwen 진단 검토 → 원시 출력·실패 기록**

정상 입력은 Qwen을 4번 호출한다. 50건 전체에서는 중간 실패로 196회였다. 네 호출은 같은 Qwen 모델에 서로 다른 일을 맡기는 것이며, 네 종류 모델이나 네 대의 서버를 뜻하지 않는다.

| 담당 | 실제 입력과 하는 일 | 어디까지 믿을 수 있나 |
|---|---|---|
| Kiwi | 어간·어미·품사를 관찰해 입력 위치와 연결 | 의미·상황을 확정하지 않음. 형태 분석 자체도 모든 문장에서 완벽하다는 뜻 아님 |
| Qwen 절 담당 | 원문 어절 ID로 절의 범위와 포함 관계 표시 | LONG001처럼 범위 모순 가능 |
| Qwen 의미·관계 담당 | 문장 기능·시간·높임·부정과 단위 사이 관계 판단 | 현재 한 담당. 반말 오분류, 문장 간 기능 복사, 관계 누락 남음 |
| 코드 + KG | KG의 구성→용법→조건→허용값 연결을 읽어 조건 묶음을 준비. 입력 단위 종류에 맞는 규칙들의 값을 대조. 맞음/불일치/미확정 기록 | Qwen이 그래프를 임의로 탐색하는 구조가 아님. 코드가 기록한 그래프 경로와 조건 판정을 확인할 수 있음 |
| 전달 처리 | 조건을 통과한 지식에서 분석 이의와 관련된 후보를 제외. 원문·분석·보존정보·남은 후보를 작성자에게 전달 | 설명성 경고 때문에 후보가 빠진 사례 있음 |
| Qwen 작성 담당 | 후보를 적용할지 정하고 문장 전체 생성. 지식이 없는 곳에서는 자체 방언 지식 사용 가능 | 적용 신고와 실제 적용은 다름. 과거·높임 보존 실패와 잘못된 자체 지식 변경이 남음 |
| Qwen 검토 담당 | 원문과 출력을 대조해 오류 의견 반환. 코드가 인용 위치 등을 확인 | 맞는 표현을 틀렸다고 하거나 실제 오류를 놓침. 이번 실험에서는 자동 재작성하지 않음 |

**검색과 전달의 중요한 경계:** 미정제721항목을 찾는 문자열 기반 참고 검색 기능과 기록은 있다. 그러나 최근 분업 실행 경로의 생성 요청에 들어가는 `knowledge`는 **56개 조건 조회 용법 중 통과·선별된 후보**다. 참고 검색 결과721개가 그대로 생성에 사용되는 것은 아니다. 분류 모듈 전체를 매번 Qwen에 보내는 방식도 아니다. 이것은 앞으로 전체 지식 활용 범위를 검사할 때 반드시 구분할 대상이다.

## 3. 문법 지식은 어디까지 준비됐나

12모듈은 **분류 틀**, 26묶음은 **정제 작업 목록**, 56용법은 **조건을 확인할 수 있도록 작성한 후보 규칙**이다. 숫자가 크다는 이유로 자연스러움이나 전체 문법 완성을 뜻하지 않는다. ‘활성화56개를 모두 통과해야 번역된다’는 구조도 아니다.

| 문법 분야 | 현재 확보한 범위 | 완료로 말할 수 없는 것·다음 검사 |
|---|---|---|
| 동사 | 의문·일부 평서·요청 후보와 어간/어미 관찰 | 활용 부류와 어휘별 결합 전체. 과거 보존과 본/보조 위치 확인 |
| 형용사·계사 | 형용사 질문, 현재·과거 계사 후보 | 모든 계사·높임·시제 조합. ‘아니다’의 기능·품사 오분류 검사 |

**26묶음의 상태:** 기존 작업대장에는 전체 묶음 완료로 표시된 항목이 없다. ‘아무것도 안 했다’는 뜻이 아니라 부분 지식과 구현이 있어도 그 묶음 전체를 끝냈다고 인증하지 않았다는 뜻이다. HTML의 상세표에서26개 모두를 볼 수 있다. 대장의 `new_rule_ids`는 11월6일 **추가44용법만** 세므로, 이 수치가0인 계사 묶음에도 이전12용법의 계사 지식이 존재한다. 이를 지원0으로 오해하지 않도록 표시했다.

**다음 목록 검사에 넘길 연결 확인 대상:** 56규칙 중6개는 직접 `IN_MODULE` 연결이 없다. 간접 연결까지 없거나 실행 불가능하다고 단정하지 않았다. 모듈 탐색에서 어떻게 보이는지 다음 단계에서 확인한다. 현재1,491개 노드를 재집계한 것이 전체 노드 의미 검증을 마쳤다는 뜻은 아니다.

**출처 분리는 일부만 끝났다.** 출처·검토 전용 속성과 노드의 별도 저장은 완료됐지만, 규칙 설명에 섞인 메모까지 모두 정리하지는 않았다. 약속 규칙의 ‘리드 판단 필요’·문헌 쪽수와 보조용언 규칙의 쪽수가 실제 작성 요청에 남아 있음을 원시 기록에서 확인했다. 다음 검사에서 설명문을 일괄 삭제하지 않고, 실제 문법 조건은 남기고 관리 메모만 분리할 대상을 찾는다.

**최근 50문장에서 관찰한 단계별 범위:** 56개 중 조건에 맞는 후보로 나온 규칙은 26개, 실제 전달된 고유 규칙도 26개, Qwen이 사용했다고 신고한 고유 규칙은 22개다. 30개는 이번 입력에서 조건 통과가 관찰되지 않았다. 조회 과정에서 검토조차 안 됐다는 뜻이나 30개 모두 고장이라는 뜻은 아니다. 해당 문법이 입력에 없었는지, 분석 오류로 놓쳤는지는 다음 단계에서 구분한다. 보존 전용 규칙도 포함되므로 22개를 방언 변환 성공 수로 세지 않는다. 최신 출력 전체에 대한 독립적인 사람 평가는 미실시다. 과거 사용자 의견과 승인 참조는 보존하되 그것을 이번 출력의 전수 평가로 대신하지 않는다.

우선순위는 전체 항목 목록을 확정한 뒤, ①6개 규칙의 모듈 대응 ②실행 설명에 섞인 출처·검토 메모 ③30개 미관찰 규칙의 이유 ④분석 결과에 직접 담을 칸이 없는 양태·객체높임·겸양을 구분하는 것이다. 이 항목은 다음 검사 대상이며 이번에 수정한 결과가 아니다.

그다음 **조건별 예문 → 규칙 조합 → 생성 방식 비교 → 전체 연결 재검증**으로 진행한다. KG 자체 검사는 근거를 검토한 분석값을 사용하고, 실제 파이프라인 검사는 모델의 분석값을 사용해 구분한다. 생성 비교는 필요한 정보가 전달됐다는 근거가 있는 사례에서 먼저 준비할 수 있으며 전체 KG가 완벽해질 때까지 기다리지 않는다.

②의 종료는 모든 번역이 자연스러워지는 시점이 아니다. 전체 대상의 상태·검사 결과·미확인·다음 보완이 추적되면 끝낸다. 자료나 조건이 부족하면 임의 보충하지 않고 검토 대상으로 남긴다. 개선이 확인되지 않으면 같은 프롬프트를 계속 바꾸지 않는다.

**논문 과제는 여전히 남아 있다.** 같은 지식·모델·평가 조건에서 일반 검색/조건표/그래프 조회를 비교하고, 새 평가 자료와 사람의 블라인드 평가로 자연스러움·의미 보존·비용을 확인해야 한다. 지금50건은 이미 개선에 사용한 회귀 자료다. 이번 정리는 KG 효과를 증명하는 실험이 아니다.
