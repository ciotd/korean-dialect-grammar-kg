# 무엇을 확인했나

**현재 KG는 연결이 끊기거나 ID가 중복된 상태는 아닙니다. 하지만 저장된 설명·조건·분석 질문·생성 전달 내용이 완전히 맞춰져 있지는 않습니다.** 따라서 ‘구조 검사 통과 = 문법 지식 완성’이라고 결론 내릴 수 없습니다.

이번에는 전체 항목을 빠짐없이 목록으로 만들고, 실제 조회 코드가 무엇을 읽는지 확인했습니다. 새 예문을 Qwen에 넣어 번역한 검사는 아직 하지 않았습니다. 이 둘을 구분하는 것이 이번 보고서의 핵심입니다.

## 3. 결함으로 단정하면 안 되는 것

**직접 모듈 연결이 없는6규칙은 상위 문법 구성을 거쳐 연결됩니다.** 예를 들어 ‘과거 계사 해예체’ 규칙은 상위 구성을 통해 형용사·계사, 종결, 높임, 시제, 표기 모듈로 이어집니다. 조회기는 직접 모듈 관계를 적용 조건으로 삼지 않으므로 이6개가 조회 불가능한 것은 아닙니다. 관계를 무조건 추가하기보다 조회 화면과 목록이 간접 연결도 보여주게 해야 합니다.

**관계5,037개 전부가 조건 분기는 아닙니다.** 조건·실현형 읽기에 직접 쓰는 관계는6종·649개이고, 나머지는 분류·공통 개념·정제 대응·관찰 메모 등의 역할입니다. 나머지4,388개를 전부 쓸모없는 정보로 삭제해서는 안 됩니다. 다만 이 관계들이 생성 품질에 어떤 도움을 주는지는 아직 실험으로 입증하지 못했습니다.

또한 기존12규칙의13분기에는 서술어 단위라는 조건이 코드 기본값으로 보충됩니다. 공통 적용 범위도 별도 노드의 속성에서 읽습니다. 따라서 ‘모든 조건이 분기 화살표에만 있고 처리 기록에 모두 나온다’는 설명은 부정확합니다. 다음 보완에서 각 판단값의 출처를 직접 조건·상위 범위·코드 기본값으로 구별할 필요가 있습니다.

## 5. 다음은 무엇을 어떻게 검사하나

사용자가 말씀한 **‘예문을 만들어 전체 KG를 최대한 통과시키는 작업’은 여기부터**입니다. 관리·분류 노드를 억지로 방문하는 대신, 실제56규칙·57조건 분기를 검사 대상으로 삼습니다. 이후 미정제721항목은 별도 정제 대상으로 계속 추적합니다.
