# 두 리뷰어 검토와 리드 반영

기존 Orca Claude·Codex에게 review_packet.md를 전달하고 실제 독립 검토서를 받았다. 신규 하위 모델을 별도로 띄운 검토가 아니다. 두 검토자는 KG/운영 코드를 수정하지 않았고 PDF 본문을 전수 재검증하지 않았다. 원문은 그대로 보존했다.

| 담당 | 실제 수행 | 확인하지 않은 것 |
|---|---|---|
| Codex | 전체 ID·참조·조건 구조, 원본 복원, 실제 코드의 속성/관계 소비, 리드 집계 독립 대조 | 방언 자연스러움, PDF 의미, 새 모델 실행 |
| Claude | 56규칙 문구와57분기·실현형 대조, 실제 전달 사례, 미관찰30규칙 분류 | 규칙 아닌721항목의 전수 의미, PDF 본문, 최신 자연어 시험 |
| 리드 | 전수 목록 생성, 코드와 검토 근거 재대조, 자동 검출 범위 수정, 수정안·후속 검사 통합 | 아직 KG 변경·규칙별 새 예문 실험 없음 |

## 반영과 정정

| 의견 | 리드 판단·반영 |
|---|---|
| 두 리뷰어: 구조상 끊김·중복 없음 | 전수 재집계와 일치. 의미 정확성의 통과로 확대하지 않음 |
| Codex:6직접 미연결은 구성 경유 연결 있음 | 실행 결함 목록에서 제외하고 목록 표시 개선으로 분류. 무조건 직접 관계를 추가하지 않음 |
| Codex: 실제 전달 forms에도 옛 지시가 있음 | 감사 스크립트를 모든 action 필드 검사로 보완. 동일 정규식 전달 후보13→15규칙. 이 변화는 시스템 개선이 아니라 검사 범위 정정 |
| Claude:‘조건 보완’39개, 전달14개 | 동일 문자열 집계 재현. 별도 정규식37/15와 분모·기준을 구분 |
| 두 리뷰어:limits/limitations 불일치 | 원문 필드와 실제 전달 필드를 구별. limits가 실제 있는 규칙은9개임을 확인. 기존12개 모두 같은 속성이 있다는 표현은 사용하지 않음 |
| Codex:후조건·target 등이 전달되지 않음 | 필드별 누락 목록 기록. 모든 누락이 의미 손실이나 과거 오류 원인이라고 단정하지 않음 |
| Claude:분석 질문33개 값 혼합 | 실제 계약의33개 비-null 값과 null1개 확인. 관찰/질문에 표현 가능하다는 검사만으로 적절한 질문이라는 결론을 내리지 않음 |
| Claude:조건 문구 불일치·block의 대상 관계 부재 | 실제 규칙과 코드에서 확인. 잘못된 동시 적용이 이미 발생했다는 주장과 향후 위험을 분리 |
| Claude:30규칙 원인 분류18/1/3/7/1 | 규칙 목록과 기존 기록을 대조하여 검토 분류로 수록. 정규식·모델 문법 판단 한계와 미검증 상태 명시 |
| Claude:실행 문구의 쪽수 일부가 직접 SUPPORTED_BY에 없음 | 직접 근거 연결 누락 후보로 기록. 기존 audit의 원문/변경 전 전체 정보가 보존되므로 ‘출처가 이미 소실됐다’고 결론 내리지 않음. 메모 이관 시 미연결 인용 상태도 함께 보존 |
| Codex:같은 조건 명세 노드17묶음 | 동일 ID/관계 중복과 다름. 맥락·추적 차이를 확인하지 않고 합치지 않음 |
| 두 리뷰어:다음 규칙별 자연어 검사 필요 | 57분기와 기존57예문 후보를 연결. 예문이 각 분기에 적합한지는 미검증. 다음 단계의 적용/비적용/미확정 검사로 명시 |

## 검토 원문

- [Claude 원문](private/claude_structure_review.md): 56규칙 내용·조건 불일치,30규칙 분류,개별 예문 검사 후보.
- [Codex 원문](private/codex_structure_review.md): 전수 구조,속성 전달,헤더 정의,경로 추적,56규칙별 확인표.

검토자가 제안한 수정은 이번에 실행하지 않았다. 동의한 의견도 문헌 사실 인증이 아니라 코드/기록과 대조한 검사 판단이다. 다음 단계에서 운영 지식을 바꾸는 경우 별도 버전으로 저장하고, 기존 출력과 비교할 조건을 먼저 고정한다.
