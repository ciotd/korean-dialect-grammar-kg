# 변경 판단과 검토 반영

## 개발 비교 전
- 기존 복구점은 `0d1914899d788ffd529f35fa43d6fdec329cf444`. 구 경로는 `run_qwen_multi.py --analysis-backend qwen`으로 유지한다. CLI 기본은 Kiwi이며 새로운 실행기를 호출한다.
- 기준선은 Kiwi 공통 연결 + 기존 meaning/writer/reviewer. 보완은 미해석 선어말 null, 누락 장부, 관계 후보, 의미 정의, 겸양/복원 형태 지시, 평서문 보존 힌트의 질문 분류 제거. KG는 같은 파일이다. 여러 요소 묶음 효과이며 단독 원인을 증명하지 않는다.
- Codex 제안 반영: 절의 비포함 교차/문장 간 범위 거절, 두 앵커 ID의 문자 범위 대응 저장, root/연결어미 인덱스별 대응 장부, 실제 공통 입력 해시 검사, 모든 호출 상한/기록, 공통 절 비용 별도 집계.
- Claude 제안 반영: 금지와 요청 정의, 본·보조 후보를 실제 ID로 제시, 저/제/저희 겸양 힌트, 원문 글자와 복원 형태 구분, 평서문 question_kind 보존 힌트 제외.
- Claude의 본·보조 관계 자동 확정 권고는 이번에는 채택하지 않는다. 형태는 관계 후보이고 기능 연결은 Qwen이 확인한다. 이것이 이번 실험에서 유지하는 의미 판단 역할이다.
- Claude의 ‘-지 말고는 금지가 아니다’라는 단정은 채택하지 않는다. 금지 뜻과 연결어미/종결어미의 위치는 다른 기준이다. 금지 종결 규칙의 적용 여부와 의미를 혼동하지 않는다.
- 소유격 규칙 자체의 조건 변경은 이번 최초 비교에서 하지 않는다. 소유격 후보가 복원형에도 나오는 사실을 기록하고 작성자가 설명 범위에 맞게 거절하는지 확인한다. 이 전달이 계속 오작동하면 다음 한 묶음 수정에서 명시적 KG 적용 조건으로 좁힌다. 임의의 모든 복원형 차단은 하지 않는다.

##50건 진입 판정 (출력 관찰 전 고정)
1.12입력의 두 경로24개 모두 처리되고 원시 작성 결과가 최종 출력과 일치한다. 공통 입력·모델·KG·기록 해시가 맞는다.
2. development.jsonl의 construction_act가 있는6문장에서 construction 기능과 본/보조 관계2개가 모두 충족된 입력 수를 비교한다. 보완에서 실패 입력 수가 감소해야 하며 미확정도 성공으로 세지 않는다. 진단 외 입력의 연결을 맞았다고 확대하지 않는다.
3.12쌍 모두 원문 보존 항목을 리드·두 검토자가 대조한다. 보완 경로에만 새로 나타난 명백한 시제·부정·높임·내용 손실이 없고 미판정이 없어야 한다. 자연스러움의 사람 평가와 다르다.
4. 문제 해결 근거가 부족하면50건을 실행하지 않는다. 명확한 공통 원인이 있으면 추가 수정 한 묶음, 최대84호출로 같은 개발 비교를 새 Run ID에서 재검증한다. 성공 기준을 결과에 맞춰 바꾸지 않는다.
5.50건 진행 시 별도 최대200호출, 진단 검토만 수행한다. 재작성0회, 실패 원본 보존. 그 결과로 독립 평가 정확도나 KG 우월성을 주장하지 않는다.
