# 추가 보완 후보 — 아직 실행 전

첫 비교 진행 중 확인한 요청문 오류: '열어 주세요'는 본·보조 ID와 요청 기능이 맞아도 auxiliary_kind=none 때문에 수혜 보조용언 규칙에 도달하지 못한다. '기다려 주세요'는 보완 후에도 관계를 빈 배열로 반환했다. 원시 기록과 Claude의 auxiliary_diagnosis에 근거한다.

프롬프트 문장을 반복 추가하는 대신 **단위별로 필요한 질문을 구분**하는 한 묶음을 검토한다.

1. 해당 종류의 KG 조건에서 쓰지 않는 auxiliary_kind 질문을 용언/연결어미에서 제외한다. 보조 구성에는 유지한다. 부재(none)와 미확정(null)을 강제로 없애지 않는다. Kiwi가 잘못 만든 보조 구성일 가능성도 남긴다.
2. 보조 구성마다 main_predicate/auxiliary_predicate를 명시적으로 답하는 표를 의미 응답에 추가한다. 후보 중 ID 또는 null을 선택한다. 코드가 정답 ID를 대신 채우지 않는다. 빈 관계 배열에 조용히 누락되는 것과 명시적 미확정을 구별한다.
3. auxiliary_kind 영어 값의 한국어 뜻을 짧게 제공한다. 수혜(화자 포함 다른 사람을 위해 해 줌), 시도, 진행, 결과, 희망, 필요, 그밖, 부재, 미확정을 구별한다. 문장별 방언 답안은 제공하지 않는다.
4. 기존 그래프와 생성 프롬프트는 그대로 두고 의미 질문 형식만 다음 보완 버전에 반영한다. 원시 응답과 실제 결속에 쓴 값 모두 보존한다.

추가 비교는 처음12문장과 최초 공통 절/형태를 고정해 기존 정책·새 보완 정책을 다시 비교한다. 처음의 공통 구조를 복사하되 원본 입력과 해시를 확인한다. 새 호출 최대72회(각 경로3회), 추가 한 묶음 한도84 안에 든다.50건 진입 기준을 느슨하게 변경하지 않는다. 새 버전에서도 핵심 연결과 보존 실패가 남으면 더 많은 지시를 추가하는 루프를 멈추고 미해결 원인·다음 대안을 보고한다.
