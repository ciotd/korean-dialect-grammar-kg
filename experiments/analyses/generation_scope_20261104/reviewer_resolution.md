# 설계 검토 반영

- Claude의 open 문구 모호성: 인과적으로 실패를 유발했다고 단정하지 않는다. 다만 허용 범위를 명확히 한 v2를 별도 비교하며 v1 전부 보존한다. 기존 strict A는 변경하지 않는다.
- Codex의 신규 공유 분석 실패 처리: 첫 실제 분석 오류에서 중단·원시기록 보존·생성 미진입으로 명시했다. unknown과 구분한다.
- Codex의 출력 진단 예외: 호출 전 위치 검증, 호출 후 예외를 원시 출력과 별도 저장하고 중단한다.
- 의존 코드: 27개 과거/현재 해시 확인. 진행표 unit_key 추가만 허용. 실제 분석·조회 의미 처리 변경 없음.
- 하위집단·동일요청 결과는 report.py에서 구현했다. 리뷰 요청 범위에 report.py가 없어 검토자는 이를 읽지 못했으므로 ‘미구현’ 의견을 그 범위로 한정한다. 실제 요청 차이와 원시 응답은 결과검토 때 확인한다.
- 신규문장 전체 중복은 별도 preflight에서103개 과거 입력 파일과 대조했고0이다. 문법·어휘 유형의 독립성은 주장하지 않는다.
- 참고 형식·높임 검사 등 추가 지표는 자동 정답으로 만들지 않는다. C의 위치 검사 불가를 실패로 세지 않고 사람이 볼 예문에서 누락·시간·높임·화계 변화를 점검한다.
- 다/ㄴ다의 직접 근거를 D02 PDF107–115에서 추가 확인했다. 사실·상태 서술의 공유형을 연결할 수 있지만 해체 입력을 항상 해라체로 전환해야 한다는 보장은 아니다. 이번 실행KG에는 추가하지 않는다.

## 결과 검토 반영

- Claude 결과 검토 완료. DEV026의 이유→의도 변화, GS08의 과거 표지 손실, GS05의 C 조건 과거 손실을 원시 출력과 대조해 수용했다. 자유 생성 조건을 운영 기본값으로 바로 바꾸지 않는다.
- Claude의 지역별 자연스러움 판정과 20/23 높임 변화 집계는 AI 검토 의견이다. 독립 사람 평가나 검증된 정확도로 보고하지 않는다.
- 동일 요청의 출력 변동이 있다고 해서 v1/v2 차이를 전부 잡음으로 설명할 수는 없다. 두 반복만으로 문구 효과와 변동 크기의 통계적 결론을 내리지 않는다. 최종 v2에서도 주요 오류가 남았다는 관찰만 사용한다.
- 정차→멈추는 문맥상 바꿔 말하기일 수 있다. ‘-노’의 존재만으로 발화 기능 변경을 확정하거나, 특정 높임 형태소의 삭제만으로 모든 사례의 높임 의미 손실을 자동 확정하지 않는다. 명백한 사례와 화자 확인이 필요한 사례를 구별한다.
- Codex 설계·결과 검토 모두 완료. 결과 대기 중 Orca 연결 실패가 있었으나, 실제 원인은 리드 실행 환경의 연결 파일 접근 권한이었다. 권한 적용 후 기존 세션과 완료된 보고서를 확인했다. 사용자에게 앱 재실행이 필요하다고 설명한 것은 정정했다.
- Codex는 생성 672건의 요청·응답·집계를 대조했다. 운영 채택 보류, 미전달 상태별 분리, 모델 자기보고 불일치 10응답 표시, 보고서 코드·입력 해시 별도 보존 권고를 수용했다. 실제 실행 원본은 변경하지 않았다.
- 두 검토자는 모두 50회귀+12개발 전체를 검토했다. AI 검토의 일치는 사람 자연스러움 평가를 대신하지 않는다. 검토자의 인과 추정은 원시 관찰과 분리했다.
