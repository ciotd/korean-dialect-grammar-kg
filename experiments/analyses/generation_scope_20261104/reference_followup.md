| 부분 | 현재 확인 | 보완할 위치 |

| 저는→지는 | 참조의 어휘 변화. 현재 action은 설명했어요만 포함하며 위치 밖 수정 금지 | 어휘 후보·적용 범위의 명시적 연결. 공손함 보존과 사용 범위를 검토하며 다른 어휘에 일반화하지 않음 |

## 이전 실험을 반복하지 않기 위한 확인

`20261104T015832989809Z_fixed_source_prefix_surface`의 ADVCE006A는 이미 보존 문자열 ‘설명했어’, 교체 부분 ‘요’, 결과 부분 ‘예’를 전달했다. 실제 출력은 ‘설명했예’였다. 이 경우 과거형은 남지만 ‘어’가 빠졌다. 따라서 ‘보존할 글자를 써 주자’는 새 방법이 아니며, 단순 추가 강조가 해결책이라고 주장하지 않는다.

현재 r7의 형태소 조합 설명, 시제 보존 명령, 해체+예 설명, 실행 이력(Kiwi), 조건 판정 메타데이터가 한 요청에 섞인 것은 확인된다. 이 복잡성이 실패를 유발했다는 것은 아직 가설이다. 최소 지시·어절만 생성·명시적 접미부 교체·온도 비교도 이미 수행했으므로 같은 실험을 이름만 바꾸어 반복하지 않는다.

## 승인 참조의 역할을 보완

참조를 보고서에 나란히 보여주는 데 그치지 않고 다음 보완의 목표로 사용한다.

1. 참조의 변화 중 어휘, 문법 실현, 선택 가능한 말투, 생략을 나눈다. 글자 차이를 모두 오류로 계산하지 않는다.
2. 필요한 지식이 원문 문헌·원본 KG·실행 구성·조회 결과·실제 요청 중 어디까지 있는지 확인한다. 요청에 없다는 것만으로 KG 자체에 없다고 결론내리지 않는다.
3. 근거가 있는 지식은 기존 구조에 연결하고, 사용자 승인 사례에서 도출한 일반화는 그 출처와 검증 상태를 표시한다. 50문장 ID를 입력 조건으로 사용하는 규칙은 만들지 않는다.
4. 참조에 없는 새 문장에서도 작동하는지 확인한다. 참조와 가까워져도 독립 최종 평가 점수로 주장하지 않는다.

이 방식의 보완은 가능하다. 어려운 부분은 참조를 흉내 내는 일이 아니라, 여러 입력에서 의미와 높임을 지키며 같은 용법을 선택·실현하도록 만드는 일이다.
