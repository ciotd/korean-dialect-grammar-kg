# 승인 참조 기반 수정안 — 실행 전 계획

2026-11-04. 사용자 ‘진행해’에 따라 전체50 대조와 수정안 준비를 진행했다. 현재 운영 KG·생성기·기본값은 수정하지 않았으며 새 Qwen 호출은 없다.

## 결론의 범위

- 참조50의 문장별 목표와 현재 r7 요청·조회62위치를 연결한다. 옛 카드의 존재는 현재 실행 가능성이나 일반 문장 적용의 증명이 아니다.
- A를 비교 기준으로 유지한다. 정답 참조를 Qwen 입력에 넣거나 문장 ID별 변환을 만들지 않는다.
- 새로운 원인이라고 가장하지 않는다. 과거형의 실제 전달과 원시 출력 손실, 최소 지시·접두부 보존 실험의 실패는 이미 확인된 사실이다. 이번 추가는 **참조의 변화별 보완 경로**와 **검사 결과를 실제 수정 지시로 사용하는 구조**다.

## 수정안 1 — 오류 검사 결과를 Qwen에게 되돌린다

현재: Qwen 생성 → 보존 검사 → 경고 기록만 남김.

후보: Qwen 생성 → 확실히 검사할 수 있는 조건의 위반 발견 → 잘못된 출력 부분과 위반한 조건을 Qwen에 전달 → Qwen이 전체 문장을 다시 생성.

`repair_feedback.py`는 모델 호출 없이 이 전달 자료를 만든다. 기존 그래프가 이미 선언한 요→예 표면 보존 조건과 단일 action에만 적용한다. 원문에서 가져온 보존 부분·선택한 끝부분·실제 잘못 만든 부분을 분리한다. 완성된 승인 답안은 읽지 않는다. 원시 출력은 그대로 보존하고 코드가 최종 문장을 고치지 않는다.

Codex 검토에서 발견한 입력/출력 결속 누락을 수정했다. packet·graph·첫 출력의 해시를 묶고 요청 생성 시 재검사한다. 위반 설명이 조작되거나 다른 출력에 붙으면 거부한다. 복사본을 사용해 요청 작성 후 원본 객체 변경이 두 조건을 바꾸지 않도록 했다.

기존 A100출력(50×2)에서16개가 이 한정된 검사의 대상이고,6개(설명했어요2입력·같아요1입력×2반복)가 위반이다. 나머지84개는 이 검사 범위 밖이며 통과나 오류 없음이 아니다. 의문문의 뒀어→두노 같은 사례를 이 도구가 해결한다고 주장하지 않는다.

### 다음 모델 비교안 — 아직 실행하지 않음

| 비교 | 두 번째 호출에 주는 내용 |
|---|---|
| 중립 재검토 | 같은 원문·KG·첫 출력 + 다시 확인하라는 지시 |
| 오류 위치 피드백 | 중립 조건 + 실제 위반 위치·보존 조건 |

같은 첫 출력·같은 KG·같은 모델 설정을 고정하고 두 조건 모두 추가 호출1회를 허용한다. ‘1회’는 영구 운영 제한이 아니라 **이번 비교에서 추가 계산량을 맞추기 위한 예산**이다. 반복해서 성공한 것만 남기는 방식은 사용하지 않는다.

첫 묶음은 위반이 확인된 6첫출력×2후속조건=최대12호출이다. 같은 문장 두 반복을 독립 입력으로 세지 않는다. 호출 기회는 같지만 피드백 내용 때문에 입력 토큰·실제시간은 다를 수 있어 별도 보고한다. 같은 출력에서 이미 나온 위반을 알고 추가 정보를 주는 실험이므로 진단 피드백 묶음의 효과로 해석하며 모델이 스스로 오류를 발견한 능력으로 주장하지 않는다.

기존 실패만 고르면 개선을 과장할 수 있으므로 먼저 저장된16출력의 검사 판정을 모두 보존한다. 새 개발 입력은 실행 전에 현재·과거·높임·아/어를 나눠 정하며, 첫 출력 성공도 함께 기록한다. 오류 판정이 불확실한 경우 자동 수정 요청을 보내지 않는다. 양쪽 추가 호출·토큰·전체시간을 기록한다. 한정된 계약 충족과 사람 자연스러움은 별도다.

종료: 고정된 비교 묶음과 새 개발 확인 한 번. 구체 피드백이 중립 재검토보다 반복적으로 낫고 다른 의미·높임 손실을 만들지 않는지 확인한다. 개선 없으면 이 구조를 미채택하고 같은 prompt 미세 수정을 반복하지 않는다. 두 번째 호출 횟수나 모델 역할을 바꾸려면 별도 설계 판단을 기록한다.

## 수정안 2 — 국소 변경과 무관한 미확정 값의 전역 차단을 재검토

DEV026의 나왔어요는 SEM_DECL_HAEYE_EO 후보가 조회됐지만 앞절 경계가 unknown이어서 전달되지 않았다. `condition_bridge/bridge.py`가 adapter_diagnostics를 모든 packet 절에 더한다. 이 사실은 확인했다.

모든 unknown을 무시하는 방식은 채택하지 않는다. 규칙마다 실제로 읽는 조건과 바꾸는 위치·보존하는 위치를 명시하여, 미확정 정보가 그 변경에 필요한 경우에만 막는 안을 검토한다. 예컨대 의문사 소속이나 높임 주체를 바꾸는 판단은 절 분석이 필요하지만, 이미 확인한 해체 부분을 보존하는 말끝 조합이 앞절의 이유 관계 판정까지 요구하는지는 따로 검토해야 한다.

종료: 허용 사례·차단 사례·미확정 사례를 모두 설명할 수 있고, 문장 ID 조건 없이 판정 가능할 때 코드 후보로 만든다. 현재는 원인·수정 설계까지이며 실행 gate를 완화하지 않았다.

## 수정안 3 — 승인 참조에 필요한 지식을 기존 구조에 순서대로 연결

| 묶음 | 참조에서 요구되는 내용 | 주의할 차이 |
|---|---|---|
| 기존 해예 구성 보완 | 과거 계사·부정 계사·거든예 등 | 표면형 보존, 구성별 조건. 단순히 모든 요를 예로 치환하지 않음 |
| 반말 평서·공손 질문 | 다/ㄴ다, 니꺼/습니꺼, 까예 | 품사·시제·질문/제안·높임을 구분 |
| 요청·금지·약속 | 주이소, 마이소/마레이, 께/께예 | 서로 다른 발화 기능이며 형태 목록만으로 결합 조건을 대체하지 않음 |
| 어휘·조사 | 먹/묵, 넣/옇, 조금/쪼매, 보다/보담, 대명사 | 원래 뜻·높임을 보존할 때만 사용. 종결 전용 위치 선정도 확장 필요 |
| 절 연결·인용 | 원인, 의도, 회상, 인용 | 사용자가 뒤로 미룬 자유로운 상황 창작과 구별. 원래 문장에 이미 있는 관계를 보존 |

원문 문헌·사용자 승인 사례·연구자 일반화를 구분한다. 문헌100% 확정만 저장한다는 제약은 없다. 다만 승인된 한 표현의 모든 어휘·생략·높임을 무조건 일반화하지 않는다. 참조와 다른 허용 후보도 보존한다.

이 묶음 전체를 한꺼번에 변경한 뒤 품질이 좋아졌다고 주장하지 않는다. 전달 후 생성 문제와 독립적으로 준비하되, 실행 검증은 묶음별로 구분한다. 첫 수정 묶음의 범위는 두 검토 의견을 반영해 확정한다.

### 검토 후 첫 지식 정제 묶음

과거/부정 계사(아니었어요·뜻이었어요·애들이었어요)의 해예 후보를 우선 정제한다. 현재4위치가 품사·선어말 범위 제한으로 제외되어 있고 승인 참조가 조합형을 선택한다. 기존 해체+예 문헌 설명과 사용자 승인 선택을 함께 기록하되, 범위를 넓히기 전에 형태 보존·계사/부정·과거 조건과 정상/반례를 정리한다. 부정계사 현재 아이다·공손격식·약속까지 한꺼번에 추가하지 않는다. 반말 평서 다/ㄴ다는 다음 독립 묶음으로 유지한다.

약속의 화행 분류와 객체높임 구별은 약속/요청 묶음의 선행 조건이며, 이미 지원한 해예 과거형 오류 피드백까지 모두 막는 선행 조건으로 삼지 않는다. '-니까→-어가', '-는데→-드만'은 현재 옛 카드와 입력 조건이 다르므로 사용자 승인 사례 기반의 일반화 후보로 별도 보류한다. 돕습니더의 돕- 보존은 모음 앞 ㅂ 변이와 같은 조건이 아니며 독립 방언 음운 규칙으로 만들어서는 안 된다.

QUAL003의 어예 단일 전달과 원래 해체 보존은 해석 혼선을 줄 수 있다. ‘모델 오류가 아니라 전달 오류’라고 인과적으로 확정하지 않는다. 기존 r8/r9의 표면 교체에서도 같예 실패가 있었으므로 단순 아예 표기 추가를 이미 검증된 해법으로 채택하지 않는다.
