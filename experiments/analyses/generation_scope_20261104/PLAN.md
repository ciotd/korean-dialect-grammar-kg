# ② 비교 조건 확정 → ③ 생성 범위 비교

사용자 승인: 2026-11-04 “2,3단계 같이 진행”. 지식 미전달 시 원문 유지 강제 해제는 타당성 판단 후 비교하도록 요청했다. Qwen은 계속 최종 문장 작성자다.

## 연구 질문

같은 분석·같은 KG 지식을 주었을 때, 생성 범위 제한이 원문 유지와 문법 보존에 어떤 영향을 주는가? KG가 없는 곳을 모델 사전학습으로 보완할 수 있는가? 변화가 늘어도 자연스러움 개선으로 간주하지 않는다.

| 조건 | KG 전달 | 생성 허용 범위 | 구분할 효과 |
|---|---|---|---|
| A 기존 | 기존 packet 그대로 | 지정 위치만, 없으면 원문 유지 | 기준선 |
| B 빈 지식 보완 | A와 같은 지식 | actions가 없을 때만 사전학습 변환 허용. 있을 때는 A와 요청 동일 | 원문 유지 강제 효과. actions 있는 문장은 동일 요청의 변동 대조 |
| C 문장 전체 | A와 같은 지식 | 지정 위치 밖도 사전학습으로 변환 허용. 의미·시제·부정·높임·화행 보존. KG 지시는 해당 위치에 적용 | B 대비 actions 있는 문장에서 수정 범위 효과. actions 없는 문장은 B와 요청 동일 |

범위 정책은 시스템 문장과 packet.instruction을 함께 일관되게 바꾼다. 두 필드는 같은 정책을 담는 전달 위치이며 카드·분석·근거·형태를 바꾸지 않는다. C는 KG 적용 위치의 형태 제한을 제거하는 실험이 아니며, 지정 위치 밖 생성을 허용하는 실험이다.

## 고정·규모·종료

- 기존 run `20261104T013633051461Z_support_expansion_full50`의 50입력과 실제 generation_packet을 고정한다. 분석/조회 재실행 0. 세 조건×두 반복=300 생성 요청.
- 새 개발 12문장을 출력 확인 전 확정한다. 반말 평서, 공손 평서, 질문, 요청·약속, 혼합 문장을 포함. 기존 r7 분석·조회 코드를 그대로 재사용해 각 문장 한 번만 분석하고 세 조건에 공유한다. 세 조건×두 반복=72 생성 요청. 문장당 EF 수만큼 분석 호출한다.
- 원문·KG·원시 packet·모델·temperature=0·top_p=1·비사고 모드·출력 JSON 구조·max_tokens=2048 고정. 반복 seed=20261104/20261105. 같은 seed가 서버에서 결정성을 보증하지는 않는다.
- 2 workers, 조건 순서 순환 배치. 호출 자동 재시도 0. 연속 5개 통신/구조 실패 또는 10건 이상에서 실패율 20% 초과 시 해당 묶음 중단, 실패 보존. 서버 설정 조사는 필수 아님.
- 기존 개발/실험 입력과 신규 개발의 문자열 중복 검사. 새 문장은 독립 최종 평가셋이 아니며, 문법 유형 자체는 기존 유형과 겹친다.
- 새로운 문법 규칙, 자연스러움 참조문장, Claude 번역 정답을 요청에 추가하지 않는다. 운영 KG·기본 생성 경로는 이번 결과로 자동 교체하지 않는다.

## 측정과 판정

1. 실제 요청 차이, 원시 출력/저장 일치, 지식 내용 불변 검증.
2. 전체/지시 있음/지시 없음 별 출력 유효성·원문 유지·변경 건수. 동일 요청 반복 간 차이도 표시. 변경률은 품질 아님.
3. 현재 지시가 요구한 보존의 기계 검사: 고정 위치 밖 글자 변화, 아/어요계열 해체+예 결합의 문자 일치. C에서 위치 밖 변화는 허용 행동이며 오류로 집계하지 않는다. 전체 문장이 재구성되면 위치별 문자 검사 불가를 별도 표시.
4. 원문·세 조건·반복·승인 참조(조회용만)를 사람이 비교할 UI. AI 검토는 구체적인 누락·시간·높임·기능 변화와 불확실성을 기록. 자연스러움 최종 점수나 논문 정답률로 대체하지 않는다.
5. 토큰, 호출 수, 호출별 지연 분포, 전체 묶음 벽시계 시간. 조건을 동시 실행하므로 조건별 독립 처리시간으로 해석하지 않는다.

② 종료: 세 조건·실제 요청 변환·검사 코드·동일 지식 검증·검토 완료.
③ 종료: 제한된 두 반복과 신규 개발 실행 또는 중단 사유 보존, 입력별 결과/오류/비용/다음 판단 정리. 결과가 나쁘면 프롬프트 문구 탐색을 추가 반복하지 않는다.
방식 채택은 자연스러움과 의미 보존 근거가 필요하다. 이번에는 자동 변경 증가만으로 채택하지 않는다. 전체 분석 재실행④·KG 확장⑤는 별도 단계다.

이전 실험은 동일 위치에서 결합 설명·접두부·문자 편집·온도를 주로 비교했다. 이번은 빈 actions의 강제 원문 유지와 지정 위치 밖 생성 금지를 직접 비교한다. A/B의 지식 없는 구간은 사전학습 생성의 진단 기준선이며 KG 효과 증거가 아니다. C의 효과도 KG 우월성을 뜻하지 않는다. 최종 논문에는 별도 독립 데이터와 동등 모델/예산의 무KG·텍스트검색·조건KG 비교가 필요하다.

## 실행 중 검토 반영: v2 (신규 개발 실행 전)

전송 승인 대기 중 별도로 승인된 첫 회귀 비교를 실행했다. 독립 검토에서 open 정책의 ‘새로운 방언 규칙은 만들지 않는다’가 모호하다는 지적이 나왔다. 학습 지식 사용과 규칙 발명 금지가 논리적으로 같은 것은 아니지만, 범위 조작에 불필요한 모호함을 없애기 위해 v2에서 ‘KG 지정 위치의 결합형을 사용하고, 그 밖은 학습 지식을 사용할 수 있다’로 범위를 명시했다. 첫 300응답을 v1로 보존하고, v2 300회와 개발72회를 수행한다. 정답·개별 실패 표현에 맞춘 튜닝이 아니다. 이 수정 뒤 추가 문구 탐색은 하지 않는다.

신규 공유 분석은 **실제 분석 호출/구조 오류 한 건 발생 시 즉시 중단하고 생성 비교에 진입하지 않는다**. 분석의 의미적 unknown은 통신·코드 실패와 다르며 그대로 기록한다. 기존 선언의 5연속/20% 기준은 생성 호출에 적용한다. 진단 코드 실패도 별도 사유로 중단한다.

운영 분석 의존27파일은 과거 해시와 대조한다. 진행표 unit_key 추가 한 곳만 의미 처리와 무관한 차이로 허용하고 기록한다. span/target/겹침 사전검사, 원시 출력 보존, p95 최근접 순위(ceil)도 명시한다. 결과 하위집단과 동일 요청 변동은 report.py에서 집계한다.
