# 실험 전 판단과 다음 순서

2026-11-02. 이번 범위는 저장된 연구 기록 대조, 두 검토자의 독립 검토, 다음 실험안 작성이다. 새로운 Qwen 생성, KG·카드·생성 코드 수정은 하지 않았다.

## 먼저 알아야 할 결론

**지금은 KG 전체를 다시 만들거나 같은 50건을 바로 재실행할 단계가 아니다.** 필요한 카드가 빠진 문제, 카드의 활용 설명이 부족한 문제, 모델이 받은 정보를 잘못 읽는 문제, 프로그램의 전달·판정 문제가 함께 관찰된다. 어느 하나가 전체 실패의 주원인인지는 아직 확정하지 못했다.

## 실제로 확인한 것

| 문제 | 실제 기록 | 의미 |
|---|---|---|

숫자는 50개의 서로 다른 문장 수가 아니라 300개 반복 처리 기록 또는 그 안의 편집 수다. 항목 간 중복이 있다. 자연스러움 정확도를 계산한 것이 아니다.

### 카드가 빠진 위치를 실제로 찾은 예

**‘확인해 볼게요’ → `-께예` 카드**: 카드 존재 → 조회됨 → 원래 어미와 높임 일치, 37점 → 마지막 선별에서 탈락 → Qwen에 미전달.

마지막 선별 코드는 ‘문법 기능 일치’ 또는 ‘연결 어미 일치’만 인정한다. 이 카드가 받은 ‘원래 종결 어미 일치’는 인정 항목에 없다. 따라서 이것은 단순히 48장 제한에 밀린 문제가 아니다. `verify_selection.py`로 독립 확인했다. 반면 DEV002의 `-다` 카드는 이 문턱은 통과하지만 동점 후보 순서와 위치별 3개 제한에서 빠진다. 두 원인을 구별해야 한다.

수정할 때도 ‘어미만 맞으면 무조건 허용’하면 안 된다. 질문인지 약속인지 등 카드의 필수 기능을 함께 확인하도록 연결해야 한다. ADVCE010B는 분석이 질문으로 기록되어 있으므로 같은 방법으로 자동 허용할 수 없다.

## 검증 상태

- 원문 50개와 두 조건·세 반복의 300기록 연결 완료. 실제 과거 Qwen 호출은 219회.
- 기존 실행 자료 184개와 저장 산출물 2,846개 해시 일치. 원격 서버의 정확한 체크포인트·GPU까지 검증한 것은 아니다.
- Qwen 모델 목록 조회 성공: Qwen3.8-27B. 이번 생성 호출은 0회이므로 생성 요청까지 성공한다고 단정하지 않는다.
- Codex 검토자는 GPT-6-Astra High, Claude 검토자는 Opus 5.5. 역할과 정확한 전달 지시는 private/dispatch에 보존한다.
- 확정 50건은 회귀·진단용이다. 새 문장 일반화의 최종 평가 자료로 사용하지 않는다.

## 다음 작업 제안: 먼저 연결 오류, 그다음 설명 효과

아래는 **승인 전 제안**이다. 이번에 실행하거나 생산 코드에 반영하지 않았다.

| 순서 | 할 일 | 통과 기준 |
|---|---|---|
| 1. 연결 오류 수정 | 원래 어미 일치와 필수 문법 기능을 함께 읽도록 선별기 보완. 보류된 편집에 적용 지시를 보내지 않음. 최종 계획과 요약 상태 일치 | 전체 50개의 저장 기록 재검사. 의미·높임·시제와 무관한 위치에 새 카드가 허용되지 않는 반례 검사. 전달 상태 모순 0건, 요약 상태 불일치 0건 |
| 2. 비교 조건 동결 | 같은 분석·같은 카드·같은 선택 위치를 두 조건에 사용. 입력별 적용 가능/보류 이유를 호출 전에 확정·저장 | 두 조건의 차이가 승인한 설명 항목뿐인지 자동 대조. 정답 참조 및 문장별 완성 교체 표현이 요청에 없는지 확인 |
| 3. 설명 효과 비교 | A: 기존 표현의 지시. B: 하이소체의 뜻을 설명하는 한 문장만 추가 | 해당 등급을 반말로 오해한 보류가 줄어드는지 확인. 원시 활용 오류·시제·높임 손상은 별도로 대조 |

첫 단계는 **확인된 연결·집계 결함 수정**이다. 이것이 자연스러움을 얼마나 높이는지는 아직 모른다. 두 번째 이후는 **그 수정본을 양쪽에 공통으로 적용한 통제 비교**다. 과거 출력과 새 출력을 비교하여 모든 개선을 ‘설명 덕분’이라고 주장하지 않는다.

### Qwen 비교의 정확한 범위

- 전체 50개를 포함한다. 적용할 카드가 아직 없는 문장은 실패 원인을 기록하며, 억지로 목표를 만들어 호출하지 않는다. 임의의 소수 문장만 주 평가로 삼지 않는다.
- 호출 가능한 입력 수를 N으로 동결한 뒤 A/B 각 3회, 최대 300회 생성. 원문·분석·카드와 순서·선택 위치·편집 ID·검사 코드·모델·생성 설정을 고정한다. 한 조건의 반복 요청도 같은 seed와 본문으로 전송하며 순서를 교차한다.
- B는 다음 한 문장만 추가한다. “여기서 haiso(하이소체)는 문헌에서 윗사람을 대우하는 용례가 확인되는 말투이며, 이름만 보고 반말로 판단하지 마세요. 하소체와의 구별은 지역에 따라 다릅니다.” **순수 JSON 모양 변경이 아니라 해석에 필요한 설명을 추가하는 실험**이다. `plain` 설명·활용 조합 안내는 동시에 바꾸지 않는다. 새 활용 정답·Claude 완성 문장·새로운 방언 규칙은 넣지 않는다.
- 카드 자체의 결합 지식이 없는 문제는 이번 비교에서 해결됐다고 주장하지 않는다. 설명 추가로 개선되지 않으면 그 가설을 보류하고 결합 지식 또는 생성 방식 문제로 넘어간다.
- 원시 응답, 코드 보정, 최종 출력, 시간·토큰·호출 실패를 따로 기록한다. 중복·누락 편집 번호나 길이 종료는 문법 오류와 분리한다. 원문 유지도 무조건 오류로 세지 않는다.
- 문법 기호를 오해한 보류가 감소하는지가 1차 관찰 항목이다. 목표 위치의 활용 적절성과 시제·높임 보존은 검토자가 근거와 함께 판정하고, 자연스러움에 대한 최종 판단은 사용자에게 요청한다. 모델끼리 동의한 비율을 정확도로 보고하지 않는다.
- 동일 요청의 응답도 달라지면 그 변동을 먼저 보고한다. 양쪽 차이가 반복 변동과 구분되지 않으면 설명 효과를 확정하지 않는다. 완전히 동일한 요청에서 달라지지 않았다고 해서 서버의 결정성이 증명된 것은 아니다.
- 첫 생성 연결 점검이 실패하거나 요청 차이 검사에 실패하면 본 실행을 중단한다. 중간 결과를 보고 프롬프트를 고치지 않고 같은 버전을 끝까지 유지한다. 불가피한 수정은 새 실행으로 분리한다.

실제 비용·시간은 첫 연결 확인 후 이전 처리시간과 함께 추정한다. 300회는 호출 상한이며 정확한 소요시간을 미리 확정하지 않는다. 확정 50건은 이미 내용을 본 진단용 데이터다. 다른 문장에서도 되는지 확인하는 별도 평가가 이후 필요하다.

### 검토 의견에서 바로잡거나 한정한 부분

- Claude는 ADVCE010B의 평서 `-지예` 카드를 0점이라고 썼지만 저장된 판정은 **37점**이다. 문법 기능 일치가 없어 마지막 필터에서 제외된 점은 맞다. `private/selection_verified.json`에 대조 근거를 보존했다.
- 형태 목록 검색에서 안 나온 표현은 **카드의 해당 필드에서 미발견**이다. 7문헌 전체와 원본 KG에 없다고 확정하지 않는다. 활용 조합으로 만들어지는 형태는 목록에 없어도 가능하므로 조건·결합 설명까지 확인해야 한다.
- `-예`와 `-습니더`가 함께 쓰였다는 사실은 참조 오류의 증거가 아니다. 복수의 자연스러운 표현이 있을 수 있다. 지금 사용자에게 둘 중 하나만 고르도록 요구하지 않는다.
- Claude의 문법 판단은 검토 의견이다. 예를 들어 `괜찮먼`과 `놓먼`의 검사 차이만으로 두 활용이 동일하게 허용돼야 한다고 결론내리지 않는다. 어간별 조건 확인이 더 필요하다.
- Claude는 전체50의 출력·카드를 대조했으나 거절 사유 전문은 주로 1회차를 읽고 반복 사유는 검색으로 집계했다. 300개 사유를 모두 정독했다고 보고하지 않는다.

### 외부 근거의 확인 범위

Claude가 검색한 자료 중 총괄도 [이상규(1991), 경북 방언의 경어법](https://www.korean.go.kr/nkview/nklife/1991_3/1_4.html)의 본문을 직접 확인했다. 이 자료에는 윗사람을 대우하는 명령·허락 표현으로 `-이소` 계열이 제시되어 있다. 따라서 모델이 이름만 보고 반말로 단정한 사유는 재검토할 근거가 있다. 이 자료만으로 현재 모든 경상도 지역의 사용 빈도와 자연스러움을 확정하지 않는다. 나머지 검색 자료와 미확인 범위는 Claude 검토 원문에 남겼다.
