# 기존 수정 효과 정리와 단계별 원인 확인 준비

2026-10-31 사용자 “한번 진행해 봐” 승인 범위: 기존 진단을 반복하지 않고 이전 수정의 효과를 연결하고, Qwen 없이 단계별 원인 확인 실험을 준비한다. KG·카드·생성 코드 추가 수정이나 새 모델 실행은 이번 범위가 아니다.

## 결과

- 기존 여섯 수정의 관찰·확인된 효과·미검증 범위를 연결했다. 새로 오류를 50개 진단한 작업이 아니다.
- 기존 12개 Run의 결과504개를 재집계해 기존 요약의 변경/유지/무출력 수치와 일치함을 확인했다. 중복 입력의 여러 실험 결과이며 504개 독립 문장이 아니다.
- 최신50입력,100출력, 과거50진단, 사용자 승인표현을 연결했다. 과거 진단의 source batch와 최신 실행 batch를 구분한다. 과거 진단을 최신 출력의 확정 원인으로 재사용하지 않는다.
- 모델용 입력50개는 기존 전달 패킷과 정확히 같게 복사했다. 승인 정답은 검토 자료에만 있고 모델 패킷에 새로 넣지 않았다.
- 기존 Multi 선택 응답50개를 보존했다. 응답이 존재한다고 유효한 선택 또는 올바른 선택으로 인증하지 않는다.
- 별도 검토한 수정 선택표는0개다. 검토 슬롯50개와 선택만 변경하는 입력 검사기·실제 위치 연결 예제1개를 준비했다. 라이브 진단 실행기는 아직 구현하지 않았다.
- 유효한 위치 연결 예제1개·검토된 변경 없음 예제1개, 잘못된 연결·정답 텍스트 필드 등10개 거부 사례를 확인했다. 언어학적 정확성 검사가 아니다.

## 핵심 판단

| 기존 작업 | 해석 |
|---|---|
| 관련 카드 추가 전달 | 당시26문장에서는 추가 카드 최종 반영0. 전달만으로 해결하지 못함. |
| 카드 내용 v2/v3 비교 | 카드 사용과 문장 변경이 늘었다. 자연스러움이 개선됐다는 측정은 아님. |
| 요→예 부분 교체 | 선택·적용된20곳의 범위 일치 확인. 전체 활용을 해결한 것은 아님. |
| 분석 보정 재검증 | 선택을 고정해 재생했으므로 새 검색·선택 효과는 알 수 없음. |
| 말높임·연결어미 종합 수정 | 무출력은 감소했지만 여러 변경이 함께 들어가 개별 원인은 분리 불가. |
| 추천·적용 기능 통일 | 저장 응답의 잘못된 보류 일부 해소. 새 Qwen 결과는 없음. |

따라서 모든 수정이 무효였다는 결론과 시스템이 개선됐다는 결론 모두 과도하다. 검증된 국소 동작을 보존하고 미검증 연결만 구분해서 시험한다.

## 다음 실험의 조건

기존 전달 카드 안에서 카드·형태·원문 위치를 검토한 선택과 기존 선택을 동일한 Multi 워커로 비교한다. 두 조건의 전체 카드 목록, 지시문을 만드는 방식, 분석, 모델 설정, 반영 검사도 같게 둔다. 원래 자유서술 지시와 검토자의 자세한 새 지시를 바로 비교하면 설명 효과가 섞이므로 금지한다. instruction뿐 아니라 reason/after/action/편집 묶음·의존관계도 같은 생성 절차로 다시 구성해야 한다. 전체 정답이나 완성된 교체 단어를 입력하지 않는다. 과거 워커는 선택 카드만 받았으므로 새 전체 카드 대조군을 과거 출력과 직접 비교해 선택 효과라고 해석하지 않는다. 새로 실행한 두 조건끼리만 비교한다.

검토 결과 변경 없음은 미검토 빈칸과 구분한다. 검토된 변경 없음에서는 워커를 생략하고 원문 유지·호출0회를 기록한다. 전체 짝지은 사례의 결과와 실제 호출된 부분의 비용 분모를 따로 표시한다. 승인 정답을 참고한 검토 선택은 진단용 도움 조건이며 자동 선택기 성능이나 새로운 문장에 대한 성능이 아니다.

필요한 카드가 전달되지 않은 사례는 선택만 바꾸는 실험에 임의로 넣지 않는다. 기록에서 제외하지 않고 별도 전달/지식 적용 검토 대상으로 유지한다. 선택이 이미 같으면 선택 효과 실험이 아니라 지시문/활용 시험이 필요하다. 선택이 검사에 막히면 차단도 결과로 남기고 검사를 끄지 않는다. Single을 쪼개 워커를 추가하면 구조가 변하므로 이 진단을 Single/Multi 성능 비교로 부르지 않는다.

조건당 최소3회 짝지은 반복과 순서 교대를 사전 명시한다. 반복은 서버 변동을 관찰하기 위한 것으로 충분한 통계적 검정력을 보장하지 않는다. 실제 호출 수는 검토 완료·실행 가능 계획 수에 따라 결정하고50개 전체의 적격/미적격 사유를 공개한다. 기존 설명/조합 도움300조건 비교는 별도 질문을 다루므로 그대로 보존한다.

## 파일과 재현

- `prepare.py`: 기존 요약·문장·분석·카드·응답을 읽어 새 timestamp 준비 묶음 작성. 네트워크 클라이언트 없음.
- `verify.py`: 과거12 Run 재집계, 소스 불변,50패킷 동일성, 선택 입력 거부 검사.
- `private/latest.json`: 최신 준비 묶음 위치. 이전 묶음은 보존.
- `private/preparations/<timestamp>/ledger.json`: 근거별 효과 표.
- `cases.json`: 과거 진단·최신 결과·승인 표현을 연결하는 사람용 자료.
- `model_inputs/`: 정답을 추가하지 않은 기존 모델 입력·형태소.
- `archive_only/`: 원본 Multi 선택 응답. 번역 표현이 자유 지시문에 들어 있을 수 있어 실제 워커 입력으로 직접 재사용하지 않는다.
- `selection_review/`: 미검토 선택표50개. `pending`이며 자동 승인하지 않는다.
- `protocol.json`: 고정 조건·변경 허용 범위·미해결 사항·결과 해석.
- `verified_source_hashes.json`, `verification.json`: 원본 추적과 재검증.

```powershell
python experiments/analyses/effect_ledger_20261031/prepare.py
python experiments/analyses/effect_ledger_20261031/verify.py
```

재실행은 새 준비 폴더를 만든다. 보고서 최신 표시만 갱신하며 이전 보고서도 해당 준비 폴더에 보존한다. `private/`는 Git 제외 자료다. 로컬 파일과 실험 원본을 별도로 보존해야 한다.
