# 50문장 오류 위치 점검과 다음 설계 · 2026-11-09

이번 질문: 최신 50문장 결과에서 분석 오류, 지식 조회/전달 문제, 생성 오류, 출력 형식 실패를 실제 기록으로 구분할 수 있는가? 어떤 문제에 워커 분담이 도움이 될 가능성이 있는가?

범위는 읽기·독립 검토·설계 제안이다. Qwen 새 호출, KG 수정, 연구 파이프라인 수정은 하지 않는다. 공유 보고서는 원본을 보존한 별도 웹 사본으로 배포한다. 사용자는 링크를 아는 누구나 열람하도록 승인했다.

근거 실행: `experiments/runs/20261109T030211818725Z_kiwi_default_regression`.
원본 보고: `experiments/analyses/kiwi_focused_full50_20261109`.
이전 분업 설계: `experiments/analyses/semantic_workers_design_20261109/DESIGN.md`.

1. 기존 50개 출력과 단계별 원본 기록 대조. 코드로 확인되는 실패와 언어학적 판단, 원인 가설을 구별한다.
2. 기존 Orca Claude와 Codex가 독립 검토. 반드시 문제 위치 → 실제 근거 → 수정안을 제시한다. 검토자는 runtime/KG를 수정하지 않고 지정 검토서만 작성한다.
3. 리드가 근거를 다시 확인하고 의견 차이를 조정한다. 모델 합의는 정답 인증이 아니다.
4. 수정 우선순위, 공통 대조 조건, 분업 후보, 비용/종료/중단 기준을 쉬운 말로 제안한다.

종료: 두 실제 검토와 근거 대조를 마치고, 실행할 다음 묶음과 실행하지 않을 범위를 구별한 설계안을 제시한다. 인과가 확인되지 않으면 확정하지 않고 다음 통제 비교 대상으로 남긴다. 50건은 노출된 회귀 자료이며 자연스러움 정확도를 임의 계산하지 않는다.

산출물: 독립 검토서 2개, 통합 설계안, 사용자용 쉬운 설명. 연구 효과 증명은 후속 비교 실험의 과제다.
