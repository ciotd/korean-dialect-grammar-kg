## 현재 구조를 이해할 핵심 사실

공통 문법136항목은 AnalysisConcept48·Construction54·GrammarFeature23·AggregateInterface11이다. 표준어와 방언을 공통 특징으로 연결하려는 분석 설계이며 전체 표준어 문법의 검증된 실행기가 아니다. 기술 책임54와 문헌 항목721은 별도다. `original_spec`에 입력·처리·조건·금지·출력·보존·미확정 대응·근거·시험 설계가 저장된다. `design_blueprint`와 `runtime_active=false`인 설계 항목을 구현 완료로 말하지 않는다.

현재 실행은 입력 관찰→Qwen 기능·관계 분석→코드 결속→조건 조회→전달→Qwen 전체 생성이다. 조회기는 실행 용법의 조건과 원문 항목의 문자열 참고 검색을 읽는다. 기존 `cross_reference` 2,841개를 자동으로 모두 따라가며 문법 변환하는 구조가 아니다. 문장만 늘려 모든 설계 관계가 실행되기를 기대할 수 없다. 검사대장에서 문장과 관계를 연결할 수 있는지, 현재 조회가 실제 사용하는지, 구조/원문 검사로 확인해야 하는지를 구분하고 실행 연결 공백을 남긴다.

## 다음 검사 순서와 종료 기준

1. **이해 자료를 기준으로 현재 설계와 실제 구현을 대응한다.** 각 문법 항목에 저장 내용, 출처, 실행 코드 또는 실행 미연결, 실제 사례를 붙인다. 사용자가 기본 구조·주요 속성·조건 판정·실행 기록·한계를 근거와 함께 설명할 수 있게 한다.
2. **원문→KG와 KG→원문을 대조한다.** 721문헌 항목과 136공통 설계, 출처·관리 항목을 한 개도 목록에서 누락하지 않는다. 문헌에 있는데 빠진 조건·예외도 찾는다. 발췌 문자열 일치는 의미 판정을 대신하지 않는다.
3. **분기별 자연어 예문을 생성·검토한다.** 적용·비적용·미확정·관계 오류·상충 후보를 포함하고, 각 예문에 목표 ID, 변한 조건, 보존 조건, 기대 판정, 근거, 검토 상태를 연결한다. 여러 예문이 같은 목표만 반복하면 다른 미검사 목표의 완료로 세지 않는다. 미실현 조합은 이유를 남기고 임의의 문장을 억지로 정답 처리하지 않는다.
4. **채택한 모든 예문을 실제 전체 파이프라인에 넣는다.** 분석·조회·전달·생성의 실제 도달을 측정한다. 앞 단계 실패는 원본과 함께 보존하고 후속 미수행 단계를 표시한다. 기대 조건을 강제로 주입한 진단과 원문만 넣은 전체 검사를 별도 기록한다.
5. **사람이 실패·미확정·충돌을 판정하고 새 버전으로 수정한다.** 기존 실패와 미채택 수정도 보존한다. 수정한 용법의 재검사와 영향받는 다른 용법의 회귀 검사를 한다. 경고 없는 사례도 확인해 검사기의 누락을 점검한다.
6. **비교 실험용 버전을 동결한다.** 모든 항목에 판정과 근거가 있고, 실행 대상별 예문·실제 경로·출력 판정이 연결돼야 한다. 미지원·미확보·미판정이 남으면 그것을 공개하고 사용자가 전체 검증 목표의 충족 여부를 판단한다. 단순히 미확인 표지만 채워 완료라고 하지 않는다.

100개 또는1,000개를 미리 성공 목표나 비용 상한으로 삼지 않는다. 필요 예문 수는 고유 용법·조건·관계와 누락 상태에서 결정한다. 비용은 실제 토큰·호출·시간으로 계속 기록하며, 무한 재시도 대신 새로운 검사가 무엇을 추가로 확인하는지 남긴다. 시스템 실패 시 자동 반복으로 비용만 누적시키지 않는다. 기존 실행기의 과거200호출 상한을 새 연구의 예산으로 전용하지 않으며 새 검증 프로그램으로 구분해야 한다.

## 실험 동결 계약

검증·개발 중에는 오류 수정이 가능하지만 매 판본을 보존한다. 방법 비교에 들어가면 다음을 실행 전에 고정한다.

| 항목 | 동결할 내용 |
|---|---|
| 지식 | KG 파일·근거 버전·용법과 지원 범위·해시 |
| 분석 | Kiwi 버전/사전/설정, Qwen 모델·프롬프트·출력 계약·결속 코드 |
| 조회 | 후보 생성·조건 판정·unknown·충돌 처리·순위 |
| 전달 | 포함 필드·참고 선별·순서·길이 제한·제외 기록 |
| 생성 | 모델·역할·호출 수·디코딩·최종 작성 주체 |
| 자료 | 입력 ID·개발/회귀/최종 용도·노출 이력·반복과 순서 |
| 평가 | 평가 지침·판정자·주지표·실패 분모·종료 기준·불확실성의 처리 |

비교 요인만 사전 조건표에 따라 다르게 한다. 조회 방식을 비교한다면 조회 방식 두 개가 각 조건 안에서 고정되어야 한다. 실험 도중 발견한 결함이 비교에 영향을 주면 해당 실행을 종료 상태와 함께 보존하고, 새 버전에서 영향받는 비교 조건을 모두 맞춘다. 무관한 변경이라고 판정한 경우에도 이유와 해시를 남긴다. 수정 전 A와 수정 후 B의 차이를 방식 효과로 보고하지 않는다.

동료는 준비 기간에 연구 목표·가설·기존 근거·반증 조건·비교표를 검토한다. ‘KG 검증 완료 전에는 아무 논의도 못 한다’는 뜻은 아니다. 다만 검증 중인 기반에서 나온 탐색 결과와, 동결 후의 방법 비교 결과를 합치지 않는다. 새 독립 평가 자료는 지식 수정에 사용하는 예문과 분리한다.
