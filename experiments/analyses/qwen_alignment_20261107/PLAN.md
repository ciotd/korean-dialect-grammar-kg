# 분석값 연결과 검토→수정 보완

## 질문과 범위

같은 KG를 유지한 채 분석 응답의 표기·허용값과 출력 검토의 수정 전달을 바로잡으면, 실제 규칙이 생성까지 전달되고 시제·높임 손실이 줄어드는가? 단순 완료 건수는 품질 지표로 쓰지 않는다. 기존6개발문장을 진단에 재사용하며 정답은 요청에 넣지 않는다. 기존50/독립평가의 역할은 바꾸지 않는다.

## 순서와 종료

1. 저장6건 재생으로 형태·조건 충돌, 잘못된 수정값, 검토의 원인분류 때문에 수정이 차단되는 경로를 재현한다.
2. 형태/특징 용어 설명과 typed 수정제안, 단위별 잘못된 제안 격리, 원인단계와 수정대상의 분리, 검토 입력의 간결화를 구현한다. 형태 모순은 구조 워커에 최대1회 다시 묻고 원본과 수정응답을 둘 다 보존한다. 자동 정답 교정은 하지 않는다. 반복해도 모순이면 관련 후보를 보류하고 기록한다.
3. 모의검사와 실제KG도달검사를 통과한 뒤 새 코드로 기존6개발문장 한 차례 실행한다. 기본4역할·분석재검토최대1·작성수정최대1, 최대6호출/문장, 총36호출, 자동전송재시도0. 실행중 코드/KG고정.
4. 같은 분석 누락·반복검토·높임손실이 계속되면 같은프롬프트추가수정과50건확대를 멈춘다. 기존Kiwi+Qwen경로로 같은6문장 비교실행을 수행할 수 있다. 이는 전체기존경로 복귀가능성 진단이며 Kiwi 단일요인의 인과효과실험이 아니다. KG/입력/모델을맞추고 서로다른호출·생성지시문차이를표시한다. 결과/사람평가 없이 기본경로를몰래변경하지 않는다.
5. 두리뷰어의실제의견·반론·수정판단·최초실패지점·수정전후문장을 쉬운보고서로 정리한다. 성공시비교범위를확대하고, 실패시남은병목과Kiwi복귀조건을정리한다.

모든문법범위를추가하거나 출처/실행조건을수정하지않는다. 검토모델의합의는언어사실인증이아니다. 개선판단은각단계실제기록과구체보존오류에근거한다. 이후새문장일반화와독립블라인드평가는별도로남긴다.
