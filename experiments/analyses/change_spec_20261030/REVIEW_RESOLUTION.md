# 검토 반영 명세 — 무엇을 바꾸고, 무엇을 아직 확정하지 않았나

총괄은 Codex 8개·Claude 7개의 지적을 모두 읽고 실제 코드·문헌 발췌와 대조했다. **아래는 구현을 위한 명세 보완이며 실행 코드 적용이나 새 방언 생성 결과가 아니다.** 두 검토자는 같은 초안과 근거를 독립 검토했다. 보완본은 총괄의 취합 결과이며, 검토자들이 보완본을 재승인한 것은 아니다.

## 쉽게 보는 결론

| 부족했던 점 | 보완한 결정 |
|---|---|
| 형태 목록만 있으면 변환 규칙으로 보일 수 있음 | 변환 제안·관찰·차단 조건·반증 정보를 구별. 관찰/반증을 삭제·교체 명령으로 자동 승격하지 않음 |
| Qwen이 맞다고 쓰면 코드도 맞다고 판단할 위험 | 원문에서 직접 확인한 정보, Kiwi/Qwen의 분석, 코드의 대조 결과를 따로 기록 |
| 한 편집에 여러 규칙을 어떻게 연결할지 불명확 | 편집 안에 여러 ‘카드·목표형 연결’을 두고 각 역할과 순서를 기록 |
| 다어절 편집에서 일부 뜻이나 문장부호를 잃을 수 있음 | 같은 원문 기준의 범위, 내부 문장부호 보호, 겹침·절/인용 경계 검사 명시 |
| 일부 편집만 실패했을 때 처리 불명확 | 서로 독립된 편집만 부분 적용. 의존하는 편집은 묶음 전체를 보류 |
| 테스트 통과가 개선처럼 보일 수 있음 | 기존 동작 재현과 새 명세의 수용 시험을 분리. 전자는 실행 완료, 후자는 기대 결과를 정한 단계 |

## 1. 기존 필드를 어디로 옮길 것인가

원본 카드는 보존하고 별도 버전의 해석표를 만든다. 값이 없는 `required`, `resolved`, `not_yet_verified`를 실제 판정값이나 노드 ID로 사용하지 않는다. documentary와 normalized가 충돌하면 한쪽을 임의 선택하지 않고 둘 다 보존한다.

| 실제 카드/필드 | 제안한 분류 | 확실성 / 처리 |
|---|---|---|
| ACC_03 `particle_sense=accusative` | 입력 기능 후보 | 형태·문법 분석과 대조하되 분석은 추론 |
| ACC_03 `forms=[-를]` | 목표 표현 목록 | 원본에 직접 존재. 목표를 -을로 쓰면 카드 인용 불일치 |
| ACC_03 `coda_condition=not_yet_verified` | 미확보 적용 조건 | 받침 규칙을 임의 생성하지 않음. 미확보만으로 모든 조사 카드 사용을 일괄 금지하지 않음 |
| ACC_03 `np_id=required` | 분석에서 공급할 명사구 참조 요구 | 실제 명사구 ID가 아님. 현재 미공급이면 그 사실을 표시 |
| CAUSE_03 `construction_sense=cause_or_sequence` | 입력 관계에 대한 후보 설명 | 인과·계기 의미 차이를 지우는 포괄적 교체 허가가 아님 |
| CAUSE_03 `source_clause_id/target_clause_id=required` | 관계 양끝의 분석 참조 요구 | 실제 절 ID와 범위를 별도로 공급해야 함 |
| JI_ASSERT/JI_CONFIRM `ending_family=JI` | 목표 계열 설명으로 분리할 제안 | 원문이 -지여야 한다는 조건으로 자동 사용하지 않음. 문헌 대응 검토가 필요한 해석 |
| 두 JI 카드의 `utterance_function` | 용법 후보 | 화자의 확정적 태도·질문 응답·청자 확인 요청을 구별. 단순 평서와 같다고 간주하지 않음 |
| HAM_AUX_PROGRESS `kind=observation` | 관찰 자료 | 진행 구성의 존재 근거. 미래/이유 표현 삭제의 허가가 아님 |
| HAM_TOPIC_GAP 부재 반증 | 반증 자료 | 은·는 삭제/은↔는 교체의 근거로 사용 불가 |
| GEORO_BLOCK_BECOME | 차단 조건 후보 | forms에 -게 되-가 있어도 생성 목표로 사용하지 않음. 원 규칙과의 차단 관계를 확인해야 함 |
| 지역·시기·표본 범위 | 출처 범위 정보 | 보존하되 이번 연구에서 전역 필수 프로필 관문으로 추가하지 않음 |

개별 형태에 문헌이 명시한 조건도 별도로 보존한다. 예컨대 -지러에 대한 연령·높임 기술을 -지/-제 전체에 복사하지 않는다. 이번에 그 조건을 자동 필터로 활성화하는 것은 별도 결정이다.

## 2. 조건 검사: 세 층을 분리

1. **자료:** 원문 문자열·문장부호·문자 위치는 코드로 직접 확인한다. Kiwi 형태 분석과 Qwen의 기능 분석은 각각 분석 산출물이다.
2. **대조:** 조건별로 근거 참조, 판단 주체, 값, 코드의 일치/불일치/미확인을 기록한다. 분석값끼리 일치한 것은 독립적인 언어학적 검증이 아니다.
3. **적용 결정:** 구조 위반과 명시된 금지 변환은 적용하지 않는다. 문법상 중요한 모순은 해당 편집을 보류한다. 연구 범위에서 제외한 지역·시대 조건은 ‘이번 판정에 사용하지 않음’으로 표시하며 충족됐다고 적지 않는다.

‘중요한 조건’은 ID·원문 범위·목표형/카드 대응, 원문에 명시된 부정·시제·높임·논항/절 관계와의 충돌처럼 **의미 보존 또는 변환 근거에 직접 영향을 주는 항목**을 뜻한다. 미확보 조건 전체를 자동으로 중요한 조건으로 승격하지 않는다. 카드별 필수 조건의 확정은 해석표와 원문 대조를 거쳐야 한다.

검사 가능한 의미 조건이 전혀 없는 자료는 참고 자료로 남기며, 그것 하나만으로 수정 근거가 충분하다고 표시하지 않는다. 이것은 그 표현의 언어적 금지를 뜻하지 않는다.

## 3. 계획 형식과 버전 연결

```text
요청: 원문 해시 + 분석 버전 + 카드 스냅샷 해시
  편집 edit_id
    ├─ 대상: 실제 연속 어절 ID들 → 코드는 원문 문자 범위를 계산
    ├─ bindings: [카드 ID, forms 배열 위치, 바꿀 요소, 결합 순서] 여러 개 가능
    ├─ 조건 판단: 근거 위치 + 분석 출처 + 모델 주장 + 코드 대조 결과
    ├─ 보존 대상: 어휘/논항, 부정 범위, 시제·상·양태, 높임, 절 관계
    ├─ 모델 제안: apply / keep / needs_review
    └─ 코드 판정·실제 반영 상태: 별도 기록
```

- ID는 실제 KG 카드 ID를 쓴다. edit_id·요청 버전은 프로그램의 지역 식별자이며 새 KG 노드가 아니다.
- 복수 카드가 같은 부분을 다르게 바꾸거나 적용 순서가 불명확하면 편집 전체를 보류한다. 자유문장 instruction은 구조화 목표를 덮어쓰지 않는다.
- 카드 해시는 코드가 요청 패킷 생성 때 계산한다. Qwen이 해시를 생성하거나 긴 해시를 반복 출력할 필요는 없다. 모델은 카드 ID/목표형 위치를 반환하고, 코드는 고정된 요청 스냅샷과 대조한다.
- 카드 해시 대상은 기존 `id,module,kind,title,when,forms,avoid`의 정규 JSON이다. 키 정렬, UTF-8, JSON 구분자 공백 제거, NaN 불허를 고정한다. 배열 순서와 문자열 내용은 유지한다. 형태/인용 문자열의 공백·유니코드 문자를 임의 정규화하지 않는다.
- 해석표도 별도 버전/해시를 갖는다. forms 순서나 해석표가 달라지면 이전 계획을 재사용하지 않는다.
- Multi 생성 응답은 요청/계획 버전과 edit_id로 결속한다. 누락·중복·추가·오래된 응답은 구조 오류다. Single도 같은 검사를 통과해야 한다.
- 목표형과 실제 표면형의 대응을 별도로 기록한다. 코드로 확인하지 못하는 축약·방언 활용 대응은 모델 주장/검토 필요로 남긴다. `-디더`를 고른 뒤 `-ㄹ시더`를 낸 사실을 카드 ID 존재 검사만으로 통과시키지 않는다.

## 4. 편집 범위와 부분 적용

- 오프셋은 Python 문자열의 Unicode 코드포인트 기준 `[start,end)`이다. 브라우저의 UTF-16 인덱스를 그대로 쓰지 않는다.
- 모든 범위는 같은 원문 스냅샷 기준이다. ID는 원문 순서의 연속 집합이어야 하고 편집 사이의 포함·교차 겹침을 모두 금지한다.
- 한 원문 어절을 여러 어절로 바꾸는 경우와, 여러 원문 어절을 묶는 경우를 구별한다. 전자는 공백이 있다는 이유만으로 거부하지 않는다. 후자는 절/구성 범위 근거가 있어야 한다.
- 문장부호·따옴표·줄바꿈은 보호 대상으로 기록한다. 변경 구간 내부도 검사한다. 단순 ‘구간 밖 원문 유지’만으로 안전하다고 하지 않는다.
- 다어절 묶음의 경계 근거가 없거나 분석이 충돌하면 해당 묶음을 보류한다. EF나 태그 패턴은 보조 신호이며 같은 구성이라는 확정 근거가 아니다.
- 서로 의존하는 수정은 한 편집 또는 원자적 묶음으로 처리한다. 한 항목이 보류되면 묶음 전체를 보류한다. 독립성이 확인된 다른 편집만 반영할 수 있다.
- `keep`: 원문 유지, 수정 건수 0. `apply`인데 결과가 원문과 같으면 실제 결과는 `unchanged`로 별도 기록한다. `needs_review`: 그 편집/의존 묶음은 원문을 유지한다.
- 일부만 반영되면 문장 상태는 `partial`; 모델 호출 실패나 파싱 실패는 `failed`다. 실패를 정상적인 원문 유지로 바꾸지 않는다.
- 결과 재분석은 손실 의심 경고에 활용할 수 있다. Kiwi가 방언형을 분석하지 못하거나 과거 형태소가 보이지 않는다는 이유만으로 의미 소실을 확정하지 않는다.

## 5. 사용자 제한과 문헌 용법

DEV002의 중립 사실 전달에서 `샀어→샀지/샀제`는 사용자 제한으로 제외한다. 문헌의 서술 용법은 그대로 남는다. 정책은 **입력 버전/해당 구간/변환 방향/사용자 출처/적용 범위**를 갖고, 일반 문법 규칙과 분리한다.

사용자 제한과 일반 선택 후보가 충돌하면 그 입력 범위에서 사용자 제한을 우선한다. 다른 문장의 JI_ASSERT를 모두 차단하지 않는다. `샀다/샀데이`는 이 입력의 사용자 대안이며, 그 자체로 전체 과거 평서의 변환표를 만들지 않는다. `그거 니 책이제?`는 확인 질문의 사용자 용례다.

‘화자 입장에서 확정된 사실’은 외부 사실 검증이나 청자가 확인했다는 뜻으로 바꾸지 않는다. ‘질문에 대한 응답’과 ‘청자에게 확인을 요구함’도 다른 기능이다. 선행 발화가 제공되지 않으면 존재를 추정해서 조건을 채우지 않는다. 문말 부호는 실제 관측 가능한 신호지만 `?`나 `.`만으로 JI_ASSERT/CONFIRM 적용을 결정하지 않는다. 문헌 211쪽의 억양 설명은 특히 -지러의 논의 맥락이므로 모든 -지/-제 용법의 단일 판별법으로 일반화하지 않는다.
