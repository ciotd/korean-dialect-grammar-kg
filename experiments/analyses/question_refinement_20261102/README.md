# 질문 지식을 조건으로 찾고, 수정 지시까지 연결하기

이번 작업은 **질문 한 묶음의 지식 정제와 수작업 분석값 조회 검사**다. 실제 분석 모델이나 Qwen 생성 성능 검사가 아니다. 운영 KG·카드·기존 결과는 보존하고 별도 버전 `semantic_questions_20261102_r3`를 만든다.

## 무엇을 고쳤나

| 이전 문제 | 이번 변경 | 확인 방법 |
|---|---|---|
| 계사+었+노의 직접 근거에 판정 질문 예문이 연결됨 | 일반 조건 진술과 보조 재인용으로 연결. 완성 예문 직접 확인과 구분 | 원문 위치·발췌 일치 검사 |
| 큰 모듈에서 규칙을 가져올 위험 | 해당 구성 → 질문 뜻·서술어·선어말 조건 → 일치하는 용법만 조회 | 실제 간선 ID, 단계별 남은 분기 기록 |
| 조회됨과 문장 수정 준비 완료가 같아 보임 | 어간·선어말·기존 어미·명사 말음이 없으면 후보는 보이되 빠진 정보를 알림 | 16개 수작업 사례 |
| 같은 위치에 두 수정 지시가 겹치거나 조회 어미가 바뀌어도 통과 | 위치 중복 거부, 동일 그래프에서 조회 재계산 후 전달 결과 대조 | 잘못된 입력·변조 반례 검사 |
| 지역 변이·다른 기능이 일반 설명 속에 묻힘 | 9개 참고 관찰 노드로 연결. 생성 후보와 구분 | 계사+노 등 참고 기록이 후보로 혼입되지 않는지 검사 |

이전 소규모 구성도 조건 간선을 사용했다. 이번에 처음 그래프 조회를 만든 것처럼 설명하지 않는다. 이번 변경은 근거 연결, 구성별 범위, 조건 색인, 위치 검증, 전달 준비 상태의 보완이다.

## 어떻게 작동하나

`수작업 분석값 → 해당 질문 구성 → 조건 간선으로 후보 축소 → 용법/실현형/근거 → 짧은 수정 지시`

예: **그 사람이 학생이야?**

1. 예/아니오 질문, 긍정 계사, 선어말 없음이라는 분석을 받는다.
2. 실제 조건 간선을 따라 `SEM_Q_C_POLAR`를 찾는다.
3. `학생`의 받침이 확인되면 결합형 `이가`를 선택한다. 여기에는 계사 부분이 포함되므로 `이`를 다시 붙이지 않는다.
4. 원문 대상은 `학생이야`, 보존할 명사는 `학생`, 바꿀 종결형은 `이가`라고 전달한다.
5. 이번에는 모델에 보내지 않는다. 수작업 분석이 틀리면 이 조회도 틀릴 수 있다.

`갔어`처럼 어간·시제·어미가 한 글자에 겹치는 경우 글자 경계로 잘라 붙이지 않는다. 서술어 전체 위치와 분석된 형태소를 함께 넘겨 다시 조합하도록 한다. 조합의 실제 성공 여부는 다음 생성 실험에서 확인한다.

이번 수작업 형태 대응에는 원문 위치·표면형·분석된 어휘와 확인 주체를 함께 기록한다. 이후 전달 과정에서 명사·어간이 바뀌면 보류한다. 이 비교는 형태소 분석기나 언어학적 진실 판정기가 아니다. 다음 자동 분석 연결에서는 모델이 스스로 `수작업 확인 완료`라고 쓰게 하지 않고, Kiwi/정렬 검사 및 필요한 사람 확인으로 대응을 별도로 확보해야 한다.

과거 계사에서는 입력의 계사·-었- 계열을 보존하고 종결형만 바꾸는 **시험 전략**을 명시했다. 문헌에 모든 완성 예문이 없다는 이유만으로 일반 규칙 적용을 차단하지 않는다. 다만 `ready`는 전달 정보가 준비됐다는 뜻이며, 원문 채록 확인이나 자연스러움 인증이 아니다. 이랐- 등 다른 방언 선어말형을 고르는 일은 이번에 하지 않는다.

## 범위와 근거

- 현재: 해라체 직접 정보 질문, 용언·긍정 계사, 선어말 없음/-었-, 주체높임 없음. 여섯 용법은 첫 묶음이며 전체 KG 규칙 수의 상한이 아니다.
- 원문 재독: 지정 25쪽(D02 139–147, D04 8–15, D03 3·27–28, D05 21–25) 및 추가 인접 문맥. 총괄 PDF 화면 대조 7쪽. 각각의 읽은 범위는 `private/source_reading.json` 및 검토자 기록에 구분한다.
- D02 각주162는 재인용이다. D03·D04·D05는 같은 위키 계열이다. 여러 노드가 있다고 독립 근거가 늘어난 것으로 세지 않는다.
- -시-, -더-, -겠-, 높임 질문, 지역별 다른 체계, 확인·반어·명령 질문은 후속 범위다. 이번 미지원이 잘못된 한국어라는 뜻은 아니다.
- 현대 경상도 화자가 자연스럽다고 보는지, 수작업 분석 대신 실제 분석 모델도 같은 조건을 찾는지는 아직 확인하지 않았다.

## 코드와 재현

| 파일 | 역할 |
|---|---|
| `sources.py` | PDF 해시와 발췌 위치 대조, 읽기 범위 기록 |
| `build.py` | 이전 구성과 ID를 이어받아 새 명세·그래프 생성 |
| `query.py` | 조건별 역색인 조회, 위치/그래프 검사, 짧은 전달 자료 생성 |
| `development.py` | 수작업 분석 16건과 기존 24건의 후보 대조 |
| `test_query.py`, `validate.py` | 정상·모호·범위 밖·잘못된 입력 검사와 수치 집계 |
| `reviewers.py` | 기존 Orca 두 검토자의 독립·교차 검토 기록 |

작업 폴더에서 `python build.py`, `python validate.py`를 실행한다. 이전 산출물은 덮어쓰지 않는다. `sources.py`의 PDF 렌더만으로 화면 검토 완료로 표시하지 않는다.

원본 발췌·입력별 결과·검토 원문은 `private/`에 보존하며 커밋하지 않는다. 자동 검사 통과는 언어학적 정확도나 생성 품질 점수가 아니다.

## 다음 단계

교차 검토의 문제를 반영한 뒤 이 지식 버전을 고정한다. 이어 동일 예문에서 수작업 분석 조회와 실제 분석 조회를 비교하고, 전달 지시를 Qwen이 올바르게 반영하는지 확인한다. 분석이 틀린 사례와 지시를 받고도 조합이 틀린 사례를 따로 센다. 이 연결이 확인되면 서술·약속 및 필요한 높임·활용 묶음으로 확대한다.
