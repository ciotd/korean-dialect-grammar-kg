# 이번 비교에서 다룰 문법과 아직 다루지 않을 문법

2026-11-06. 이것은 **작업 범위 결정**이다. 새 요청 규칙을 KG에 넣었거나 번역 품질을 검증했다는 뜻은 아니다.

## 무엇부터 넓히는가

현재 질문·공손 평서·명사 서술을 유지하고, **보조용언 ‘주다’를 쓰는 긍정 요청문** 한 묶음을 먼저 추가한다. 예를 들면 ‘창문을 열어 주세요’다. ‘열어’라는 행동에 ‘주다’가 붙어 상대에게 부탁하는 구조다.

이 선택은 성공한 출력만 골라서 내린 결정이 아니다. 문헌에 직접 용례가 있고, 기존 형태소 분석기로 본동사와 보조용언을 구별할 수 있어 분석 체계 전체를 다시 만들지 않고 시험할 가능성이 있기 때문이다. 번역 성공 여부는 아직 모른다.

|문법 묶음|이번 결정|실제 준비 상태|
|---|---|---|
|반말 정보 질문|유지|기존 실행 그래프에 구성 있음. 의미 판단·어간·과거형 손실 문제는 남음|
|공손 평서|유지|해요체에서 해예체로 바꾸는 기존 구성 있음. 모든 평서문 지원은 아님|
|현재 긍정 명사 서술|유지|‘라예’ 구성 있음. 모든 계사 용법 지원은 아님|
|‘어요’로 끝나는 공손한 정보 질문|유지|기존 구성 있음. ‘나요’ 등 다른 어미로 자동 확대하지 않음|
|과거 긍정·부정 계사|별도 후보로 유지|기존 실험 후보에는 있음. 기본 버전으로 자동 채택하지 않음|
|긍정 ‘-아/어 주세요’ 요청|다음 확장 대상으로 선정|근거·형태 분석 가능성 확인. 분석 조건·KG 연결·새 문장 검사는 아직 필요|
|반말 ‘아/어’ 평서|공유형 대조 후보로 보존|무조건 ‘다/ㄴ다’로 바꾸는 일반 규칙은 확정하지 않음|
|금지·일반 명령·약속·청유·복잡한 절 연결|이번 비교 범위에서 보류|삭제가 아니라 후속 확장 목록에 유지|
|조사·어휘·사동/피동·상/양태의 포괄적 처리|후속 연구|현재 소규모 실험을 전체 경상도 문법 지원으로 표현하지 않음|

## 요청문을 고른 실제 근거

- D02 원본 추출 본문 PDF 192쪽: ‘골라주이소’가 있다. 리드와 Claude가 해당 추출 본문을 확인했다.
- 같은 문헌 PDF 218쪽: ‘말미 주이소’가 있다. 이것은 물건·시간을 달라는 본동사 ‘주다’의 사례다. 앞 사례와 같은 분석으로 합치지 않는다.
- D02 PDF 149~155쪽은 ‘이소/시소’ 계열 명령을 설명한다. Claude가 추출 본문을 대조했다. 이번에는 PDF 이미지 전체를 다시 읽지 않았다.
- 위키 계열 D03·D04·D05는 독립된 세 개의 근거로 세지 않는다. 오래된 채록 자료의 빈도를 현대 자연스러움의 점수로 쓰지 않는다.
- 사용자가 승인한 ‘문 좀 닫아 주이소’는 현대 목표 표현의 선호를 보여준다. 이 문장 전체를 생성 요청에 넣거나 정답 암기 규칙으로 만들지 않는다.

## 새 요청 규칙이 구별해야 할 것

|입력 예시|현재 Kiwi에서 확인한 차이|첫 확장에 포함할지|
|---|---|---|
|창문을 열어 주세요.|‘열’은 본동사, ‘주’는 보조용언|긍정 요청·주절 조건까지 확인한 뒤 포함|
|물을 주세요.|‘주’ 자체가 본동사|이번 보조용언 묶음에서는 제외|
|서류를 주셨어요.|본동사 ‘주’와 과거 형태|요청 규칙 적용 제외|
|창문을 열어 주실래요?|보조용언이지만 질문 형식|이번 단순 명령형 요청 범위에서는 제외|
|문을 열지 마세요.|보조용언 ‘말다’|금지 구성으로 분리, 이번에는 제외|

‘세요’라는 글자만 보고 모든 문장에 같은 규칙을 적용하지 않는다. Kiwi가 실제로 반환한 형태는 기록하고, 공손 요청인지·누구를 높이는지는 문장 구조와 함께 판단한다. 검토자가 제안한 **모든 ‘세요’를 강제로 주체높임 있음으로 바꾸는 처리**는 그대로 채택하지 않는다.

첫 후보 실현은 문헌에서 직접 확인한 ‘주이소’로 제한한다. 다른 변이형을 틀렸다고 선언하는 것이 아니라, 이번 비교의 지식 범위를 고정하는 선택이다. ‘주세요’와 ‘주이소’의 말투가 모든 상황에서 완전히 같다는 뜻도 아니다. 하이소체 요청을 허용하는 목표 스타일은 사용자의 기존 승인 표현과 일치한다. 현대 자연스러움은 별도로 평가한다.

앞 본동사를 ‘데워→뎁하’처럼 바꾸는 어휘 규칙은 이 묶음에 몰래 섞지 않는다. 생성 모델에는 원문·적용 위치·요청 기능·보존할 의미와 함께 필요한 문법 지식을 전달한다. 완성 문장의 작성자는 계속 생성 모델이다.

## 다음 작업과 끝나는 기준

|순서|할 일|끝나는 기준|실패하면|
|---|---|---|---|
|1|보조용언 연결과 긍정 요청 여부를 기존 분석 결과에 연결|새 요청문과 본동사·과거·질문·금지 대조문에서 올바른 위치와 조건을 확인|형태 분석 오류와 의미 판단 오류를 구별해 해당 부분만 보완|
|2|같은 기존 KG 구조에 요청 구성·조건·실현형·근거를 연결|문장 정답 없이 조건으로 조회되며, 범위 밖 대조문에는 이 규칙이 선택되지 않음|근거 부족은 후보로 남기고 비교 범위를 고정. 전체 문법 체계 재설계로 확대하지 않음|
|3|새 범위의 개발 입력·분석·지식 전달 내용을 고정|문장별 실제 전달 내용과 선택 이유를 검토 가능. 정답 전체문장 미포함|전달 누락을 고친 뒤 새 버전으로 다시 고정|
|4|모델을 하나씩 연결해 동일 자료로 생성 비교|실제 요청 호환성 확인 후 모든 입력의 출력·실패·비용 보존|호환성 실패와 생성 품질 실패를 분리. 실패 입력을 빼고 순위를 내지 않음|
|5|같은 지식으로 일반 검색·조건표·그래프 조회 비교|검색 방법 외 조건을 맞추고 조회 차이와 생성 결과를 함께 평가|표와 그래프 결과가 같으면 그래프의 품질 우월성을 주장하지 않음|
|6|새 쉬운 문장으로 블라인드 사람 평가|모델·KG·검색 조건과 평가 기준을 먼저 확정한 뒤 평가|한계와 적용 범위를 명시하고 쉬운 자료 성공을 복잡문 전체로 확대하지 않음|

기존 50문장과 노출된 쉬운 30문장은 개발·회귀 자료로 보존한다. 최종 평가 문장을 보고 모델이나 KG를 고르는 방식은 쓰지 않는다. 모델 선택 기준은 자연스러움·의미/시제/높임 보존·비용이며, KG와의 성능 차이가 가장 커 보이는 모델만 사후 선택하지 않는다.

## 검토자 역할

- Claude: 원문 근거, 현대 목표 표현과의 차이, 문장 분석부터 전달·생성까지 정보가 처음 누락되거나 잘못된 지점, 불필요한 전달 정보 검토. 모델 의견을 문헌 사실로 확정하지 않는다.
- Codex: 입력 누락, 조건 변경, 실패 집계, 비용 분모, 버전 기록, 정답 유출·유리한 결과만 선택하는 편향 검토.
- 리드: 두 의견을 실제 자료·코드에 대조해 반영 여부 결정, 구현·검사·기록. 의견 일치 자체를 정확성 증명으로 쓰지 않는다.
