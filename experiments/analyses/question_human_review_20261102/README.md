# 질문 16건의 사용자 검토

기존 `question_refinement_20261102/private/development.json`의 16건 전체를 읽어 뜻·기대한 대답·미확정 방언 후보·확인 질문으로 정리했다. 원문·KG·기존 분석·기존 실험은 변경하지 않는다. 별도의 Qwen 또는 Reviewer 호출은 없다.

- `private/review.html`: 전체 요약표와 항목별 자연스러움/뜻 보존 선택 화면.
- `private/review_set.json`: 입력 해시, 후보 작성 주체, 실제/가정 규칙 ID, 근거 위치, 아직 검토되지 않은 상태.
- `private/review_table.md`: 같은 내용의 읽기용 표.
- `private/ui_check.json`: 오프라인 저장·복원·잘못된 파일 거부 검사. 실제 브라우저 화면이나 다운로드 완료 검증은 아님.

16개 ID이지만 원문은 15종이다. Q13은 두 해석의 후보를 별도로 평가한다. Q16은 Q05와 같은 원문에 명사 받침값을 누락한 기술 검사이므로 별도 언어 평가를 요구하지 않는다. 따라서 실제 평가 입력란은 16개다. Q15는 재촉 표현이며 현재 지원 범위 밖의 참고 후보로 구별한다.

후보는 총괄이 문법 규칙과 원문을 보고 수작업 구성한 것으로, 자연스럽다고 인증하거나 문헌에 채록된 완성 문장이라고 주장하지 않는다. 어휘 교체를 추가하지 않아 종결 변화가 보이지만, 사용자는 어휘·어순을 바꾼 대안도 제시할 수 있다.

## 검토 저장과 반영

각 항목의 자연스러움·뜻 보존을 선택한다. 대안·이유는 선택 사항이다. 미완료 상태도 저장할 수 있다. 모든 선택의 기본값은 비어 있다. 보류 응답도 기록하지만 정답 승인으로 처리하지 않는다.

브라우저 localStorage는 임시 보관일 뿐 연구 폴더나 SQLite에 자동 저장되지 않는다. **검토 파일 저장**을 눌러 JSON을 내려받고 채팅에서 경로를 알려야 총괄이 접근할 수 있다. 버전과 내용 해시가 같은 검토표만 다시 불러올 수 있다. 브라우저가 임시 보관을 막아도 현재 입력을 다운로드할 수 있다. 서버·모델·KG에 요청하는 기능은 없다.

다음에는 사용자 의견을 원본 그대로 보존하고 의미 해석/표현/어휘 선호/다른 상황으로 나눠 판단한다. 문장별 외운 답을 규칙으로 등록하지 않는다. 피드백은 단일 화자의 개발용 판단이며 모든 경상도 지역의 유일 정답이나 독립 평가로 쓰지 않는다. 실제 KG 수정은 변경 범위·근거를 정리한 뒤 진행한다.

## 발견한 기존 기록 오류

Q15 `빨리 안 와?`의 기존 `polarity=positive`는 부정 표면형과 맞지 않는다. 이번에는 과거 기록을 보존하고 `review_set.json.known_issue`에 수정 대상을 남긴다. 후보도 ‘안’을 보존한다. 이 오류의 확인을 사용자에게 넘기거나 이번에 KG를 조용히 수정하지 않는다.

재현: 이 폴더의 `build.py` 실행 후 `node check_ui.cjs`. PDF 근거의 긴 원문과 후보 문장은 private 영역으로 관리한다.
