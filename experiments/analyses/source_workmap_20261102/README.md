# 문헌의 내용에서 다음 KG 수정 범위를 정하기

## 결론과 이번 작업의 경계

**전체 작업지도 → 묶음별 의미 정제 → 조건 조회 → 생성 검증** 순서는 현재 상황에 적합하다. 하지만 ‘7종 전체를 모두 같은 깊이로 정제한 다음에야 생성 실험’은 채택하지 않는다. 현재 장애는 지식·조회·전달·생성이 섞여 있다는 것이다. 전체 지도로 누락을 관리하고, 작은 완결 단위마다 원인과 효과를 확인해야 한다.

이것이 모든 가능한 방법 중 최선임을 입증한 것은 아니다. **큰 모듈의 모든 카드를 가져오는 구조를 그대로 둔 채 선별만 조절하는 방법보다, 현재 확인된 지식·조건 연결 문제에 직접 대응한다**는 판단이다.

이번 산출물은 작업지도다. 기존 KG 변경, 721개 의미 검증, 모든 문헌 정독, Qwen 실험 완료를 뜻하지 않는다. `private/atlas.json`의 각 상태에 이를 분리했다. 26개 작업묶음은 새 KG Schema나 실행 규칙 수가 아니며, 기존 12모듈을 대체하지 않는다.

## 무엇을 실제로 했는가

1. 원본 PDF7종·474쪽과 기존 KG·카드·첫 의문문 구성의 해시를 기록했다.
2. Claude가 만든 문헌 중심 장절 지도102개에 실제 읽은 깊이를 남겼다. 총괄도 목차·지정 본문을 대조했다. D02의 다수 세부 결합조건 본문, D05의 본문 전체, 표의 화면 대조는 아직 남아 있다.
3. 기존 911개 설계 ID를 모두 보존해 **방언 항목721 / 공통 문법 계약136 / 기술 책임54**로 나눴다. 기존 문헌 참조와 장절 쪽 범위의 교집합은 ‘대응 후보’로만 기록했다. 작업 배정 초안이 있다는 뜻이며, 911개 배정의 의미 타당성이 검증됐다는 뜻은 아니다.
4. 원문 장절에서 출발하는 작업묶음 연결과 기존 ID에서 출발하는 작업 배정을 별도로 만들었다. 뒤쪽은 ID·분류명에 의한 초안이므로 의미 대응 인증이 아니다.
5. 각 묶음에 **무엇을 읽을지 → 어떤 분석값이 필요한지 → 어떤 조건으로 찾을지 → 무엇을 전달할지 → 어떤 검사로 끝낼지**를 명시했다.
6. 두 Orca 검토자의 독립 검토를 수집했고 교차 검토 및 반영 결과는 별도 기록한다. 모델 동의를 문헌 사실 인증으로 사용하지 않는다.

이번 지도 종료는 **의미 정제의 전체 완료가 아니다.** 102개는 거친 장절 위치 단위다. 각 묶음 정제 때 세부 표·각주·주장 단위를 나누며 새 누락을 지도에 추가한다. ‘참조되지 않은 페이지=누락 지식’ 또는 ‘참조가 있음=충분한 지식’으로 판단하지 않는다.

## 첫 묶음은 왜 여전히 의문문인가

이미 조건을 실제 관계로 표현한 작은 의문문 구성이 있어, 처음부터 다른 유형을 만드는 것보다 **새 정제 방식의 연결 여부를 검증하는 비용이 낮다.** 의문문이 전체 방언을 대표한다는 뜻은 아니다. 다음 순서는 과거 실패와 직접 관련된 **서술·약속 어미, 필요한 높임·활용**으로 정한다. 거로·인용·부정·보조용언도 전체 지도에서 빠뜨리지 않는다.

첫 묶음은 **해라체의 직접 정보 질문 × 용언/긍정 계사 × 선어말 없음/-었- × 주체높임 없음**으로 한정한다. 이는 지원 시험 범위이며 다른 표현이 틀렸다는 뜻이 아니다. 높임 의문·확인/반어·-시/-더/-겠·아니다·지역별 다른 질문 체계는 다음 하위 범위로 명시해 남긴다.

읽기 범위: D02 PDF139–147, D04 PDF8–15, D03 PDF3·27–28. 지역별 다른 질문 체계를 합치기 전에 D05 PDF21–25를 함께 확인한다. 세부 용법에 관련된 각주와 앞뒤 설명도 포함한다. `next_work.json`에는 필요한 특징→공급할 공통 계약→근거→미확정 처리→수용 시험과 제외한 후속 읽기 범위를 기록했다. 해당 문서는 계획이며 새 시험을 실행한 기록이 아니다.

첫 묶음이 내놓아야 할 결과:

- 문헌 속 형태 목록이 아니라 **질문의 뜻·서술어 종류·선어말열에 따른 용법**과 근거.
- 기존 ID와 새 용법의 대응표: 유지·분리·통합·참고·미확정 이유.
- 실제 조건 관계, 같은 절에 묶인 분석값, 맞는 후보·보류 이유·보존 정보.
- 본문·표·주석의 조건 대조, 조건별 적용/비적용/미확정 시험, 다른 어휘·시제로 바꾼 개발 사례.
- 원문과 추출 표가 다르면 PDF 화면을 확인. 근거가 부족하면 해당 분기만 유보한다.

`work_packages.json`의 의존관계는 **필요한 공통 부분을 먼저 확보한다**는 뜻이다. F01의 모든 활용을 완성해야 F03의 질문을 시작한다는 뜻이 아니다. 한정된 범위의 완결 검증을 먼저 수행한다.

## 교차 검토 후 고친 작업지도

- 인용 `GS_HAM_QUOTE`를 질문으로 보내던 접두어 충돌을 수정하고 회귀 검사를 추가했다.
- 모듈 번호에 따른 공통 계약69개 배정을 없애고, 제목을 대조한 명시적 작업 배정으로 바꿨다. 이는 제목 기반 범위 지정이며 조건 의미 검증은 아니다. 새 항목은 임의 모듈 배정 대신 미배정으로 검출한다.
- 모든 종결형을 높임 묶음의 본작업으로 중복 배정하지 않는다. 높임을 참조할 필요는 `context_links`로 남긴다. 지역 관찰도 같은 원칙을 적용했다.
- 문헌의 내용 역할과 후순위 여부를 분리했다. 낮은 우선순위의 문법 지식도 문법으로 남는다.
- 장절 목록 순번을 배정 키로 쓰지 않는다. `문헌ID:장절ID`로 고정하고 원본 지도·배정표·코드 해시를 기록한다.
- 문헌 중심 배정과 기존 참조 기반 배정의 불일치226개는 검토 대기열로 남겼다. 이것이 오류226개나 빠진 규칙226개라는 뜻은 아니다. 같은 쪽의 다른 내용·공통 배경·잘못된 기존 참조 등이 섞여 있어 묶음별 원문 대조 때 판정한다.
- 문법 장절에 방언 항목의 쪽 참조가 없는17곳도 추가 대조 대상으로 남겼다. 공통 계약만 있는 곳, 개요·중복 설명도 포함되므로 실제 지식 누락 수로 쓰지 않는다.

따라서 **전체 위치·작업 배정 초안은 확보했지만, 세부 표·각주 목록과 주장별 의미 대응은 다음 정제에서 완성**해야 한다. 이 한계를 숨긴 채 ‘7종 전체 KG 정제 완료’로 표시하지 않는다.

## 검토자 의견 중 그대로 따르지 않는 부분

- Claude의 ‘특정 지역·세대를 반드시 먼저 고정’은 부분 채택이다. 지역·시대 차이는 지식에 보존하되, 모든 입력에 지역 설정을 강제하지 않는다. 실제로 충돌하는 체계나 현대 사용 여부를 판단해야 할 때만 구분한다.
- Claude의 ‘D02 표준형을 생성 후보로 쓰면 안 됨’은 과도하다. D02 PDF39–40은 방언 발화에서 사용된 표준형도 연구 대상이라고 한다. 따라서 표준형을 방언 고유 변환 규칙으로 간주하면 안 되지만, 올바른 원문 유지 또는 공유 형태를 일괄 배제해서도 안 된다.
- 위키의 단정적 세대·지역 서술, 문헌의 표본 한계, 모델의 자연스러움 판단은 서로 구별한다. 이번 지도는 현대성 인증이 아니다.
- 기존 출처 메타데이터의 D02 ‘1978–1984’와 원문 주7의 ‘1차 사업1979–1985’ 차이를 수정 후보로 기록했다. 사업 기간과 실제 채록 날짜를 동일시하지 않는다. 과거 원본은 덮어쓰지 않는다.

## 연구 방향에서 지켜야 할 것

KG의 크기나 원문과 달라진 비율을 품질로 쓰지 않는다. 같은 지식·분석·생성기를 둔 평면 조건표와 그래프 조회를 비교해야 KG 구조의 기여를 분리할 수 있다. 첫 묶음에서는 오류 시작점을 확인하고, 비교 실험은 작동 가능한 구조가 확보된 뒤 진행한다.

기존 50문장은 이미 개선에 노출된 회귀 자료다. 새 쉬운 문장은 개발용과 최종 평가용을 분리하고, 성공한 유형만 사후 선택하지 않는다. Claude 정답 50문장을 개별 입력의 조회 규칙으로 외워 넣지 않는다.

## 파일과 재현

- `work_packages.json`: 총괄이 작성한 26개 작업묶음의 목적·입출력·종료 기준.
- `source_assignments.json`: 순서에 의존하지 않는 문헌 장절별 작업 배정.
- `next_work.json`: 첫 의문문 범위와 필요한 공통 계약·종료 기준.
- `build_atlas.py`: 원본을 읽어 페이지·설계 항목·대응 후보·묶음·통계를 생성. 운영 KG는 쓰지 않는다.
- `private/atlas.json`: 전체 지도. `private/legacy_worklist.csv`: 기존 ID별 대장.
- `private/reviewer_work/`: 두 검토자의 원문 결과와 자체 구조 검사.
- `private/dispatch/`: 한국어 지시문, 모델 응답, 전달·완료 기록.
- `private/report.html`: 사람이 읽을 요약·표·검색 화면. `private/validation.json`: 검사 결과.
- `private/review_resolution.json`: 검토 의견 반영·보류 내역.

프로젝트 루트에서 `python experiments/analyses/source_workmap_20261102/build_atlas.py`로 재집계한다. 원본 전체 추출·검토 상세는 private 영역에 보존하며 자동 공개하지 않는다.
