# 50개 입력 전체 진단

사용자 지시에 따라 8개 사례로 범위를 제한하지 않고, **기존 입력 50개와 Single/Multi 실행 기록 100건 전체**를 대조한다. 일부 입력은 여러 문장으로 구성된다. 100개의 서로 다른 입력을 새로 만든 작업이 아니다.

먼저 [전체 검토 화면](private/review.html)을 연다. 원문과 두 출력을 나란히 비교하고, 문장별 분석·선택 카드·수정 지시·그래프 연결 근거·검토 의견을 펼쳐 볼 수 있다. 검색과 필터를 제공한다. 전체 내용을 표로만 보려면 [50개 비교표](private/casebook.md)를 이용한다.

## 현재 확인한 결과

| 기록상의 결과 | Single | Multi |
|---|---:|---:|
| 원문과 다른 최종 출력 | 37 | 40 |
| 원문과 같은 최종 출력 | 1 | 1 |
| 최종 출력 없음 | 12 | 9 |
| 해당 출력과 정확히 일치하는 기존 사람 평가 | 9 | 11 |

이 수치는 자연스러움·정확도가 아니다. 출력이 달라도 잘못될 수 있고, 원문 유지가 허용될 수도 있다. 기존 사람 평가가 있는 20개 출력을 전체 100건의 평가로 확대하지 않는다.

- 출력 없음 21건: 응답 길이 제한 16건, 한 어절 제약 4건, 수정 항목에 빈 카드 ID 목록을 남긴 경우 1건.
- 완료된 수정 기록 171개 중 34개는 수정 전후 문자열이 같다. 이를 실제 변환 성공으로 세지 않는다.
- 완성 출력 4개에는 결합되지 않은 한글 자모가 남았다.
- 동결된 코드로 카드 순위를 다시 계산한 50개 입력 모두, 저장된 양쪽 실행의 순위·선별 결과와 일치했다.

## 어떤 부분을 먼저 고쳐야 하는가

| 확인된 문제 | 실행 기록의 예 | 다음 수정에서 확인할 것 |
|---|---|---|
| 문장 분석과 구성 범위 | 반말을 공손체로 표시; 같은 절의 의문사와 종결부를 서로 다른 의문 유형으로 표시 | Kiwi의 어간·품사·위치와 Qwen의 기능 판단 연결, 여러 어절로 된 구성의 범위 |
| 관련 카드의 선별 | `condition` 검색어가 `coda_condition`에도 일치하여 목적격 조사 카드가 조건문 점수를 얻음 | 속성 이름의 글자 일치를 문법 기능 판정으로 쓰지 않기; 구성별 필요한 후보가 남는지 확인 |
| 카드 내용과 수정 지시 불일치 | `-를` 카드를 인용하며 `열쇠을`을 지시; 회상 카드 ID를 달고 의지 어미를 지시 | 선택 ID·적용 조건·수정 지시·실제 결과가 같은 규칙을 가리키는지 확인 |
| 활용과 보존 | `사었지`, `미끄러우아가`, `되ㄴ가`; `빌려` 소실 | 어간·어미의 결합 처리와 어휘·시제·부정·대우 보존 확인 |
| 출력 계약과 처리 | 여러 어절 표현을 제시한 카드를 사용하면서 공백은 금지; 수정하지 않는 항목을 edits에 남김 | 편집 범위와 카드 표현 범위 일치; 미적용 항목 생략; 무변경과 실제 변경 분리 |

이 작업에서 수정 효과를 실험으로 입증한 것은 아니다. 기록에서 처음 발견되는 불일치와 그것이 하류 오류의 원인이라는 가설을 구분한다. 다음 단계는 이 진단을 바탕으로 수정 범위를 정하고, 한 요소씩 바꾼 원인 확인 및 50개 전체 재실험을 설계하는 것이다. 현재 KG·실행 코드 변경이나 Qwen 재호출은 하지 않았다.

## 데이터와 검토 범위

- 대상 실행: `20261028T011829489985Z_cards_single_regression`, `20261028T011829489985Z_cards_multi_regression`.
- 실행 당시 입력: `standard_inputs_50_20261023_v1`.
- 사용자가 ADVCE008A를 수정한 `standard_inputs_50_20261029_v2`는 별도 보존되며 이번 과거 출력의 입력으로 소급 적용하지 않는다.
- 이 50개는 이미 오류 분석에 사용된 회귀 검사 자료다. 앞으로 개선에 활용할 수 있지만, 새로 숨겨 둔 독립 최종 평가 자료라고 주장하지 않는다.
- 기존 사람 평가와 사용자가 추가한 선호 문장을 구별한다. 선호 문장을 유일한 정답이나 임의 점수로 만들지 않는다.
- 두 Orca 검토자는 각각 같은 50개를 검토한다. 전달은 10개씩 나누되, 문장 범위를 나누어 분담한 것이 아니다. 응답 수집 범위는 [현재 진행 기록](private/progress.json)과 보고서에서 확인한다.
- Codex 검토 세션의 파일 접근 문제 때문에 실제 자료를 메시지로 나누어 전달하고, 저장된 대화와 정확히 일치하는지 확인한다. Claude는 동일한 로컬 자료를 읽는다. 모든 문장의 두 방식 결과와 실제 인용 카드 조건을 제공한다. 다른 검토자의 의견·총괄 판단·사람 점수는 독립 검토 전에 제공하지 않았다.
- 전체 원문헌 7종을 이번에 다시 전수 정독한 검증은 아니다. 실행 기록과 카드·개념 정의 중심의 진단이며, 방언 수용성을 AI의 기억이나 두 모델의 합의로 확정하지 않는다.
- 조회 경로 예시는 카드별 최대 2개이며 원본 전체 조회 기록으로 연결한다. 시간순 방문 이력 또는 적용 조건 충족의 증명이 아니다.

## 재현과 파일 역할

| 파일 | 역할 |
|---|---|
| `prepare_packets.py` | 원본 실행에서 50개 검토 자료와 원본 해시 목록 생성 |
| `review_exchange.py` | 지정된 Orca 세션으로 전달·응답 수집, 문장 ID 누락 검사 |
| `audit_details.py` | 모델 호출 없이 동결된 카드 선별 결과 50개 재현 |
| `lead_observations.json` | 총괄의 문장별 대조 결과 |
| `review_adjudication.json` | 검토자의 의견 중 수정·보류·기각한 판단과 근거 |
| `build_review.py` | 원본·검토 결과에서 비교표, 보고서, 실제 통계 재생성 |
| `private/packets/` | 10개씩 5묶음의 실제 검토 자료 |
| `private/reviews/` | 두 검토자의 원문 응답·구조화 결과·모델 및 시점 기록 |
| `private/dispatch/` | 전달한 자료와 접수·대화 일치 확인 기록 |
| `private/selection_diagnostics.json` | 카드 순위 재현 결과와 누락 사례의 실제 순위 |
| `private/shared_inputs_check.json` | 두 방식의 분석·형태소·전달 카드가 같은지 50개 대조 |
| `private/validation.json` | 원본 변경 여부, 출력 재조립, 사람 평가 대상 일치 확인 |
| `private/report_checks.json` | 50개 표시·로컬 링크 검사와 최종 리뷰 자료 무결성 |

로컬 Python 환경에서 `audit_details.py`, `build_review.py`, `verify_report.py --complete` 순서로 실행하면 진단 수치와 보고서를 다시 만들고 완료 조건을 확인할 수 있다. 이 스크립트들은 Qwen이나 Neo4j에 연결하지 않는다. 검토 응답을 새로 받는 작업은 별도이며, 이미 받은 결과의 재생성과 구별한다.

문장·출력·리뷰 원문은 `private/` 아래에 보존한다. 이 작업은 Git 커밋·푸시를 수행하지 않는다. 원본 저장소와 기존 실행 결과도 변경하지 않는다.

화면 검증 한계: 브라우저 도구가 로컬 파일 주소 열기를 차단하여 실제 브라우저 렌더링 검증은 수행하지 못했다. 문서 구조와 로컬 파일 연결 검사는 별도 기록한다.
