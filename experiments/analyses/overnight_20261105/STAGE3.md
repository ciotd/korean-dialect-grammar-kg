# ③ 분석과 차단: 한꺼번에 완화하지 않는 이유

기존50의62목표 위치를 코드로 다시 대조했다. 문법 조건에는 맞지만 구조 미확정 때문에 전달이 막힌 위치는 **1곳(DEV026 나왔어요)**이었다. 따라서 전역 차단을 없애면 전체 실패가 해결될 것이라는 설명은 실제 기록과 맞지 않는다.

## 확인한 두 문제

|위치|실제 관찰|이번 판단|다음 해결책|
|---|---|---|---|
|늦을까 봐 조금 일찍 나왔어요|나왔어요의 규칙은 eligible. 앞부분 늦을까→봐 연결이 unknown이라 전달 보류|차단의 실제 위치를 형태소 ID와 함께 새 진단 파일에 기록. 무조건 해제하지 않음|변경 대상의 규칙 선택·높임·부정 범위에 필요한 연결만 명시하는 의존 검사 후 국소 허용 비교|
|자료를 읽고 계세요|Kiwi가 계/명사+이/계사+세요/어미로 분석. 후보5개에도 계시/VX가 없음. 과거 계셨어요에는 계시/VX가 있음|두 번째 분석 후보를 고르는 것만으로 현재형 문제가 해결되지 않음. Qwen 설명을 자동 정답으로 승격하지 않음|표준어 형태 분석의 어휘·활용 지식 보완 또는 구조화된 수정 후보 생성→반례 검사. 방언 KG 부족과 분리|

계세요 단어만 강제로 바꾸면 진짜 명사 계와 문장 위치를 잘못 처리할 수 있다. 구조 차단을 풀면 의문사의 소속·부정·높임의 불확실성까지 허용할 수 있다. 두 검토자 모두 의존 근거를 먼저 확인하도록 권고했다. 이번에는 진단을 추가했고 운영 분석/차단은 변경하지 않았다. 실패한 새 분석 방법을 반복 실험하지 않았다.

산출물: analysis_diagnostic.py, private/analysis_diagnostic/targets.json(62위치), kiwi_nbest.json(5문장의 후보5개), summary.json. 원본은 보존. 단어 위치·분석 원인·판정 근거를 읽을 수 있도록 최종 미팅 자료에 연결한다.

종료: 원인 위치와 단순 완화가 부적절한 이유를 확인. 수정 효과는 미검증으로 남기고, 이미 개발 검사에 통과한 r10만 기존50과 비교한다. 연구 전체를 서버 조사나 분석기 교체로 넓히지 않는다.
