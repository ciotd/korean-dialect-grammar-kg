# ⑥ 논문 준비용 통제 파일럿 — 실행 전 설계

연구질문: 같은 Qwen과 입력 분석에서 KG 지식을 주는 것과 주지 않는 것은 어떤 차이가 있는가? 같은 지식을 JSON/줄 단위 텍스트로 전달하면 어떤 차이가 있는가?

자료: Claude 검토자가 범위를 알고 작성한 EZ01–30 전체. 모두 개발 파일럿이며 독립평가 아님. 처음 문서의 D/E 표시는 폐기. 한 주요절 중심·한 문장·시제/높임/품사 대립·지원 밖 포함. 출력이 나온 뒤 성공 입력만 골라내지 않는다. 기존50와 정확중복 검사를 하되 이것만으로 어휘/형식 독립성을 주장하지 않는다.

- N: 공통 원문·분석 + 문법 지식 없음. 사전학습으로 생성 허용.
- T: 같은 원문·분석 + KG에서 선택한 지식을 결정적 경로=값 텍스트로 전달.
- J: 같은 원문·분석 + T와 같은 지식을 JSON으로 전달.
- T는 자연어 재작성/요약이 아니다. 모든 키·리프 값·빈 배열/객체까지 역복원해 J와 같음을 검사한다. T/J의 정보·ID·근거는 같고 길이와 배치는 다르다.
- 후보 r10 고정. 세 조건의 system prompt·모델·seed·온도·출력형식·호출기회 동일. 분석은 문장별 한번 공유. KG로 선택된 위치만 N에 주지 않는다. 모든 분석목표의 형태/특징을 공통으로 전달.
- 원문 복사 강제 지시를 새 공통 프롬프트에서 제거하고 패킷 instruction은 넣지 않는다. 이번 파일럿은 A형 범위 정책 회귀 비교와 별개다. 운영 기본값 변경 아님.
- 정답참조·expected_surface·모델교사출력 미전달. 추가 수정 호출0. 문항별 N/T/J 순서 순환.
- 최대30입력×3생성(+실제목표수 분석). 분석5연속실패 또는10입력 후20% 초과이면 중단. 생성은 각조건5연속실패 또는10호출 후20% 초과시 전체 묶음중단. 미완료 쌍은 쌍비교에서 제외하고 실패는 남긴다.

측정: 모델 요청 성공/JSON 형식, 출력 변화(품질 아님), 자동 형태소상 과거·부정·높임 관찰 감소 경고(정확도 아님), 동일 지식/설정 검증, 토큰·호출·시간. 자연스러움·의미 보존은 사람이 나중에 평가. 알려진 전달 결함 EZ01/EZ21는 별도 표시하되 실험 중 고치지 않는다.

가능한 주장: 이 고정된 구현과 개발 자료에서 정보 유무/표현 형식에 따른 출력·비용 차이. 불가능: 독립평가 일반화, KG 우월성, 그래프 검색이 텍스트 검색보다 우수, 인간급 자연스러움. 그래프 검색 자체의 기여는 향후 동일 지식 원천의 텍스트 검색과 조건경로 검색을 별도로 비교해야 한다.
