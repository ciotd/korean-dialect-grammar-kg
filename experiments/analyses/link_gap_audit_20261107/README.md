# 직접 연결 공백 107개·27개 수정 전 감사

## 수행 범위

사용자는 직접 연결이 없는 공통 항목 107개와 후보 용법 27개를 코드·실행 기록으로 구분하고 **수정하기 전에** 설명하도록 요청했다. 이어 최초 136개가 표준어 문법책의 규칙 목록을 그대로 옮긴 것이 아닌 이유를 물었다.

연구 질문은 ‘설계의 어떤 책임이 현재 실행 경로에 구현되었고, 연결 기록의 공백과 기능의 공백은 어떻게 다른가’이다. 전체 의미·높임 보존 검증에 앞서 대응표와 실제 기능 수정 범위를 구분하는 데 사용한다. 새 KG나 알고리즘의 효과 실험이 아니다.

현재 `tools/run_integrated_grammar.py` 진입점, 통합 그래프 구축·조회·분석 계약·전달·출력 검사, 과거 통합 실행 4개를 읽었다. 이전 조합기와 의문사 범위 검사 코드는 현재 호출 여부를 구분했다. 관련 원문 문헌을 전수 의미 검증하지 않았다.

## 산출물

`private/20261107T042114917700Z/report.html`이 전체 보고서다. 공통 107개와 용법 27개를 모두 펼쳐 볼 수 있으며 분류·검색·항목 이동을 제공한다.

- `overview.html`: Archify로 생성한 쉬운 전체 그림. 설명용 대응과 실행 조건의 다른 경로, 수정 전 판정 흐름을 그렸다.
- `audit.json`: 모든 항목의 판정, 원래 계약, 실제 코드 위치, 부분 실행 증거, 연결 부재 원인, 제안과 사실의 구분.
- `replay.json`: 저장 분석 99건의 메모리 비교. 원본 연결 55개 포함/제외 조건의 조회·전달 동일성.
- `logical_probes.json`: 미연결 용법 27개·28분기의 조건 조회, 결과 상태 조건 불일치 검사.
- `rule_trace_evidence.json`, `delivered_rule_witnesses.json`, `feature_witnesses.json`: 당시 용법 전달 및 특징·관계 기록.
- `near_misses.json`: 전달 사례가 없는 용법 중 원문 형태가 맞지만 다른 조건에서 배제된 기록. 배제 자체를 오류로 판정하지 않는다.
- `manifest.json`, `snapshot/`: 읽은 소스·설계·현재 KG와 과거 기록 해시. 실제 입력·출력은 private에만 보관한다.

`judgments.py`는 감사자의 해석을 따로 보관한다. 측정 수치와 이 분류 판단을 동일시하지 않는다. `audit.py`를 실행하면 새 고유 폴더가 생기며 기존 결과를 덮지 않는다. Archify 원고·최종 HTML은 해당 판본에 별도로 보존했다.

## 27개 용법의 확인 결과

27개 모두 현재 조회·전달 경로에 존재한다. 조건을 직접 넣는 28분기 검사에서 모두 선택 가능했다. 합성 관계 대상은 조회기의 ‘관계 존재’ 검사만 충족하므로 자연어 결속·언어적 타당성 검사가 아니다.

직접 연결 부재의 구현상 원인은 다음과 같다.

| 경로 | 개수 | 확인 근거 |
|---|---:|---|
| 문헌 항목만 legacy_ids에 기재 | 17 | refined_knowledge와 compile_overlay의 REFINES 생성 |
| legacy_ids가 빈 배열 | 7 | 리드 후보 5개 및 다른 후보 2개의 실제 정의 |
| 이전 실행 KG에서 승계 | 3 | r7 확장 2개와 r10 과거 계사 확장 1개의 빌더 |

구축기는 해당 ID의 존재는 검사하지만 공통 설계 대응이 하나 이상 있어야 한다고 요구하지 않는다. 자동 링크가 사라진 것이 아니라 대응 기록을 일관되게 만들지 않은 경로다. 개별 작성자가 왜 목록을 비웠는지의 의도까지는 결정 기록이 없으면 확정하지 않았다.

과거 통합 실행 4개에서 13개 용법 ID의 전달 기록이 있고 14개는 찾지 못했다. 실행 판본과 노출 입력이 다르고 반복을 포함하므로 현재 지원률·품질 점수로 계산하지 않는다. 요청 보조용언 후보는 과거 실행에서 전달됐으나 repair의 IG013에서는 분석 조건 불충족으로 전달되지 않았다. 한 실패 사례로 기능 자체가 없다고 결론내릴 수 없다.

## 107개 공통 항목의 감사 분류

| 현재 책임의 구현 상태 | 개수 |
|---|---:|
| 공통 처리 구현 | 3 |
| 용법에 한정 구현 | 17 |
| 분석·지시 일부만 구현 | 36 |
| 현재 전용 구현 없음 | 40 |
| 묶음 창구 설계만 존재 | 11 |

각 항목을 원래 설계의 match/output과 대조했다. 앞의 3개도 설계의 모든 부가 요구가 완성되었다는 판정은 아니다. 예를 들어 글자 위치 확인은 있으나 최종 출력과의 완전한 대응 그래프는 없다. 17개는 좁은 용법·조건에 구현된 일부 책임이며 36개는 특징·관계·보존 지시 정도만 확인된다.

40개는 **현재 진입점에서 설계에 맞는 전용 처리 절차를 확인하지 못한 항목**이다. Qwen이 해당 문장을 자체 지식으로 처리할 수 없다는 뜻이 아니다. 일부는 명시적 보류 기록이 있고, 나머지는 현재 계약의 입력/출력·호출 경로 부재로 판단했다. 11개 인터페이스는 원래 묶음 창구이므로 개별 용법의 1:1 연결 누락으로 보는 것부터 부정확하다.

## 연결만 추가해도 해결되는지 확인

실제 KG 파일은 수정하지 않고 별도 메모리 사본에서 공통↔용법 직접 연결 55개를 제외했다. 저장 분석 99건·802단위를 **동일한 현재 조회 코드**로 처리했을 때 조회 기록·전달 패킷·분석 계약은 모두 동일했다. 현재 실행기는 이 대응 선들을 조건으로 읽지 않는다.

이는 연결 추가가 현재 실행 결과를 직접 바꾸지 않는다는 코드 근거다. 새 Qwen 생성이나 새로운 전체 파이프라인 실험이 아니며, 과거 출력이 현재 코드로 재생성됐다고 주장하지 않는다. 원본 결과 100건 중 1건에는 결속 분석이 없어 재조회 대상이 99건이다.

## 연결 외에 실제 남은 문제

1. `INT_AUX_PRESERVE_COMMON`은 제목에 ‘상태’를 포함하지만 조건의 허용값에는 `resultative`가 없다. 같은 다른 조건에서 `progressive`는 eligible, `resultative`는 condition_mismatch였다. 제목과 조건의 불일치이며, 상태 값을 추가하는 것이 맞는지는 별도 문헌·구성 검토가 필요하다.
2. 현재 `G_Q_SCOPE`·`G_Q_WH_BIND`에 필요한 의문사 출현 절·의미 범위 절 필드는 분석 계약에 없다. 11월2일 실험의 제한적 검사 코드는 있으나 현재 통합 진입점은 이를 호출하지 않는다.
3. 의문사 어휘 후보의 조건은 interrogative를 요구하지만 저장 분석은 같은 단어에 location 또는 subject를 부여한 사례가 있다. 질문 역할과 문장 성분 역할이 동시에 성립할 수 있어 모델 오답이라고만 판정할 수 없다. 분석 계약과 용법 조건의 구별 방식이 맞는지 검토해야 한다.
4. 형태만 맞아도 올바르게 배제된 경우가 있다. 금지 연결어미 지를 확인 의문 종결 지 후보에서 제외한 사례는 배제되었다는 이유로 오류라고 세지 않았다.

## 표준어 문법책 관련 판단

최초 설계의 `root.common_grammar_source_limit`은 별도의 공통 한국어 문법책 전체 본문이 제공되지 않았다고 명시한다. 따라서 ‘문법책을 충분히 검토하고 그대로 옮기는 방식을 의도적으로 배제했다’는 역사적 설명은 근거가 없다.

문헌의 서술을 조건·관계·보존 검사로 바꾸는 추가 설계가 필요하다는 것은 일반적인 구현상의 설명이다. 이 설명이 당시 원전 확보·대조 부족을 정당화하거나 최초 136개의 완전성을 보장하지 않는다. 방언 자료에서 출발한 공통 분석·보존 계약이라는 실제 성격으로 소개하고, 이후 표준어 문법 원전과 정의·분류·조건·예외를 대응해야 한다.

## 다음 작업과 분기

우선 제시된 대응 후보를 전체 책임/부분 책임/관련만 있음으로 검토한다. 현재 승인된 출처·검토 기록 분리 방침에 맞춰 대응표를 외부 추적 기록에 두는 방법을 우선 검토하며, 실행에 쓰이지 않는 연결을 무조건 KG에 늘리지 않는다.

명백한 기록 공백은 근거가 확인된 대응만 기록한다. 기능이 부족하면 연결 추가로 완료 처리하지 않고 상태 조건·의문사 범위·뜻별 어휘·활용 검증 등 별도 수정 범위를 정한다. 원문 근거가 부족하면 보류하고, 준비된 조건별 자연어 사례를 전체 실행한 뒤 실제 도달·보존·사람 판정을 확인한다.

이번 종료 기준은 모든 107/27 ID의 누락 없는 판정, 코드·기록 근거와 한계, 원본 무변경 확인이다. 별도 검토자는 호출하지 않았고 독립 언어학 평가도 하지 않았다. 판단이 들어간 분류를 합의나 측정된 정확도로 제시하지 않는다. 사용자에게 지금 필요한 것은 수정 승인이 아니라 현재 구조와 한계의 이해이며, 이번 감사 자체에 추가 승인은 필요하지 않다.
